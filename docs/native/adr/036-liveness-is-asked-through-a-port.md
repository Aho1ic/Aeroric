# ADR-036：存活代是问出来的，不是记出来的——core 用 `LiveRuns` 端口去问宿主

- 状态：已接受（Task P2-05 门禁，Q65 —— 用户拍板，采纳推荐）。
- 日期：2026-09-24
- 相关：ADR-034（迟到观察丢弃是 core 的规则）、ADR-035（决策与落盘解耦）、ADR-033（28 处一次性全交）、ADR-020（编号只有一处来源）、ADR-025（存活看任意代）、P3-01（`TaskRegistry` 端口）

## 背景

ADR-034 把"这条状态用户该不该看到"定成 core 的一条规则：**该任务在本进程已无存活代 ⇒ 丢弃**。
补记四十八量出两件事实，让这条规则在移交前必须先解决"存活代从哪来"：

1. 产品路径**今天一条 core claim 都不产生**——`lib.rs:672` 的注释自己写着"仍由 `storage.rs` 保存，
   没有任何 mutation 走 `TaskService`"。
2. 22 处 legacy `task-status` 里有 **5 处是 launch 时报的 `running`**（`pty.rs:1970`/`2734`、
   `ssh.rs:1388`、`wsl.rs:1022`、`dsh_webui.rs:1473`）。删掉它们之后，这些运行在 core 的账本里
   查不到存活代，会被 ADR-034 自己丢掉——**前置不是 dsh 那 9 处独有，是整张表**。

三种机制可选：core 里另存一份"宿主报上来的存活表"（镜像）、launch 一律经 core 取号（真 claim）、
或 core 持一个端口去**问**宿主。

## 决策

1. **core 定义 `LiveRuns` 端口，`TaskService` 持有它**：`has_live_run(task_id) -> bool`。
   宿主用自己那张 `RunRegistry` 实现——**进程句柄在谁手里，存活事实就归谁**，core 不复制一份。
   core 侧默认实现是 `NoLiveRuns`（恒 `false`），供无进程的宿主与单元测试使用。
2. **准入判据取两者之并**：`open_claims(task)` 非空（core 自己铸造并在飞的运行）**或**
   `live_runs.has_live_run(task)`（宿主报的存活）。不是替换：claim 一路已经由 30 条端到端用例覆盖，
   把它换成端口等于把 ADR-017 的双开保护改成依赖宿主记得注册。
3. **不新增第二份账**。镜像方案被否的理由是具体的：任何一条 `retire` 路径漏掉，core 里就留下一个
   "永远活着"的条目，而失效方向是**抑制闸不再挡**——即 ADR-034 要防的那个事故（卡片重新点亮）
   会静默回归。本仓已经因为"三套并行编号"立过 ADR-020，同一类错误不再犯一次。
4. **`RunKey::UNMINTED(0)` 与真实代同等参与**。宿主侧的 `has_live_run` 今天问的就是"这个 id 有没有
   任意存活代"，未 minted 的运行（writer 未递交前由旧命令直接起的）本就在同一张表里。
   把它当成"没有代"等于把 ADR-034 的判据又写宽一次。
5. **可核对**：端口必须被真的问到——一条 core 用例在**没有任何 claim** 的情况下，仅靠
   `LiveRuns` 回答"活着"就让一条本会被丢弃的观察通过；同一状态换成 `NoLiveRuns` 必须仍被丢弃。
   两条一起，才排除"端口形同虚设而测试仍绿"。

## 后果

- 28 处删除的最后一个机制前置关闭：观察通道的输入面（存活）与输出面（sink）都不再依赖写权移交。
- **P3-01 的边界被提前画出一格**：`LiveRuns` 正是计划里 `TaskRegistry` 端口的一个切片。
  到 P3-01 时它应当被并入 `TaskRegistry`，而不是让 core 长期持有一个只回答一个是非题的端口——
  这条并入是收敛，不是新增工作。
- `TaskService::new` 多一个参数。全仓构造点只有 4 处（`core_adapter.rs`、`core_adapter_tests.rs`、
  `tests/common/mod.rs`、`task_lifecycle.rs`），所以这不是一次伤筋动骨的改动，也因此
  "为了避免改构造函数而选镜像方案"不成立。
- 一处必须显式接受的耦合：core 从此在决策时同步调用宿主代码。端口实现**不得回调 core**
  （否则就是 Action 4 禁止的那个递归方向），这条要进 adapter 的锁序说明——`RunRegistry` 是叶子锁，
  持锁期间不取别的锁（补记三十四的既有约束正好覆盖它）。
