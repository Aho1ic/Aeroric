# ADR-030：取消与手动完成的标记按任务共享，由最后一个退出者销账

- 状态：已接受（Task P2-05 门禁，Q59）
- 日期：2026-09-23
- 相关：ADR-020（`TaskManager` 按运行重键）、ADR-025（taskId-only 的寻址规则）、ADR-017（同任务允许多代在飞）

## 背景

ADR-020 决策 1 要求 14 个容器一律"按运行这一维度重新表达"，但 `cancelled_tasks` 与
`manually_completed_tasks` 这两个集合不是句柄表——它们记的是**用户做过一个动作**，而这个动作
按 ADR-025 属于意图型（作用于全部在飞代）。于是重键第二波必须先回答：这条账按代记还是按任务记。

源码里的既有事实（本轮实测，不是推断）：

- 今天两个集合都是**读时消费**：`finalize_task_exit` 用 `HashSet::remove(task_id)` 的返回值当判定
  （`pty.rs:157-161`；远程同理 `ssh.rs:1329-1331`、`wsl.rs:951-952`）。所以这条账本来就是**一次性**的。
- 写入点分四族（local / ssh / wsl / dsh），其中 dsh 另有一套自己的 `cancelled_tasks`
  （`dsh_webui.rs:110`），不在 `TaskManager` 内——本 ADR 只约束 `TaskManager` 那两份。
- 起新运行前一定会先清账（`pty.rs:1612-1615`、`ssh.rs:1760-1763`、`wsl.rs:1571-1574`、
  `dsh_webui.rs:1842`），所以"标记残留"不会跨到下一次运行。

## 决策

1. **账按任务记，一条**：`cancelled_tasks` / `manually_completed_tasks` 保持 `HashSet<taskId>` 形态，
   不随代复制。意图型操作**触达**全部在飞代（逐个 kill），但**记账**只有一条。
2. **销账权属于最后一个退出的代**：某代退出时，先把自己从 `RunRegistry` 注销（`remove_pty_handles*`
   已经这么做），再判断"这个任务还有别的代在飞吗"。
   - 没有了 → 消费标记并据此定终态（cancelled / done / failed）。
   - 还有 → **不消费、也不定终态**，与 ADR-017"另有代在飞就不落终态"共用同一条判断。
3. **迟到的退出监视器不得参与销账**：`remove_pty_handles_if_current` 返回 `false`（它的代已经被
   取代）时，既不能销账也不能判据——今天就是这个早退分支，保持不变。

## 理由与被否方案

- **按代记账 + 意图操作 fan-out 写入（推荐方案，被否）**：双开时每一代都能看到"自己被取消了"，
  语义最直白；代价是一次取消写 N 条、退出要按 `(task, generation)` 查，且与"用户点了一次取消"
  这个事实的粒度不符——用户撤销的是任务，不是某一代。
- **原样保留一次性消费**：改动最小，但在 ADR-017 允许双开之后，先退出的一代会把标记吃掉，
  后退出那代的正常收尾会被判成 `failed`。这是行为回归，不是省事。
- 被否方案与选择 B 的共同点：都接受"任务级一条账"，分歧只在**谁来消费**。用户选择由"最后退出者"
  消费，而不是第一个。

## 后果

- 顺序变成硬约束：**销账判断必须在自我 retire 之后**。写反了会把"还剩两代"看成"还剩一代"，
  于是没有任何一代能销账，标记一直留到下次 start 被清掉——任务状态停在 running。这条要有测试。
- 两代同时退出时，销账者由谁先跑到 `RunRegistry::retire` 决定，可能**两代都判定为"还有别的代"**
  吗？不会：`retire` 与"读剩余代"之间不得跨越锁释放（同一把叶子锁内完成，或 retire 后立即重读）。
  这条也要有测试。
- "还有别的代"的判据只能用**已注册**的代集合（ADR-025 的同一口径），不能用 core 账本的计数器当前值。
- `wsl_active_ids`（WSL 侧的"这个任务在跑"）与四张会话表的粒度另计，见 Q60/后续条目；本 ADR 不覆盖它们。
- **顺带纠正一处今天的错误**：`finalize_task_exit` 在消费到取消/手动完成标记时会立刻做清理副作用
  （删任务附件目录、`event_watcher::cleanup_task_events`、`cleanup_task_model_patch`）并 return。
  两代在飞时，今天**先退出的那代**就会去删还在运行的那代正在写的附件与事件目录。ADR-030 的"最后退出者销账"
  把清理也一并挪到最后一代，这是选择 B 相对"现状原样搬"的实质收益，不只是记账粒度之争。
- **消费点必须收敛成一个函数**：`pty.rs:157-161`、`ssh.rs:1329-1331`、`wsl.rs:951-952` 三处各自实现了一遍
  "读并消费"，规则改完后三处都要走同一个宿主函数（否则远程族的退出会按老规则吃掉标记）。
- dsh 侧另有一套 `DshWebUiManager::cancelled_tasks`（`dsh_webui.rs:110`），**不在本 ADR 范围内**：
  dsh 的会话按 task_id 唯一（`active_sessions` 单值 + `begin_task_completion` 幂等），今天不存在两代并存，
  所以没有"谁销账"的问题。等 P3-05 把 DSH 变成 core 服务时再一并处理。
