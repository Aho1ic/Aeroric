# ADR-031：路径 claim 的释放靠反查会话表，不新增持有者状态

- 状态：已接受（Task P2-05 门禁，Q60）
- 日期：2026-09-23
- 相关：ADR-020 决策 3（`claimed_session_paths` 故意保持路径粒度）、ADR-015（转录收养）、P2-05 重键第二波

## 背景

`claimed_session_paths` 是 `TaskManager` 里唯一一个**不按 taskId 键**的容器：它存的是会话文件路径，
职责是"一份 jsonl 只能被一个持有者看着"。ADR-020 决策 3 明确拒绝把它改成 `(task_id, generation)` 键，
因为那样每代都能各自认领同一路径，**互斥消失**。

会话表改成按代键之后，"谁还依赖这条路径"这个问题变了形：同一个任务的两代各自持有条目，但**不可能
各自持有同一个 claim**（认领是全局互斥的）。所以释放规则要回答的是"还有没有会话条目引用这条路径"，
而不是"还有没有代活着"。

本轮实测到的既有事实：

- 四族都是"claim 成功才插条目"：claude/codex 顺序不嵌套（`session.rs:1805→1811/1820`、
  `session.rs:1994→2000`），omp/dsh 则**在持有 `claimed_session_paths` 的同时插会话表**
  （`session_omp.rs:34-47`、`session_dsh.rs:679-691`）。
- 而 `lib.rs` 锁序表第 3 条写的是"`claimed_session_paths` 在 sessions 释放**之后**获取"。
  登记侧与拆除侧顺序相反。今天没有真死锁（拆除侧不跨锁持有会话表），但这张表已经不是事实。
- `release_claimed_session_paths`（`pty.rs:344`）与 `finalize_task_exit` 都是"删会话条目 → 删它的
  路径 claim"，与反查规则的差别只在：**没有查另外的条目是否也引用同一路径**。

## 决策

1. `claimed_session_paths` **继续是路径集合**，形态不变（不是持有者计数，也不按代键）。
2. 释放一条路径的**唯一**规则：先在会话表里删掉本次要销的条目，再反查四张会话表
   （codex / claude / dsh / omp）；**只要还有任何条目引用这条路径，就不释放 claim**。
   这条反查集中成一个宿主侧函数（`release_session_path_if_unreferenced`），所有释放点都必须走它，
   不允许再有"删条目顺手删 claim"的第二条路。
3. 锁序随之定死为**嵌套方向只有一种：`claimed_session_paths` → 会话表**（omp/dsh 的登记侧今天
   就是这个形状）。实现时更正了本 ADR 初稿：初稿写"会话表 → claim"，理由是"拆除侧已经是它"，
   但拆除侧**根本不嵌套**（每个 `.lock()` 都是语句级临时量，取 claim 时会话表锁早已释放），
   所以它不构成顺序约束。真正需要唯一的只有嵌套那一处；改登记侧反而会引入"先插条目、认领失败
   再回滚"的可见中间态。规则因此写成：**谁嵌套谁定序，拆除侧只定因果**（必须先删条目、后反查释放），
   `lib.rs` 锁序表第 3 条按这个意思重写。

## 理由与被否方案

- **持有者集合（`path → {RunKey}`）**：判定最快最局部，但它是第二份"谁持有什么"的账。会话表才是
  事实来源；任何绕过会话表的删条目（收养、handoff、清理路径）都会让那份计数漏，最后变成一条
  **永远释放不掉的 claim**——表现是"任务重跑时报会话被占用"，比现在难查。
- **现状原样搬（删条目即删 claim）**：改动最小，今天也大体成立，因为它赌的是"两代不会引用同一条
  路径"。而 P3-04 的转录收养（ADR-015：core 从未发布过的文件收养一次）与 ADR-028 的
  `claude_gpt55`（Claude 格式转录）恰好都在制造"不同运行指向同一份 jsonl"的场景。赌注会失效，
  失效形式是静默的（两个 agent 往同一文件写）。
- 反查的代价已核：四张表规模等于"活任务数"，释放是低频动作（一次退出一次），不做索引。

## 后果

- 重键第二波里 `finalize_task_exit` 的这段顺序变成硬约束：**删四族条目 → 反查 → 释放 claim**，
  且反查必须在删掉本次条目之后做（否则自己引用自己，永不释放）。这条必须配一条真实测试：
  两代共享同一路径时，先退出的一代不得让路径重新可认领。
- omp/dsh 的登记侧要改锁序，属于**行为等价的重排**（仍是同一临界区内原子完成），但它是本次门禁
  查出来的既有偏差，修它不是顺手重构——锁序表如果与代码不符，后续所有"按表加锁"的推理都不可信。
- 释放语义集中到一个函数后，`tauri-adapter` 门禁可以机械断言："除该函数外，源码里不存在
  `claimed_session_paths.remove(...)` 的调用点"（正控同批配，证明扫描真读到内容）。
