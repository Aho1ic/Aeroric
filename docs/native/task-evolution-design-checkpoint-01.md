后续执行包必须明确目标/非目标、允许文件、业务owner、接口、审批门槛、

- 遵守项目 `AGENTS.md` 与 `.trellis/workflow.md`；本设计/监工线程沿用
  现有planning任务，不自行新建/激活任务。外部执行者仅在用户明确要求
  执行独立执行包后，按其子任务与审阅门槛操作，不以本快照启动整套外壳。
- 仅使用main；本轮不创建分支、提交或推送。先检查协作者dirty文件，
  不覆盖、回滚或顺手修复无关改动。
- 不读取凭据，不安装/运行参考项目，不修改研究材料的忽略或发布规则。
- 按本文和轻量索引逐项回源，不重新扫描全部harness仓库或一次注入整库。
- 本文的场景是后续验收要求，不是已运行、测试通过或四家族已接线的证明。

## 2. 产品目标与演进边界

围绕用户布置的实际任务，在coding过程中同时支持：

1. **项目交付**：主执行者改项目、跑获准验证，完成用户目标。
2. **任务专属能力改进**：改进任务专属Harness副本里的工具实现/执行逻辑，
   形成可追踪候选，经宿主验证与必要评审后受控试用。

两者分开取证，不能把普通修bug、换模型或改提示词自动称为代码自进化。
不默认自改已安装CLI、Aeroric宿主、模型权重或本轮裁判。
权限、审批、验收标准不允许Agent自行修改；是否默认启用本功能尚未决定。

## 3. 已确认的决定

| 问次 | 已确认规则 |
|---|---|
| Q13 | 可改项目及任务专属工具/执行逻辑；不能自行改权限、审批、验收标准；三角色支持不同API/模型，也允许相同 |
| Q14 | 全局三角色默认模板＋当前任务分别覆盖；主执行者改绑不隐式改变监督角色 |
| Q15 | Aeroric统一控制面＋Claude Code、Codex、OMP、DSH适配目标，不是已认证所有家族能力相同 |
| Q16 | 三角色中只有主执行者在授权内写工作区/执行命令；反思与治理只读获准证据，产意见或补丁草案；宿主可保存评审记录 |
| Q17 | 工具候选副本改进→宿主受保护验证→安全点按既有审批自动试用→失败停用并回退工具版本；不自动回滚项目或撤销外部副作用 |
| Q18 | 治理意见由宿主按授权规则阻断对应候选，不任意强停整个任务；旧工具安全、宿主允许时可继续 |
| Q19 | 监督API失败/超时记失败或待审，不算通过/模型否决；缺审候选不启用；有限重试，不静默换API/模型或以主执行者自审替代 |
| Q20 | 普通编码每阶段反思必核对，反思可主动向主执行者发消息；治理是三角色最高监督/复审层，仍低于用户授权和宿主固定规则 |
| Q21 | 反思及既定验证满足后关闭阶段；待核对/待整改只约束依赖路径，安全无冲突的独立工作可继续；治理须及时、独立进程运行 |
| Q22 | 阶段反思新结论、反复失败、角色冲突、方向偏离、候选待启用等关键事件立即通知独立治理侧，异步及时复审；不等长周期/主执行者空闲，不每条命令双审 |
| Q23 | 普通阶段满足Q21后不额外等待治理签字，可关闭并推进依赖；治理仍须及时复审，待审不算通过/免审；候选启用保留必要治理评审 |
| Q24 | 治理须引用既定要求、当前证据和影响范围；允许有限举证复审，实质争议升级用户；有据的验收问题由宿主约束相关依赖/候选，风格偏好不自动阻断阶段 |
| Q25 | 迟到实质漏检仍适用当前版本时，保留原通过记录，局部重开并复核实际受影响依赖链；整改/反思、既定验证及原问题定向复审满足后只解除对应限制 |
| Q26 | 首批外部交付为SwiftUI原生可交互审阅样例，用明确离线数据展示角色配置、阶段/证据与工具候选；不接真实模型、不写真实任务/配置、不启动治理进程 |

Q25中的实质争议仍可按Q24交用户裁决，但不替代工具候选必需评审或既定验证。
API服务故障本身不触发有效工具回退；实际工具故障才按Q17处理。

## 4. 三条闭环必须分清

### 4.1 普通编码阶段

提交当前版本成果→待反思核对→满足既定验证且无未解决验收问题→关闭。
治理在独立进程及时复审，不为每个普通阶段增加额外签字等待。

待核对/待整改时，不推进依赖该阶段的工作；可证明安全、不依赖该阶段、
没有工作区冲突且宿主允许的独立工作可继续。不能把依赖联调改名为
“独立工作”绕过门槛。
反思通过不替代受保护验证，也不等于用户最终验收。

### 4.2 工具候选生效

任务专属副本产候选→宿主受保护验证及必要独立评审→满足既有审批→安全点
受控试用。候选与证据版本绑定，不用旧结论批准新版本。

缺必要评审时不启用；队列拥堵、限流、API失败、证据不足均不能伪装通过。
监督意见不赋予直接写码/执行权，控制面不能被候选工具自行修改或绕过。
具体如何强制保护、评测与切换尚需技术设计，不能只用prompt承诺。

### 4.3 已关闭阶段的漏检

确认有据的验收问题仍适用当前产物→保留原结论/版本/证据并局部重开→
约束实际受影响的后续依赖→主执行者整改→反思、既定验证及治理定向复审→
仅解除对应限制，按新前提补验相关下游。

相关新步骤暂不启动；已开工工作只在家族支持的安全点收束，不假设可截断
任意CLI内部调用。未观察到暂停时，必须显示仍在执行/待收束，而非“已停止”。
不支持安全收束时显示能力限制并升级用户；宿主硬安全和用户Stop仍立即
按已有机制处理，不等待治理。保留下游成果，无关安全工作不必重做。

## 5. 角色、消息与进程的硬边界

- 反思核对“声称完成”与实际证据；治理还监督反思是否漏查、空转或偏离目标。
  治理最高是模型复审层级，不是绝对正确，也不高于用户及宿主固定规则。
- 主执行/反思可举反证，不能静默忽略治理意见；有限复审仍有实质争议，
  汇总双方证据和影响交用户。改变目标/权限/审批/验收必须走既有流程。
- 自动监督消息须具有可信机器来源，不能冒充用户授权；具体消息结构、
  去重/重投/回执尚未确定。入队、进入模型请求、模型处理和验证完成必须区分。
- 治理单独进程，与主执行/反思执行循环分离。不同API/client或同进程线程
  不满足该要求；单独进程不证明OS沙箱、凭据隔离、崩溃恢复或更高权限。
- 反思的进程形式、治理每任务或共享服务、驻留/按需启动与IPC尚未决定。

## 6. 原生界面与四家族兼容边界

- 最终前端为SwiftUI/AppKit，使用真实Apple系统材料；macOS14基线、
  macOS26 Liquid Glass增强门控。浏览器样本不得冒充原生实现。
- 沿用已确认的A样式和stage01圆角/面板衔接；独立图标按钮不增加圆形边框。
  颜色来自语义角色；glass/classic与interactionMode分离。
- 原生相邻互斥控件采用系统选择态，共享规则在
  `macos/AeroricKit/Sources/AeroricUI/Design/NativeSelection.swift`；
  不自行绘制邻接项选中底色/下划线。若另做React审阅样本，须走现有工具链及
  `src/components/ui/AnimatedSelection.tsx`，不另造无关单页。
- 业务对象由Rust core持有，host执行，protocol承载类型化契约，原生UI负责
  呈现和交互；UI不靠解析ANSI/CLI文字判业务通过或模拟执行事实。
- OMP保留原生PTY/TUI，不传`--mode`、不复活rpc-ui；新core历史发现只在
  `~/.aeroric/agent-homes/**`，不顺手改变旧Tauri外部历史行为。
- DSH自动监督反馈不得经普通user来源冒充人类授权；投递ACK不是消费证明。
  四家族的实时反馈、安全点/暂停与热加载能力必须分别验证，不一概声称支持。

## 7. 后续验收场景——本轮未执行

| 场景 | 必须体现的结果 |
|---|---|
| 接口待反思核对 | 依赖联调等待；安全独立文档可以继续 |
| 普通阶段已满足反思/验证，治理排队 | 普通阶段可以关闭，治理仍显示待审而非已通过 |
| 工具候选缺治理必要评审 | 保持不启用，不以阶段通过代替 |
| 监督API失败/超时 | 明确失败/待审，不静默换模型、不自审替代、不自动回退有效工具 |
| 两个模型都说通过，治理提出实质问题 | 依据既定要求和当前证据复审，不按票数决定事实 |
| 原结论针对旧版本 | 不自动套到新版产物，先核对当前适用性 |
| 已关闭阶段发现当前实质漏检 | 留史、局部重开、定向约束依赖，保留成果与安全独立路径 |
| 监督消息已发送但未确认暂停 | 不显示已停止或已整改 |
| 只是风格偏好或要求改变验收标准 | 不自动阻断阶段/自改标准，实质争议按Q24升级 |
| 工具故障回退或阶段重开 | 不声称自动撤销项目代码与外部副作用 |

## 8. 仍需技术设计，不能默默补成默认值

1. 阶段划分、可信完成事件、版本/证据引用、实际影响传播与冲突判据。
2. 模型结论如何由宿主依固定规则落实；证据充分性、权限与受保护验证的
   具体强制机制，以及任务副本/候选隔离和安全切换。
3. 独立治理进程的IPC、生命周期、凭据/获准证据范围、故障与重启恢复。
4. 机器消息的来源、持久化/去重、投递/处理/整改回执，以及四家族安全投递点。
5. 启用默认值、超时、有限重试/复审的具体额度、排队/并发/预算与升级阈值。
6. 运行中改绑API/模型如何影响在途请求；不存在默认静默fallback许可。
7. 跨任务知识/工具继承、长期收益验证及原生界面的具体布局。

上述未决不否定已确认原则，但不能靠一份设计快照直接交付整个演进引擎。
后续执行包必须选择可独立验证的子集，并列出仍不能连接真实执行的边界。
