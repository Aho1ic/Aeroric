## 手写约束（`--check` 只重导上面那张表，本节不会被覆盖）

> 每条都在 2026-09-28 当场回源验过，判据是文件里的实际行为，不是计划或 AGENTS.md 的转述。

1. **落点目录叫 `sessions/`，不叫上表机械推出来的 `session/`。** P3-04 正文要求的是 `core/crates/aeroric-core/src/sessions/{mod,discovery,registry,parser,claude,codex,dsh,omp,history,resume,export}.rs`。搬迁时按正文归并，**不要**真建出 `session/`、`session_dsh/`、`session_omp/`、`usage/`、`usage_index/`、`analytics/` 六个平行目录——那正是 §5.1 "不得把缩写当成另一个新工程" 禁止的形状，也会把一个模块拆成七个真相源。上表的 destination 是生成器按"模块名＝目录名"机械产生的，是**索引**不是**方案**。

2. **OMP 的读取根进 core 必须收窄，且不得顺手删旧行为。** 今天 `session_omp.rs` 往发现列表里推三类根：托管档案 `~/.aeroric/agent-homes`（`:127`）、用户自己跑过系统 omp 的 `~/.omp/agent/sessions`（`:136`）、以及 `~/.omp/profiles/<name>/agent/sessions` 的档案枚举（`:142-145`，注释自己写明对应上游 `dirs.ts::resolveActiveAgentDirOverride` 的语义）。AGENTS.md 的 "Native OMP session history boundary" 与 INV-06 已定：**新 core 只许 `~/.aeroric/agent-homes/**`，外部历史导入分支 capability 默认 false**，只有满足 ADR-001 §5 的评审才能开启。搬这两支时既不借迁移静默扩权限，也不删旧客户端的现存行为。

3. **"omp 无超时"与"dsh 有超时"这两句要分开验，后者的落点不在 `session_dsh.rs`。** omp 是 mtime 比较：`session_omp.rs:208-240`，`modified_ms <= since_ms` 直接跳过（`:178` 的注释解释懒会话为什么不能被窗口漏掉）。而 grep `deadline|timeout` 在 `session_dsh.rs` **0 命中**——真正的时限窗在 `session.rs:1876-1890`：`start_elapsed >= 1500ms`、`first_output_elapsed >= 1s`、`start_elapsed >= 8s` 三档结算条件。**动 P3-04 之前必须先判清这张窗属于哪个家族、删掉它会不会改变 done/input_required 的时机**；照 AGENTS.md 那句"不像 dsh 那样有 deadline"直接给 omp 造一个补偿性超时，是拿文字推断替代行为。

4. **`claimed_session_paths` 保持路径粒度，是 ADR-020 §3 写明的例外，不随重键改。** 站点：`session.rs:97` 取锁，`lib.rs:1278`（登记）、`:1287`/`:1293`（反查是否仍被引用）、`:1310`（释放）；锁序声明在 `lib.rs:118`——嵌套方向只有一个，`claimed_session_paths` → 会话表。会话四张表已按 `(task_id, generation)` 键（P2-05 重键 wave 2），claim 仍按路径。P3-04 的验收"同一文件不能给两个 task"就靠这条路径级排他，改成任务粒度即失效。

5. **cwd → 目录名的编码是纯函数，必须逐字符对齐上游。** `omp_project_dir_name` 在 `session_omp.rs:71`，两处 `replace(['/', '\\', ':'], "-")` 在 `:81` 与 `:88`；三分支是 home 相对 `-<rel>`、temp `-tmp<rel>`、否则 `--<absolute>--`。搬进 core 后要一条"同一 cwd 两侧算出同一目录名"的用例，注释不算证据。DSH 侧同理：`session_dsh.rs:6` 的 `--<项目路径 slug>--/<转义会话id>/session.jsonl[.zstd]`。

6. **引用解析阶梯的计划行号已经漂了，按符号搬。** 计划 P3-04 Acceptance 写 `src/state/app/taskLifecycle.ts:549-615`，实测（2026-09-28）阶梯落在 **:574 / :592（`invoke("read_session_id")`）与 :607（`recover_task_session`）**。四级顺序（记录里的 family 字段 → 按 path 读 session id → legacy 字段/path → recover）都要在 core 有对应判定，而 core 只保留"解析不出 session 就拒绝续跑"这一条；`local 且 worktree 未丢弃` 的前置条件别在搬运中丢失。

7. **usage 三件套的验收重点是"重放不重复计费"。** `usage_index.rs:1418` 的注释写明续扫只读新增尾段、已封存前缀既不重复计数也不丢；`:1608` 的 `a_claude_dedup_group_is_never_split_by_the_cursor` 守住 dedup 组不被游标劈开，`:527` 解释了为什么必须收成一条。P3-04 Action 4 直接复用这两条判据；terminal 文字一律不作计费依据（INV-12）。另有一处**必须收成一份**的分叉风险：`analytics.rs:58/72/84` 用**内容嗅探**回答"这份转录属于哪个家族"（`:264` 就用它选解析路径，`is_zstd_usage_log` 在 `:1073`），而 `session/parse.rs` 是按家族**显式分派**的解析器（`parse_claude_session`/`parse_codex_session` 等 9 处引用）；`agent_usage.rs`/`usage.rs` 里没有第三份判定，但这两套口径一旦各自进 core，改一处就会与另一处分叉——P3-04 落 `sessions/{claude,codex,dsh,omp}.rs` 时应当让内容嗅探只做一次并复用同一答案。

8. **DSH 转录有两种物理形态，且切换会留旧产物。** `session_dsh.rs:36`/`:38` 是 `session.jsonl` 与 `session.jsonl.zstd` 两个常量，后缀由插件的 `compression` 决定（`:9-10`：Aeroric 受管 patch 请求 `none`，插件默认却是 `zstd`）；`:111-115` 说明**从 zstd 切回 none 之后同一 root 里旧的压缩产物仍然存在**，所以读侧必须两形都试。core 里新增解压依赖之前先看这里用的是哪个 crate，别引入第二个 zstd 实现。
