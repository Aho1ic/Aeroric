## 2. 本阶段已确认的分层

1. **工作配方：如何做。** 起步可不选或选一个，复杂任务在共同主计划
   分阶段使用不同方法，不直接把多个配方指令混拼，也不强制另开会话。
2. **组合能力：谁来协助。** 团队协作、独立审查、任务工具进化可叠加，
   不与配方互斥；首次普通会话只启用主执行者，必要验证不免除。
3. **执行配置：用什么执行。** 各角色独立执行器 / API / 模型 / 强度，
   权限另行显示；上下文、工具资源、环境、护栏分组，不塞进工作方法。
4. **任务工作面：开始后去哪里。** 计划、沟通、成果、证据、工具知识
   关联同一任务；不把所有任务中功能都放进新建表单。

工作方案复用配方 / 能力 / 各角色执行配置及资源引用，必须明确应用，
不复制提示词、附件、凭据、权限或单次授权；更新不追着旧草稿改变。
恢复项目草稿优先，切页不重套默认；同项目成功发送后的下一份草稿
保留配方 / 能力选项，不复制旧运行、团队实例、工作包或监督结论。

## 5. 用户可手动核对的主要路径

- 写提示词 / 选择模型、权限、配方与能力 → 全部任务 → 原项目「＋」：
  原草稿恢复；切另一项目不会混入相同内容。
- 浏览配方，选择“项目体检”，搜索“技术债”仍可找到；另存为
  “发布前体检”不改变内置原版，保存后需明确选用。
- 独立审查与进化同时启用：审查者、反思者、治理者分别配置；
  改主执行配置不联动监督，必需监督缺配置时具名受阻。
- 打开工作方案：先预览角色 / 模型等变化，再明确应用；
  内容 / 归属 / 权限不变，方案不能静默关掉已有能力。
- 审阅工具模拟方案新版本：旧草稿和模拟会话不自动切换。
- 文档配方选实际 DOCX：提示缺生成 / 检查依赖；不自动降级为文本。
- 模拟成功原地展示会话；明确失败保草稿；交办未知先核对、不重发。

全部为假数据交互，不是产品验收路径已经运行的证据。

## 6. 下一终端能做什么、不能做什么

当前可做：审查文档与稿件是否漏掉既定功能、指出差异、协助整理待审
视觉反馈。不要把“可审阅”写成“已批准”。

用户逐屏视觉批准后，才可另行形成带范围、真源、适配矩阵、非窗口测试
和明确验收门禁的原生实施包。候选实现应沿现有 Rust core / host /
protocol 扩展；SwiftUI 只消费客户 API，不拼 Agent argv、读原始 JSONL
或写共享业务数据；单数据根只有一个 writer。

继续使用 Claude Code / Codex / OMP / DSH 和 custom，不做第五编码内核。
监督只读、治理独立进程但不是第二 writer；新技能安装 / 更新仍人工同意。
Full Access 不取消这些约束，也不更改固定权限 / 审批 / 验收规则。

不启动 App / Preview / 浏览器自动化 / XCUITest / AX；不创建、克隆、
恢复、准备、下载或启动 VM，不以 Docker / 桌面替代绕过暂停。
浏览器仅允许本轮已审查的纯离线稿手动预览；原生 UI 仍 NOT RUN / DEFERRED。
