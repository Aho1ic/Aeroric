## 1. 分成三个工作面，避免把添加连接变成设置大全

1. **设置 / 网络**：代理唯一真源。
2. **添加连接**：API / 官方账号两条路，保存基础连接及选中的模型规则。
3. **模型与能力**：相同编辑器可在添加时打开，也可从已保存连接进入；
   不复制一套模型库。Agent配置按工具引用，任务选择这些模型/推理选项。

仍保留保存连接后可跳过的Agent配置引导，不因模型选择自动建配置或设默认。
不在添加连接面改任务权限、角色监督、MCP或技能授权。

## 2. 设置 / 网络：只在这里配置代理地址

建议展示代理类型、地址/端口、可选认证、绕过列表及手动连接检查。
密码由host安全存储；UI只回显是否设置，不显示完整密码或含密码URL。
不修改系统代理。已有旧代理覆盖应显式迁移/提示冲突，不默默丢弃。

添加连接只剩一行：

```text
☐ 使用设置中的代理       HTTP · 127.0.0.1:7890     前往设置
```

推荐默认不勾选；未配置时仍可看见入口，但勾选后须补齐设置才能执行网络动作。
勾选表示使用指定全局代理，不勾选表示显式直连；不得因为代理出错偷偷直连，
也不得因环境变量让“直连”暗中走另一个代理。回环回调始终直连；
其他绕过规则显示实际有效结果。

host发出的目录/额度/授权交换请求与适配后的Agent网络路径要分别验证；
外部系统浏览器不自动受Aeroric代理控制，界面要说明而不是修改浏览器设置。
不能让配对手机的新请求通过此开关绕过现有内网/SSRF边界。

每个在途请求固定代理版本；设置更改不重启Agent，不暗换运行任务网络快照。
新任务/新检测采用已提交版本；运行任务需要显式受支持的安全更新流程。

## 3. API 添加：上半部连接，下半部模型

```text
名称                         API 协议
Base URL                     API Key（安全输入）
☐ 使用设置中的代理          简短状态 / 前往设置

模型                                      获取模型   ＋ 手动添加
搜索模型…                                 已选 3 / 12
☑ 映射名称      上游模型ID       上下文      最大输出      能力/推理
☑ 日常编码      example-code    128K        16K          文本 图片 · 3档
☐ 深入分析      example-think   未知        未知         能力待核实

高级设置（折叠：超时/请求头等，不再出现代理地址）
取消                                           保存连接
```

数字和名称只是布局样例，不是任何真实模型能力或生产默认。
保持圆润Sheet、轻量分隔、柔和点缀色与灰黑深色，不为每个单元格再套玻璃卡。
宽屏使用紧凑列表，容量/输出/映射名可直接编辑，能力与推理用原生popover/
disclosure；窄屏选中行展开同一编辑器。不是每行都常驻多层表单。

**获取模型**：

- Base URL / Key / 协议满足本地校验后才启用；点击才发出目录请求。
  保存并非前提，host可持有一次性的受保护草稿凭据句柄。
- 默认只获取目录，不自动推理、不自动余额采集；推理测试另作具名授权。
- 成功展示搜索、勾选、只看已选、手动添加；批量勾选需显示当前筛选范围，
  不把“全选当前结果”误作隐藏模型全部选中。
- 目录不存在/鉴权失败/网络失败/返回格式不支持分开显示。失败保留草稿；
  手动添加不依赖发现成功。可以只保存连接、稍后配置模型。
- 获取中可取消；按URL/协议/Key版本和请求ID匹配结果，过期响应丢弃。
  刷新不覆盖手动映射、能力覆盖或旧任务，不静默删除下架模型。
- 模型来源标“账号目录 / 公开资料 / 手动”，单独标“调用待验证”。
  不用公开目录掩盖无效Key；不跨未确认域发送Key，不盲跟跨域重定向。

## 4. 模型规则：显示、路由与能力分开

每一条建议包含：

| 字段 | 用户体验 | 实际约束 |
|---|---|---|
| 映射名称 | 新建任务里显示的友好名称，可编辑 | 显示名不当上游ID；内部有稳定model entry ID |
| 发布/请求别名 | 高级设置，可选 | 如需CLI请求别名，由适配器映射；在连接/发布范围校验冲突 |
| 上游模型ID | 可查看/手填 | 固定实际来源；别名不允许偷偷转到其他账号/模型 |
| 上下文窗口 | token整数，可显示K/M单位 | 保存精确值、来源/时间与用户覆盖；填大不扩展真实能力 |
| 最大输出token | 独立整数 | 与协议/真实上限及共享窗口预算校验，不等于本次必用输出 |
| 输入类型 | 文本/图片/PDF等复选，音频/视频按适配显示 | 勾选是配置允许/手工声明，不冒充实测；原始未知类型保留来源 |
| 实际兼容性 | 支持/受限/待验证/不支持 | 结合模型＋协议＋Harness＋授权，不只看一个供应商标签 |

目录声明、补充资料、用户覆盖、实测观察分层保存，不用刷新把覆盖抹掉。
PDF原生输入与本机提取成文本是不同路径；不支持时明确说明/征求转换，
不能背后把用户文件上传到另一个服务。音频/视频也不因勾选就自动转码或外发。

## 5. 推理规则：用户命名，适配器发送真实参数

每模型一项“启用推理档位配置”；开启后可添加/删除/排序若干档位。
每档包含稳定ID、显示名称、实际映射方式/值、适用范围，以及可选默认。

| 显示名称（可任意改） | 映射样例（只对支持的模型适用） |
|---|---|
| 轻快 | 枚举 `low` |
| 均衡 | 枚举 `medium` |
| 深入 | 枚举 `high` |

支持预算型上游时改为明确的token预算，不能把预算值装成所有供应商通用effort。
提供协议适配器定义的typed字段，不给任意JSON/脚本改鉴权、目标域或安全终检。
模型支持三档时可重命名/取子集；未知档位可编辑但必须明确未验证，
已知不支持的参数不得伪造成功或静默夹成别档。

**关闭此配置**表示不向用户提供这些自定义覆盖、按已声明的上游默认处理，
不保证模型停止思考。若模型支持真正关闭推理，另提供有真实参数映射的“关闭”
选项。必需推理的模型不得显示虚假的关闭成功。

新建任务选择相应模型后只呈现该模型/配置/Harness适用的档位显示名，
提交稳定ID及版本，host解出真实值。切换到不兼容模型时保留旧选择并具名待处理，
不暗中换档；编辑规则不回写旧任务。主执行/反思/治理分别读取各自绑定。

## 6. 官方账号：先选来源，不以原始token作为统一入口

建议顶部仍选择Codex / Claude Code，下方用系统选择控件表示：
**本机已有账号 / 浏览器授权 / 批量导入**。

### 6.1 本机已有账号

首次说明读取范围并授权；之后进入本机来源时自动识别允许来源的账号标签、
工具、组织/工作区及登录状态。只读原版工具支持的状态来源；来源不明、
无权限或离线时明确待核实，不扫描整个Home/历史或遍历全部Keychain。
提供刷新和更换授权来源，macOS沙箱权限通过受支持平台方式获取。

发现后显示“关联此账号”；关联不是复制所有配置或读取历史。
可安全复用则明确授权owner和工具适用范围；无法在现有受管环境安全复用则
保留发现结果并引导官方重授权，不能一边继续强制隔离Home，一边假装登录自然继承。
账号变更后不把原引用静默指向另一用户。

### 6.2 浏览器授权

开始→打开官方登录→等待自动回调，另有“手动粘贴回调链接”兜底；
保持本次state/PKCE/nonce/精确回调地址及过期时间。粘贴仅解析当前待授权流程，
不打开该URL、不向其中任意目标交换token；校验后走固定官方端点。
完成/取消/过期互斥，重复回调不得覆盖另一账号。整条回调/密钥不得进日志或持久草稿。

Codex只用适用的原版流程或合资格官方应用接入，不能借CPA客户端身份；
Claude由未修改的原版Claude Code完成登录/人工代码输入，
不设计Aeroric自建Claude.ai登录器或通用订阅桥。

### 6.3 CPA 批量导入

一个入口多选若干JSON，或拖入允许范围的文件；本版不声称CPA原生有数组/ZIP导入。
暂存解析→预览勾选→一次确认导入所选→逐项结果，不逐账号弹十几次确认。
显示新增/重复/冲突/不支持/待重新授权；不按文件名或邮箱直接覆盖。
解析成功与授权有效、适配可用、可入账号池分开。

仅支持明确版本/认证类型；Codex外层认证和SIWC分区不能混成同一注册。
Claude.ai订阅token不纳入Aeroric第三方凭据库，给出原版登录入口。
导入的proxy_url/headers/脚本/路由规则不自动执行；代理回归全局设置。
需明确同一轮换凭据不由原CLI/CPA/Aeroric多个owner并发刷新；
无法成立则重授权，不假装复制一份就安全。

秘密经host受保护暂存/安全存储，不在SwiftUI返回token或写临时明文；
跨凭据库/业务记录的部分写入需具名补偿与收据，不宣称天然跨系统事务。
不自动加池、设默认、发布Agent配置或发送测试请求。

## 7. 原生实现落点与审批边界

复用Rust的ProxySettings、SecretStore、model_detect/model目录、local_router
及受管Agent适配，但新增返回须区分模型来源/覆盖/实际映射；旧Vec<String>
与单effort字段不能直接证明此闭环已满足。现有探测顺带查余额的行为不能
不经说明套到新“获取模型”按钮。SwiftUI仅通过typed client收投影/发命令，
凭据与网络/校验/发布在core/host单writer；无第五Agent或第二常驻网关。

正式端仅SwiftUI＋Apple原生Liquid Glass＋系统选择/动画，
复用NativeSelection、Toggle、List/Table、DisclosureGroup、Menu及原生文件导入。
不照搬React/Tauri界面、Go服务或第三方布局/动画库。
尊重减少透明度/动态效果、增强对比度；正文可滚动不显示滚动条。
iOS/iPadOS是受信host的原生控制客户端，不承诺读取另一台设备本机CLI账号。

以下均需独立浏览器设计稿和用户视觉批准：全局代理设置、API/模型列表、

受影响的选择状态。不以本提案认可替代逐屏审批，不改已确认V3主屏。

## 9. Q133原提案：规则维护一份，配置引用，任务固定版本

本节形成时待答，不随Q132一并批准；后续Q133确认回执见§10。
要解决的是：模型及推理档位只在
一个地方维护，同时不能让修改一条规则就静默改变四种工具、未发送草稿或运行任务。

可选路径的取舍：每个Harness复制一份容易漂移；所有引用无条件跟随最新
虽省操作却会改掉既有选择；推荐**单一规则源＋版本引用＋明确应用更新**。

### 9.1 三层责任

| 层 | 推荐负责 | 不负责 |
|---|---|---|
| 连接 / 模型与能力 | 该连接内的稳定模型ID、上游ID、映射/显示名、容量、输入类型及推理档位定义；保存版本及来源 | 不将同名模型跨连接合并；不自动发布到四工具 |
| Agent配置 | 引用模型规则的已接受版本，按Harness选可用子集、默认模型/档位及受支持的执行预算 | 不复制第二套模型库、不自造无映射档位；预算不能虚增真实能力 |
| 新建任务 / 各角色 | 选择配置版本及稳定模型/档位ID；提交时由host校验并固定有效执行快照 | 不提交显示名称作为上游参数；不因主执行切换而改反思/治理 |

重命名档位只改变其标签，不自动改变实际参数；更改实际参数属于规则修订。
新建任务显示用户命名，host按所引用版本解析实际值。
本节不决定账号池/故障转移策略，也不把所有模型认作四工具通用。

### 9.2 更新如何抵达配置和草稿

1. 保存模型规则形成新版本，显示受影响配置及差异；可在同一保存流程明确
   应用到选中的配置，形成配置新版本。不逐条重复弹窗，不自动替用户全选更新。
2. 未应用的配置仍指向原已接受版本；新增/删除模型、修改映射或推理参数
   不因目录刷新静默传播。新建配置可主动选用新版本，不自动成为默认。
3. 新建任务按所选配置的已接受版本提供选择。已保存草稿保留提示词、模型、
   档位与配置版本，提示有更新并可查看；用户确认后才迁移。
4. 原选择已失效或不兼容时标出具体原因，发送前要求处理；不清空输入、
   暗换默认模型/档位/账号或自动代发。仍受支持的旧版本不因“有更新”强迫迁移。
5. 运行任务不因编辑模型规则而切换模型、参数或重启Agent。固定快照不是固化
   凭据、权限或有效性：撤销、禁用、真实兼容限制和发送前安全终检仍生效；
   不用旧版本继续绕过失效授权，不自动换账号来补救。

主执行、反思与治理可各自引用不同连接、模型和配置；一个角色接受更新
不联动其他角色。本节只讨论配置传播原则，不批准自动刷新/实测、凭据发布、
运行任务热更新或业务协议。受影响界面仍须浏览器稿逐屏审批；
V5浏览器稿**尚未制作，未获视觉批准**。

- 授权完成后先展示经允许来源确认的脱敏账号/组织、授权来源与适用范围，

  不因浏览器显示成功就自动覆盖已有账号，不自动加池、设默认或建Agent配置。

- 取消/过期后保留非敏感表单，重新授权开启新一轮，不自动后台重试登录。

  上游可能已授出的权限，也不擅自登出原版工具。
