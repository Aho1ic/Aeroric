## 3. 一个几何所有者，两个内容职责

布局契约：

```text
顶部系统窗框/工具区
┌───────────┬─────────────────────────────────────────┐
│ 左项目/任务 │ Content envelope（连接/冷启动状态的宿主）  │
│            │ ┌──────────────────┬─────────────────┐ │
│            │ │ 中央任务 / 预览    │ 右文件 / Git清单 │ │
│            │ └──────────────────┴─────────────────┘ │
└───────────┴─────────────────────────────────────────┘
底部非交互状态文字
```

- 共享壳按已确认25pt面板圆角、横向/底部7pt留白、6pt栏间距分配宽度。
  保持具名主壳变体，不全局改`DSRadius.xl`或重写历史review samples。
- 一个窗口级布局所有者计算左栏、中央、右栏与content envelope预算；
  子视图消费预算，不再自行套第二套splitter/最小栏宽或重复扣边距。
- content envelope负责连接阶段、禁用覆盖层、既有bootstrap信息与稳定
  内容身份；它不是包住中央和右栏的又一层有边框大卡片。
- 中央与右栏各有一个视觉面板；不得在内层再次生成完整任务/完整Git双栏。
- 检查器仍可显式开关；三栏样本均展开以便审稿，不据样本改变默认开关
  或用户现有选择。窗口缩窄和项目切换不自动关闭/打开检查器。
- 非本版工作面保留原内容约束与既有入口；不把新三栏强加给账号等页面。

### 3.1 已确认样本与本稿预算细化

右栏展开时，横向留白14＋两道间距12＝26pt；原生不扣浏览器外轮廓。

| 壳可用总宽 | 左栏 | 中央 | 右栏 | 留白/间距 |
|---|---:|---:|---:|---:|
| 1260 | 240 | 714 | 280 | 26 |
| 1220 | 200 | 714 | 280 | 26 |
| 1180 | 200 | 714 | 240 | 26 |
| 1000 | 200 | 534 | 240 | 26 |
| 1728 | 240 | 1182 | 280 | 26 |

1260与1000两行已向用户展示并获确认；1220/1180/1728是本稿推导样本，
不称用户已经看过全部组合。本次整稿细化：默认未拖动时以中央714为
收缩保留目标，先从左240让出40，再从右280
让出40；1180以下由中央继续收缩。714是目标，不是硬性最小宽度，不能
复制旧fixture算法后把合法1000pt样本误判为不支持。

初始窗口1260×800，仅用于没有用户恢复尺寸的新窗口；首次显示适配当前
屏幕可用区域，不重置用户已恢复的窗口。最低1000×640不变，不声称支持
400pt产品窗口。设计样本不含系统阴影；原生按实际壳bounds预算，不把
`NSWindow.frame`、内容bounds与网页外框混算。
若可用区域或辅助设置使1000×640与可读内容不能同时满足，明确回报该
限制，不自动降下限、缩字或裁切来声称支持。

### 3.3 顶部、底部与宽屏

## 4. 字体与密度是一套角色，不是全局缩放

| 角色 | 已确认字号 | 已确认行高/高度 |
|---|---:|---:|
| 文件树、Git文件名 | 12pt | 文件行24pt |
| 项目名称 | 12pt | 项目行28pt |
| 正文/任务阅读文字 | 13pt | 20pt |
| 代码、diff | 12pt | 18pt |
| 计数、路径提示、辅助文字 | 11pt | 依控件内容，不压缩命中区 |

本次整稿细化：任务导航行与项目行同为12pt/28pt；内容小标题最多
16pt/22pt，不再沿用巨大欢迎标题。它们是新稿参数，不是已经获逐屏
视觉批准的原生常量。

- 可控文字统一JetBrains Mono；中文系统苹方、emoji系统回退。
  使用已有官方v2.304字体与OFL，不系统安装或重新下载。
- 浏览器新稿和原生各自明确字体采用证据。sfnt元数据/哈希不能证明实际
  渲染。原生系统管理文字若不能通过公开API采用字体，保留系统行为并
  单列差异，不重画系统菜单来伪装“全字体已统一”。
- 树名称单行省略，完整名称/路径可由辅助标签、悬停提示与中央页头读取；
  不另占路径副行。树层级每级14pt作为稿件细化，不重复累加List缩进。
- 文件行连续排列，不额外加行间gap；展开箭头和图标有固定槽，计数不
  挤掉名称/“＋”。长名称不自动缩字，树也不因长名而增高。
- 13寸/27寸同逻辑度量，尊重系统显示缩放、手动可读性和辅助设置；
  不承诺不同屏幕缩放/观看距离下物理毫米完全一致。

## 5. 左侧项目、任务与统一新建

项目行从左到右为展开箭头、图标、单行名称、必要计数、固定28pt“＋”槽。
普通行无底色、无胶囊边框；hover反馈与持久选中分离。选中使用系统
`List(selection:)`，尊重系统强调色/高对比，不另画深色active托盘。

“＋”常驻、低强调、可辨识；hover/键盘聚焦增强。它是独立动作，不吞掉
行选择或折叠事件。点击精确进入该项目草稿，复用统一新建入口；保留其
已存在草稿，不因点击新建重置另一项目内容，也不直接启动Agent。

全局新建继续不偷偷绑定一个最近项目。无项目上下文时，右栏明确显示
“先选择项目”，不借别的项目填充文件。所有可用性、未知提交锁定、成功
回执后清草稿/导航、Q119/Q120偏好规则继续消费既有typed契约。

## 6. 中央：两个固定入口，一个预览目标

中央导航只有“当前任务”和“预览”两个入口；预览未选资源时不可误作
内容已加载。文件树点击、Git变更点击及本版内的文件链接都进入同一
中央预览目标，保留真实项目身份与资源种类，不跳右栏/自动开外部App。

文件/变更切换只替换该临时目标，不创建多标签、不增加固定/重排/关闭
全部等IDE管理功能。返回统一用“当前任务”；本版不另做一套页签恢复系统。

本次整稿细化：显式点击左侧任务会选择该任务并回到当前任务页，之前的
预览描述/阅读位置仍保留在该窗口×项目现场；不能为了恢复预览而拦截用户
明确的任务导航。同项目任务切换不清空右侧清单现场。

### 6.1 当前任务与新建页

- 新建状态用V6真实结构：项目/cwd范围、输入区、配置/模型/强度/权限
  控件和能力状态；不再以“后续接入”大段文字填满中央。
- 运行状态展示当前任务标题、执行/阅读区、既有输入区与真实状态来源。
  设计稿只用虚构输出片段，并显著标注fixture，不调用Agent。
- 原生仍使用既有真实交互PTY及原始输出，不恢复RPC UI，不从ANSI
  推断工具、审批、完成或权限。未知内容保留来源，不能自动批准。
- 当前任务页保持稳定身份；切预览/切外观不重建Agent或修改session、
  model、permissions、cwd、PTY generation，草稿和任务滚动位置保留。
- 预览激活时不能向隐藏输入区发键盘/resize。按既有GR10离开可输入
  任务面的规则主动释放持有权；返回不自动接管、不补发输入。
  host权威票据仍是后续独立业务门禁，不能仅靠Swift布尔值假装已实现。

### 6.2 文件与diff

- 页头显示项目、完整相对路径、资源类型、只读/缓存状态；长路径可换行
  或选择复制，不把文件树撑成双行。完整路径不以另一个项目替代。
- 文本/代码保持原始内容，行号和正文可读；长行横向滚动，不裁切后称
  完整。Markdown可以只读呈现，不执行嵌入HTML/脚本或自动导航外链。
- 统一diff单列展示，含旧/新行号、上下文和`＋/−`文本标识，不靠红绿
  单独编码；暂存/未暂存/未跟踪来源分别标明。不能自动暂存、提交或回滚。
- 图片/PDF等仅在既有受支持只读查看器存在时使用；二进制、过大、
  不支持类型、不可读或受限链接，在中央显示具名状态/元信息，不能
  假装成功预览、擅自追外部路径或退回右栏。
- 编辑和复杂Git显式进入既有完整工作区；缺少真实客户端能力则明确
  受阻，不造可点击但无效的成功入口。原工作区不被本版替换或删除。

## 7. 右侧仅负责定位资源

顶部使用一个系统左右分段“文件 / Git”，不是两排独立胶囊。
原生复用`NativeSelection.swift`中的系统包装；不手画移动thumb/下划线。

文件区：项目范围/刷新状态、一棵紧凑树、必要计数。目录操作只展开，
文件动作把目标交中央。Git区：分支摘要和已暂存/未暂存/未跟踪清单，
不在280或240pt栏里嵌完整`GitPanel`、历史与第二个diff。

切换右侧分区只改变清单，不自动替换已经在中央阅读的资源或任务；
选另一个文件/变更才替换预览。同项目换任务保留清单分区、展开和滚动。

## 8. 状态所有权与读取安全

| 所有者 | 负责 | 不负责 |
|---|---|---|
| 窗口布局状态 | 可见性、期望/有效栏宽、导航与焦点 | 业务持久化、跨窗口覆盖 |
| 窗口×项目阅读现场 | 文件/Git分区、树展开/选择/滚动、当前预览描述与阅读位置 | 关闭/重启恢复、修改任务/Agent |
| 既有窗口草稿/任务阅读owner | 草稿、稳定提交身份、当前任务及其阅读现场 | 另建一份共享业务状态 |
| Rust core/host与typed client | 资源读取、业务写入、执行身份、输入/resize权威票据 | 让Swift构造argv或解析原始会话JSONL |

预览目标至少区分项目、资源标识、文件/diff种类及变更来源；读取请求再
携带独立的请求代次。旧请求晚到不能覆盖新项目/新文件；读取代次不是
PTY generation，不可据此重启PTY。缓存来源/版本若不能核实就标未知。

读取状态必须分别覆盖：

| 状态 | 清单/中央处理 |
|---|---|
| 未加载/加载中 | 说明正在读取，不伪装空目录或零变更 |
| 已加载且真实为空 | 独立空状态与项目身份 |
| 失败 | 原因及显式重试；原有缓存有则标出，不能变“ready” |
| 缓存/过期 | 保留来源和缓存标记；不称实时 |
| 目标失效/项目不可用 | 中央具名受阻，不默选其他文件/项目 |
| 不支持/受限资源 | 中央解释限制，不自动写入、授权或打开外部资源 |

切项目恢复该窗口该项目现场，窗口A与B互不覆盖。离线稿用两个虚构项目/
窗口和内存状态即可；不使用localStorage/IndexedDB、真实路径或网络。
预览内容只保留当前目标所需数据，其他资源仅存轻量阅读位置，不无界缓存
文件正文；窗口关闭清理这批场景状态，不产生新的业务持久化。

## 9. 原生材质、颜色、系统状态与可访问性

- 原生产品仍是SwiftUI/AppKit桥接；Liquid Glass使用Apple原生能力，
  阅读正文维持稳定底色。最低平台目标按Apple-only基线，不以CSS blur
  或旧系统仿玻璃替代已确认的目标。
- 复用现有语义色和设计原语：基础/侧栏/阅读底、主次文字、必要边界、
  强调与状态角色统一。亮暗模式不各造一套品牌色，差异不靠加深孤立卡片。
- `glass/classic`与`native/advanced`分离；改变外观不改变业务状态。
- 减少透明度时稳定不透明阅读底；增强对比度时强化必要边界；减少动态
  时取消非必要动画。默认无胶囊边框不等于删除键盘焦点环或高对比边界。
- 选中、页签、分段交系统`Picker`/`List`等；裸“＋”、披露箭头与开关
  按其独立动作处理，不用手绘active背景冒充系统选择。
- 文件名称/状态有完整辅助标签；“＋”名称包含目标项目；键盘可进入、
  激活、离开预览且焦点不落隐藏任务输入，不能只在hover时暴露功能。
