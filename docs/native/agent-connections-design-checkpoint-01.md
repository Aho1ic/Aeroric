## 1. 推荐：一个管理入口，几种不同的业务对象

不在 Aeroric 里摆放三个工具的设置页，也不把账号、模型和执行器混成
一个下拉框。建议在既有设置/工具与连接体系中增加「账号与连接」入口，
管理真实资源；新建会话只选四个工具及兼容的 Agent 配置。

```text
供应商连接：服务地址、API 协议、代理及能力
    ├─ API 密钥引用 / 官方授权账号 / 原版 CLI 登录状态引用
    ├─ 模型目录与能力观察
    └─ 可选账号池与路由策略
                  ↓ 引用，不复制凭据
Agent 配置：所属工具、连接/账号或池、默认模型、别名、上下文与推理设置
                  ↓ 独立选择
任务角色绑定：主执行 / 审查 / 反思 / 治理
                  ↓ 启动时固定有效快照
实际执行：工具版本、账号来源、模型、路由尝试与用量
```

统一入口不是所有认证方式共享同一个 token，也不是所有配置支持四工具。
权限属于任务授权；Full Access 不属于供应商连接或配置模板。
工作方案复用配置引用，不携带凭据、登录会话或单次授权。

## 2. 三种接入路径不能混淆

以下为 2026-10-21 公开官方文档核查，不是已完成真实登录或法律意见；
实施及发布前仍须复核届时规则、客户端版本和 Aeroric 分发资格。
原文与获取记录保存在本轮临时证据的 `official-sources/`。

| 路径 | 推荐在 Aeroric 中如何表达 | 不能声称 |
|---|---|---|
| 原版 Codex / Claude Code 登录 | 启动用户明确选定的官方工具自带授权流程；显示来源、账号标签与失效状态，凭据归该流程管理 | 不修改工具认证、偷读个人 home、借用客户端 ID 或将 token 当通用 Key |
| 合资格的 ChatGPT 官方 SIWC | OpenAI 已公开开源/本地应用的订阅接入；如 Aeroric 满足资格，按官方注册、同意及 Responses 接口实现，单独保存账号注册关系 | 不等于商业/远端发行自动获准，不等于四 CLI 及所有端点兼容，更不代表无限额度 |
| 用户自己的 API / 云供应商凭据 | 统一添加 base URL、协议、凭据引用和模型能力；按执行器适配、连接检测后使用 | 订阅和 API 计费不混用，第三方宣称兼容不等于功能无损或凭据可跨域发送 |

Claude 官方规则允许用户在未修改的 Claude Code 内自行订阅登录，
但不允许第三方 App 收集、中转 Claude.ai 凭据来提供通用模型调用。
因此不设计 Aeroric 直接收取 Claude 订阅 token 再转给 OMP / DSH 的能力。

官方依据（完整链接仅供研究定位，不要求本轮运行这些授权流程）：

- OpenAI：`https://learn.chatgpt.com/docs/auth`
- OpenAI SIWC：`https://developers.openai.com/siwc/token-sharing-open-source`
- OpenAI 账号/刷新：`https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions`
- OpenAI 限制：`https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations`
- Anthropic：`https://code.claude.com/docs/en/authentication`
- Anthropic：`https://code.claude.com/docs/en/legal-and-compliance`

### 2.1 SIWC 是新增明确适配，不是复用旧 Codex 私有桥

需区分应用注册、用户/workspace 绑定及稳定 host 身份；同邮箱不等于同注册。
按官方流程验证授权及 scope，保持本地受保护存储、同会话刷新串行和撤销状态。
当前官方要求流式、非服务端存储的 Responses 请求；可用模型另行发现。
现有指向 Codex backend 的路由不能不加区分改名 SIWC 或直接视为符合要求。
此预览还限制部分参数、历史续接及托管工具；不能把通用 Responses
支持列表套入本路径。本地工具执行与上游托管工具是两回事。
模型列表需用已选账号查询，不能用 bundled 目录冒充账号可用性；
流中失败、未完成与 `response.completed` 分别记录，推理完成不等于
任务验收或工具副作用成功。

公开流程当前要求 127.0.0.1 loopback 回调；不由此推断 iOS 原地登录获支持。
iOS / iPadOS 先作为受信配对 host 的原生控制客户端；移动端直接 SIWC
登录是否支持、回调/商店规则和安全存储另行核实，未列为已解决。
官方 app-server 示例还要求 env token 更新后重启并恢复 thread，
不能把这个示例偷换成 Aeroric 运行中切换配置或 OMP RPC UI 方案。
此次不打开登录页、不申请注册、
不触碰 Keychain、不下载工具或启动任何官方 CLI。

### 2.2 四工具兼容表必须是数据，不是承诺

兼容性至少包含工具版本、连接认证模式、上游协议、模型能力、流式、
工具调用、图像/文件、推理及上下文约束。显示「支持 / 受限 / 待验证 /
不支持」及理由，不用一个绿色“已连接”代表全部支持。

Codex 原版官方登录有官方依据；Claude 订阅只走原版 Claude Code。
OMP / DSH 的用户 API 路径是适配候选；能否消费合资格 SIWC 必须逐版本
验证 Responses、授权传递与能力契约，不能默认为任意订阅通用。
custom 保留真实身份，不能悄悄变成 Codex 以绕开兼容判断。

## 3. 合并后的能力清单

下列是能力簇，不是首发必交清单。参考来源包括总库 MAG / CCS / CPA
观察；不因同名而丢掉差异，也不把 README 宣称当成本项目运行通过。

| 能力簇 | Aeroric 原生体验与实现方向 | 必须区分的状态/限制 |
|---|---|---|
| 账号与凭据 | API Key、允许的官方账号、原版工具授权状态；命名、标签、启停、重新授权和撤销 | 账号身份、授权注册、连接配置不同；同邮箱不合并；不设计账号买卖或凭据共享 |
| 连接与协议 | base URL、Messages / Responses / Chat Completions 及供应商适配、出站代理、超时与 TLS/证书设置 | 不自动降级 TLS/改 Host 绕认证；密钥不随模型别名跳到其他域 |
| 模型目录与能力 | 保存后对有接口的连接获取模型、手工添加兜底、来源/时间、上下文/输出/推理/视觉/工具能力 | 模型列出不代表有权推理；未知不伪装支持；目录刷新不重置草稿或任务 |
| 模型映射与推理 | 显示名、工具请求名、上游真实 ID 分开；每模型支持的推理档位与预算/速度单独表示 | 不把所有供应商强制映射 low/medium/high；不静默丢弃不支持参数 |
| 上下文控制 | 声明容量、用户覆盖、实际有效上限、输出预留及来源；超限在发送前解释 | 填写更大数字不扩展模型真实能力；上下文预算不是订阅额度 |
| 额度与用量 | 有公开/授权接口时读取余额、Key 上限、订阅窗口、重置时间；本地 usage 关联任务/角色/尝试 | 不支持、无权限、过期、采集失败、未知与零分别显示；费用估算不是余额 |
| 账号池与弹性 | 多个独立 Codex 账号/注册、可用性、优先/权重/并发、会话亲和、冷却/熔断与耗尽原因 | 池不合并额度、共享身份或绕上游限制；已发送状态未知不自动重放 |
| 配置方案与发布 | 工具专属配置、项目/角色绑定、预览字段差异、版本/外改/部分应用/恢复收据 | 不写用户个人 home；不覆盖监督或权限；保存配置不改变运行中的任务 |
| 扩展资源 | 复用技能/MCP/提示资源单源与部署计划，在配置中保存引用而不是另建资源库 | 安装、部署、启用、调用/授权分开；技能新装/更新仍需人工同意 |
| 诊断与统计 | 明确“连接检测”的实际探测项、路由尝试、转换限制、脱敏日志和可归属用量 | 检测可能发网/计费，须先说明；鉴权成功不等于完整 Agent 旅程通过 |
| 导入、备份与同步 | 版本化过滤迁移、暂存校验、冲突预览、敏感项默认排除、加密与恢复收据 | 普通 ZIP / hash 不等于加密；不自动云传 token、生产历史或整份个人配置 |
| 管理与部署 | 管理动作经既有 host 客户 API，loopback 路由鉴权/生命周期归 host | 不另起无认证管理面板或第五 Agent；参考项目Docker/远端部署不授权本项目创建VM |

模型映射还需保留来源 Stack 的「聚合目录、固定来源」候选：
同一工具可发布多个连接的模型名，选中稳定发布名即绑定原连接，
稳定路由 key 不转配；原连接失效就具名受阻，不落到默认账号或普通
fallback。这与普通别名、允许轮换的账号池不同。
cc-switch 的此项仅覆盖 Claude Code / Codex / Claude Desktop
（`src-tauri/src/mode/stack.rs:3–17,53–95`、
`src-tauri/src/proxy/forwarder.rs:502–513`），不证明 OMP / DSH 已支持。

WebSocket、payload 补丁、缓存提示/推理转换、插件 middleware 等属于
高级连接能力，不塞进新建会话。只在明确支持时暴露；改写规则具名、
版本化、可审计，不能悄悄改用户的提示词、签名思考块、工具调用或审批。
用户 payload 覆盖完成后，仍须不可覆盖的协议/授权/外发终检；
若违反 SIWC 等接入要求，拒绝并解释，不继续发送不合规请求。
来源中独有的会话整理、知识、调度和团队能力仍归总库原 owner，
不因本次研究集中在账号而删除或复制一套。

## 4. 账号池：可以借鉴，但不能把故障转移当重新执行任务

建议区分连接级请求调度与任务级重试：

1. 用户决定哪些自己的账号进入池、允许哪些目标/模型、各自并发及费用边界。
2. 一次新执行固定绑定快照，路由选出实际账号；有亲和需求时绑定原会话。
3. 健康、额度、权限、模型能力和维护状态均参与准入；亲和不能把被禁账号加回。
4. 已知尚未发送、或能证明安全重试的请求，才按预设范围择备选；认证失效、
   限流、模型不存在、上游失败分别处理。不用宽泛错误码等同未执行。
5. 流已开始、工具可能执行或接收情况未知时，保留 attempt 与来源，先核实/
   展示恢复条件；不通过换账号盲重发。不把另一个账号的新上下文当原会话继续。
6. 主/审查/反思/治理的池与配置各自独立；切主账号不改监督，不重启旧任务。

默认池策略、任务内是否允许跨账号、池参与哪些角色、限额耗尽后的交互
仍待后续一次性讨论，不将这些建议标为用户已批准。绝不以多账号绕过限制。
