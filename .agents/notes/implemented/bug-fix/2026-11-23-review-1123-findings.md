# Agent Note: 2026-11-23 复测：DSH 底栏没有 token、确认过的验收还挂着提示

Status: implemented

## Problem

2026-11-23 复测报告在 `~/Documents/computer-use/2026-11-23-0944-aeroric-review-1123`。上一轮查出的 DSH 第一轮历史已经好了：第一轮结束不切走就有开场白折叠，底栏写“1 轮”，切走再切回仍在。逐项核对截图和代码后，查出两处新问题。

**A2：DSH 会话底栏写“— tok”。** 这一轮回答下面写着 13.9K tok，底栏的上下文写 1%。

- ACP 的 `usage_update` 只带上下文的 `used` 和 `size`，映射成实时用量时输入、输出 token 都是空的（`acp/map.rs`）。
- 底栏只要实时用量不是全空，就整份用它，会话文件统计里的 token 一点都没拿（`LiveSessionView.statsBar`）。DSH 的实时用量有上下文，所以不算空，token 就成了“—”。
- Codex、Claude 的实时用量带 token，所以没有出这个问题。

**A5：用户确认验收后，委派卡上还留着“宣告完成，但有 1 条验收还没有自动核对”。**

- 这条提示（`unverifiedDone` 探针）在子会话回报时生成。那时 `test -f` 这条验收还没核对。
- 用户在卡上标了通过，`refresh_acceptance` 会把卡上的验收换成“通过 · 你确认的”，但探针没人管。只能点“知道了”去掉它。
- 没确认的探针会让这个委派算作“需要用户”，所以确认完验收，它还占着“需要我处理”。

**其余几项不是代码的问题：**

- **T4：** 轮间对比只写“已解决 1”。原因是计数为 0 的类别本来就不显示，被驳回的意见也本来就不参与对比（`compare.rs` 只跟踪采纳的意见）。是提示词把四类都列了出来。
- **V1：** 结果判成不合格，原因也写出来了。按设计，用警示色的是结果那一行，原因用灰字。提示词写成“用警示色写原因”，是提示词写错了。

## Decision

**底栏逐项合并：** 新增 `UsageSummary.merged(live:transcript:)`，底栏改用它取值。上下文的两项、token 的三项各自算一组，每组先取实时的；实时那组全空，再整组取会话文件统计里的。按组取，是为了让缓存命中率的分子和分母来自同一份数据，不会拿实时的输入配上会话文件里的缓存数。

**验收全部通过就撤掉提示：** `refresh_acceptance` 换上新的验收后，如果 `acceptance_passed()` 成立，就删掉 `unverifiedDone` 探针。别的探针（预算、重复调用、没有依据）照旧留着。

## Alternatives considered

**让 ACP 的实时用量也带 token。** 没选：ACP 协议的 `usage_update` 本来就只有上下文。token 要从会话文件里读，宿主已经在会话文件统计里算好了，App 拿过来就行。

**确认验收时把探针标成“已确认”，而不是删掉。** 没选：这条提示说的是“还有没核对的验收”，验收都通过以后它就不成立了，留着只会误导。真要查回报那一刻的情况，审计记录里有。

## Consequences

- **收益：**
  - DSH 等 ACP 会话的底栏有 token 数；
  - 确认完验收，委派卡上的这条提示就撤掉了，这个委派也不算在“需要我处理”里。
- **局限：**
  - 验收以后又过期了（文件被改过），这条提示不会再出现，只能看验收行上的“可能已过期”；
  - 都还没重新目检。
- **验证：**
  - Swift 新增 1 个测试，覆盖三种情况：DSH 的实时用量缺 token 时从会话文件补上；实时 token 优先，命中率和 token 出自同一份；两边都没有时为空。
  - core 延伸 1 个测试（`done_without_the_criteria_or_without_evidence_is_flagged`）：用户把验收标成通过，刷新后探针消失。
  - MacBook 上跑了 core 委派 44 个测试和 Swift 两套相关测试，全部通过。全量验证没跑。
