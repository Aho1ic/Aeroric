# Agent Note: 新建会话输入法打字卡、拖侧栏分界线卡

Status: implemented

## Problem

用户 2026-11-23 报了两个卡顿：
- 在新建会话的输入框里用输入法打字很卡；
- 拖动分界线改左侧栏宽度时动画很卡。

查到的原因（`main@083097c4`，代码阅读，没有用 Instruments 实测）：

**输入法打字卡：**
- **绑定一路连到窗口根：** 输入框（`ComposerCard` 里的 `TextEditor`）直接绑在 `draft.task.prompt` 上。这个绑定一路连到 `TaskWorkspaceView` 的 `@State draftBook`。
- **每个键都牵动整个窗口：** 每按一个键（输入法组字时每一步也算），都要做这些事：
  - 改一次 `draftBook`；
  - 重算整个工作区视图的 body，这是 App 里最大的视图；
  - 触发 `.onChange(of: draftBook)`，把全部草稿编码成 JSON，写进 `@AppStorage`（`UserDefaults`）。

**拖侧栏卡：**
- **读数会跳：** 拖动条（`SidebarResizeHandle`）的 `DragGesture` 用的是它自己的坐标系。拖动条跟着侧栏边缘移动，每一步的位移读数都受上一步移动的影响，所以会来回跳。辅助面板的拖动条早就用全局坐标系，没有这个问题。
- **每一帧都写盘：** 每一步都把宽度写进 `@SceneStorage`。
- **每一帧都重算整页：** 窗口布局预算（`MainShellBudget`）每一步都变。工作区视图读了整个预算（`@Environment(\.mainShellBudget)`），所以每一帧都重算整页，但它只用到辅助面板的宽度和窗口总宽。

## Decision

**输入框先改自己的一份。**
- **改哪里：** `ComposerCard` 里的编辑器改绑一份本地的 `typed`；
- **何时交出：** 停止输入 150ms 后交给外面的 `text`；
- **立刻交出：** 发送、⌥↩“这轮结束后再发”之前，以及输入框消失时；
- **外面改了以外面为准：** 发出后清空、选了斜杠命令，这类从外面改 `text` 的情况，会丢掉本地还没交出的那份。为了不把自己交出去的值当成外面的改动，记下最后一次交出的值（`pushed`）。
- **按钮状态：** 发送按钮是否可用，看的是本地这份。

**侧栏拖动只更新布局，松手才保存。**
- **坐标：** 拖动条改用全局坐标系；
- **拖动中：** 宽度放在 `WorkspaceRootView` 的 `@State draggedSidebarWidth`，并关掉这次更新的动画；
- **松手时：** 才写进 `@SceneStorage`；
- **工作区只读需要的两个数：** 根视图另给一个只有辅助面板宽度和窗口总宽的环境值（`mainShellInspectorColumn`），工作区视图改读它。拖侧栏时这两个数不变，工作区不会因此重算。

## Alternatives considered

**只把写 `UserDefaults` 改成延迟。** 没选：主要的开销是每个键都重算整个工作区视图，只延迟写盘解决不了。

**输入框改用 AppKit 的 `NSTextView` 包装。** 没选：本地缓存加延迟交出就够了，换控件要重做 ⌥↩、焦点、无障碍标识这些现有行为。

**侧栏改用 `HSplitView` 或 `NSSplitView`。** 没选：现有的布局预算（侧栏自动收起、辅助面板挤占）是自己算的，换成系统分栏要重写这一套。

## Consequences

- **收益：**
  - 打字（包括输入法组字）只重画输入框；
  - 拖侧栏时读数稳定，只有侧栏和内容列跟着变，不写盘，工作区页不重算。
- **局限：**
  - 打字停下后最多 150ms，斜杠命令提示和外面看到的草稿才更新；
  - 卡顿的原因来自代码阅读，没有用 Instruments 实测，改完的效果也没有在 App 里目检；
  - 侧栏拖动时侧栏自身的列表仍会按新宽度重排。
- **验证：** MacBook 上 AeroricKit 编过，相关测试都过；App 层（`TaskWorkspaceView`）要在完整构建里编译。
