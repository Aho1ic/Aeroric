# Agent Note: Claude 长回合：用量随回合更新，思考和命令收成一行

Status: implemented

## Problem

用户 2026-11-23 的截图里，一个 Claude Code 会话跑了一个多小时，看到三个问题：

- **底栏一直是空的：**
  - “— tok”，上下文“—”；
  - “0 轮 69 步”，后来是“0 轮 169 步”；
  - 会话统计里模型用时和输出速度都是“—”。
- **页面被刷屏：** 一轮里“思考 · n 字”和“已执行 2 个指令”交替排下去，几十行都是这两种，没有用的信息把 Agent 说的话挤走了。

核对的事实（`main@083097c4`）：
- **用量：**
  - `ClaudeMapper` 只在 `result`（一轮结束）时把这轮的 `usage` 加进总数，发一次 `Usage`；
  - 回合中每条 `assistant` 消息带的 `message.usage`，只用来算上下文的估计（`last_context`），没有发出去；
  - 所以第一轮没结束前，底栏没有任何数字。上下文窗口大小要等一轮结束后用 `get_context_usage` 问，一样拿不到。
- **轮数：**
  - 统计栏数的是历史里用户的消息，加上实时的“用户回显”；
  - 会话开场那条消息只显示成开场气泡（`openingPrompt`），这一轮没结束前，它既不在历史里，也不是回显，所以是 0 轮。
- **模型用时、输出速度：** 也要一轮结束才算，这次没改。
- **刷屏：** 实时行的分组（`LiveRowGrouping`）只把连着的工具调用合成一组；中间夹一段思考，就断开成新的一组。

## Decision

**用量跟着回合走（core `claude/map.rs`）。**
- **记账：** 映射器按消息 id 记下这一轮每次 API 调用的用量（输入含缓存读写、输出、缓存读）。同一次调用会拆成几条消息、每条重复带着用量，所以每项取最大值。
- **发出：** 有变化就发一条 `Usage`，数字是“之前各轮的总数 + 这一轮已有的调用”，上下文用最近一次调用的估计。
- **一轮结束（`result`）：**
  - `result` 带用量时，用它作这一轮的数，换掉调用累计出来的数；
  - 不带时，用调用累计的数；
  - 然后清空这一轮的记录。

**轮数（统计栏）：** 历史和回显里都没有用户消息，但页面正显示开场气泡，或者有一轮正在跑，就记 1 轮。

**思考和命令收成一行（`LiveRowGrouping` 和 `LiveWorkRow`）。**
- **怎么合：** 连着的思考和工具调用合成一行“工作”。Agent 说的话（`message`）会打断合并，所以它说的内容照常显示。
- **只有一种时：**
  - 只有工具调用时，和原来一样：一条单独显示，多条合成“已执行 n 个指令”；
  - 只有一段思考时，照旧显示“思考 · n 字”。
- **还在动的一行**（这一轮在跑而且它是最后一行，或者里面有正在跑的调用）：
  - 只显示最新的一步，原地换掉：正在跑的调用写“正在执行：命令”；
  - 否则写最新思考的最后一行“思考：……”，或者最后一个调用“已执行：命令”；
  - 右侧小字写“思考 n 次 · 执行 m 个指令”。
- **停下的一行：**
  - 写“思考 n 次 · 执行 m 个指令”，有失败的另标“k 个失败”；
  - 不是全为命令时写“调用 m 个工具”。
- **展开：** 点开后按原顺序列出每段思考和每个调用，各自还能再展开。
- **一轮结束后：** 页面换成历史的显示，本来就有“已完成，用时 N 秒”的折叠，那边不改。

## Alternatives considered

**回合中也去问 `get_context_usage`，拿到窗口大小。** 没做：这是发给 Claude 进程的控制请求，回合中发会不会被它及时回答、会不会打扰它，没有核实。现在第一轮里上下文只写已用多少，第一轮结束后才有百分比。

**按时间合并（比如 10 秒内的都合成一行）。** 没选：时间间隔跟内容无关，Agent 中途说的话可能被吞掉。按“有没有说话”切分更稳。

**一轮里所有过程都只留一行，连 Agent 的中间说明也收起来。** 没选：中间说明（“我先看一下现场”）对用户有用；而且历史显示里本来就把这些归到过程里折叠了。

## Consequences

- **收益：**
  - 长回合里，底栏的 token、缓存命中、上下文用量随每次模型回答更新；
  - 第一轮也显示“1 轮”；
  - 实时页面里，一长串思考和命令只占一行，并且能看出现在在做什么。
- **局限：**
  - 第一轮结束前不知道上下文窗口大小，只写已用的量；
  - 模型用时和输出速度仍在一轮结束后才有；
  - 真实 Claude 会话上没有目检。
- **验证：**
  - core 新增 1 个测试：回合中用量逐次累加，同一次调用的重复不重算，`result` 的数换掉累计，没带用量的 `result` 保留累计；
  - Swift 新增 1 个测试：思考和调用合成一行，Agent 的话打断合并，单独的思考保留原样，标题、最新一步的写法；
  - MacBook 上 core 的 Claude 实时测试、`ConversationModelTests` 都过。
