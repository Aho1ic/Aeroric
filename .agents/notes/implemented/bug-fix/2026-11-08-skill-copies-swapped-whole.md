# Agent Note: 项目里的技能副本整份换上，改过的旧副本进废纸篓

Status: implemented

## Problem

Codex 直连时，[内置技能](../feature/2026-10-30-builtin-skills.md)和学到的技能以带标记的副本放在项目 `.agents/skills/<id>/`。版本一变，原来的做法是先 `remove_dir_all` 再复制、最后写标记。2026-11-08 复现了两个问题：

- 副本里改过的文件（用户或 Agent 改的）在升级时被静默覆盖；
- 复制到一半失败时，目录还在但没有标记；之后它被当成用户自己的文件夹，永远不再修，也不再进 `.git/info/exclude`，残缺文件可能被提交。

## Decision

- **整份换上**：新副本先在 `.agents/.aeroric-staging/<随机>/new/<id>` 复制好、写好清单和标记，再改名换到位；旧副本先挪进暂存区，换上后再处理。任何一步失败，旧副本原样留着，暂存区清掉。暂存区不在 `.agents/skills` 下，半成品不会被当成技能加载。
- **清单**：标记旁的 `.aeroric-builtin-files` 记下副本每个文件的 SHA-256 和相对路径（不含两个标记文件），排序存放。
- **改过的旧副本**：升级时旧副本的文件和清单对不上，就交给 `remove`（宿主移到废纸篓，和关闭的副本一样，Q16），能找回；没改过的直接删。清单出现之前的旧副本分辨不了，按没改过处理，这次升级照旧替换。移废纸篓失败时，旧副本留在暂存区原处，报错里写明路径，不随暂存区一起清掉（2026-11-09 夜间自查补上）。
- 标记的格式和含义不变（只存版本），没有标记的文件夹仍然是用户的、从不碰。

## Alternatives considered

- **只做原子替换，改动照旧覆盖**：更简单。没有采用（用户选了推荐）：静默丢改动是问题的一半。
- **副本被改过就不升级，等用户处理**：改动不丢。没有采用：要在界面上说清楚，否则副本永远停在旧版；废纸篓既保住改动，也让新版生效。
- **把改动备份成项目里的另一个目录**：没有采用：Codex 会把它当成同名技能再加载一次。

## Consequences

- **收益**：升级不会留下残缺副本；改过的副本能从废纸篓找回。
- **代价**：每个副本多一个清单文件；升级时要多读一遍文件算哈希（技能都很小）。
- **已知上限**：清单出现前就被改过的副本，第一次升级仍会被覆盖。
- **验证**：`builtin_skills_tests::copies_are_replaced_whole_and_edited_ones_go_to_the_trash`：没改过的直接换、改过的进废纸篓、复制失败时旧副本原样、修好后下一次补齐；原有的 `project_copies_are_marked_updated_removed_and_kept_out_of_git` 照旧通过。
