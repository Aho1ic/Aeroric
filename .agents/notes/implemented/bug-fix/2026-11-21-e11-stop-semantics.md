# Agent Note: E11 停止的语义：正在停止，用户停掉的不算要处理

Status: implemented

## Problem

[1118 调研](../../proposed/architecture/2026-11-19-new-addition-1118-research.md) E11 要求：

- 点停止后显示“正在停止”，直到 Agent 真的停下；
- 用户自己停掉的回合，从不被记成失败，也不进“需要我处理”。

来源有三：

- LinkSense 停止链路复盘；
- OMB #1549：Claude 驱动把用户停止记成“没出结果就退出”，被当成故障上报；
- OMB PR #5655：系统发起的停止不算用户停止。

方案的做法是先核对，有缺口再补。

核对（`main@7f3275ad`）：

- **四个驱动的结束原因：一致，没有缺口。** 用户要求停下，四个驱动都报“中断”（`TurnEndReason::Interrupted`），任务状态记为 `interrupted`，不记失败：
  - Claude：`interrupted` 标记优先于失败判断；
  - Codex：回合状态为 interrupted 时；
  - OMP：`prompt_outcome` 里“人要求的停止”优先，`aborted` 也算中断；
  - ACP：`turn_outcome` 里人要求的停止优先，`stopReason: cancelled` 也算中断。
- **缺口一：界面没有“正在停止”。** 点停止后，`LiveSessionStore.interrupt()` 只发请求，在回合真的结束之前，发送按钮一直是停止按钮，看不出请求已经发出。
- **缺口二：用户停掉的回合进了“需要我处理”。** `AttentionQueue` 把 24 小时内所有状态为 `interrupted` 的任务都列进去，不分是用户自己停的，还是宿主重启打断的。宿主重启打断的，任务记录上有 `interruptedBy: hostRestart`，App 里对应 `restartCut`。
- **系统发起的停止：** 宿主重启打断的（`interruptedBy`）、E6 暂停时停掉的回合，都是中断。前者要用户决定是否继续；后者是用户自己按的暂停，按用户停止对待。

## Decision

**正在停止：**

- `LiveSessionStore` 加 `stopping`：点停止时置上，请求失败时撤回；轮询读到回合已经不在进行，就清掉。
- 输入框的发送状态加 `.stopping`：发送按钮的位置换成转圈，悬停写“正在停止：等 Agent 停下这一轮”。
- 会话页在停止已发出、回合还在进行时，显示这个状态。

**需要我处理：** 只列宿主重启打断的中断（`restartCut`）。用户自己停掉的，归到后面那一支：如果还有失败的检查、审查、委派或黑板要处理，照常按那些列出，只是不再因为“被中断”而列出。

两份已有的测试原本按旧行为写，“用户停掉的也列出”，跟着改了，并写明 E11。

## Alternatives considered

**宿主侧给用户停止另记一个原因（`interruptedBy: user`），App 按它判断。** 最强的理由是来源清楚，不靠“没有重启标记”来推断。没选：

- 中断的来源现在只有两种：用户（包括用户按的暂停）和宿主重启，重启已经有标记；
- 加一个字段要改任务记录、协议和迁移，得到的判断和现在完全一样。

以后出现第三种系统发起的中断时，再加来源字段。

**“正在停止”由宿主报一个中间状态。** 最强的理由是多个客户端都能看到。没选：

- 停止是这个客户端发出的，它自己知道已经发出；
- 回合真的结束时，驱动会发出结束事件，客户端据此收尾。

宿主不需要多一个状态。

## Consequences

- **收益：**
  - 点停止后立刻有反馈，直到真的停下；
  - “需要我处理”不再塞满用户自己停掉的会话，宿主重启打断的照旧在。
- **代价：** 没有。
- **局限：**
  - “正在停止”只在发出停止的那个客户端上显示，手机上和另一个窗口里看不到；
  - Agent 迟迟不停时，没有超时提示，一直转圈，直到回合结束或页面重开；
  - 四个驱动的核对只是读代码，没有在真实 Agent 上重放停止。
- **验证：** Swift 测试：
  - 新增 1 个：点停止后在停止中；回合还在跑时仍在停止中；收到中断结束后，回合不在进行，也不在停止中；
  - 改了 2 个：“需要我处理”不列用户停掉的任务，只列重启打断的。
  - `LiveSessionStoreTests`、`AttentionQueueTests`、`RestartCutTests` 共 25 个全部通过。
- **待目检：** 已记进路线文档 §8 待目检清单。
