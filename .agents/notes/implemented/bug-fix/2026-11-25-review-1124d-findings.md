# Agent Note: 目检 1124d：手机任务列表找不到任务

Status: implemented

## Problem

目检报告在 `~/Documents/computer-use/2026-11-25-0957-aeroric-review-1124d/report.md`，测的是 `f6072d7b`。

**通过的：**
- 手机 App 全屏；
- 配对；
- 配对后 Mac 设备列表不切页就出现手机；
- 任务标题是提问文字；
- 文件与 Git 的说明文字和下拉刷新；
- 收尾。

整个过程手机没有掉线。

**没测成的：** 任务页的会话、Mac 消息同步、手机插话后停止、断线后页面恢复，都没测成。原因是在手机任务列表里找不到指定任务（测试项目的 `Reply with OK.`）：
- 列表把所有项目的所有任务按存储顺序平铺。测试项目一个就有 132 个任务；
- 标题是整段提问，长的占十几行；
- 往下翻了几屏都是别的项目的旧任务。

**还查到一处：** 文件与 Git 默认选中的是 1124b 建的空项目，“Git 改动”直接写 `fatal: not a git repository`，是 git 的原话。

## Decision

**任务列表按“进行中”和“最近”分节**（`CompanionTaskList.sections`）。
- **进行中：** 还占着 Agent 或等人回答的任务（`pending`、`running`、`input_required`，和宿主 `TaskStatus::is_live` 一致），放最上面，跨项目，从新到旧。
- **其余从新到旧：**
  - 看全部项目时最多 30 个，标题“最近”；
  - 选了一个项目时最多 50 个，标题“这个项目的任务”；
  - 超出的写“较早的 N 个在 Mac 上看”。
- **新旧按什么算：** 任务记录里 `createdAt`、`completedAt`、`updatedAt` 中最新的一个（`CompanionTask.activityMs`），三个都没有的排最后。
- **项目选择：** 列表上方加项目选择（“全部项目”或某个项目）。选了项目，也同时把它设为手机的当前项目，新建任务和文件与 Git 都用它。
- **行的样子：** 标题最多两行，下面一行小字写“项目 · Agent · 状态”。
- **iPad：** 侧栏用同样的分节。

**不是 Git 仓库的项目说清楚。**
- 宿主 `git.changes` 遇到 `not a git repository` 回答 `available: false, reason: not_git`；
- 手机写“这个项目不是 Git 仓库，没有改动可看”。

## Alternatives considered

**列表加搜索框。** 没选：目检要找的是刚在 Mac 上跑过的任务，“进行中”和“最近”已经把它放到最上面。搜索要宿主支持按文字找任务，以后需要再加。

**宿主按项目分页返回任务。** 没选：手机现在一次读全部任务做快照，审批、推送重读都依赖完整的快照，改分页牵涉面大。显示时截断就够了。

**按项目分节，每个项目一节。** 没选：项目多时“进行中”的任务会散在各节里，还是要翻。

## Consequences

- **收益：**
  - 刚跑过、正在跑的任务在手机列表顶上；
  - 长提问不会把列表撑满；
  - 能只看一个项目；
  - 非 Git 项目写明“不是 Git 仓库”，不显示 git 的报错原文。
- **局限：**
  - 超过上限的旧任务手机上看不到，要在 Mac 上看；
  - 任务记录没有时间的，排在最后。
- **验证：**
  - 手机：`CompanionTaskListTests` 四条（排序、分节、上限、项目筛选、时间读取、`not_git` 的说法）；
  - iOS App 模拟器编译通过；
  - `not_git` 的宿主分支没有单独的宿主测试：现有的远程测试项目是靠任务请求顺带登记的，再加一个非 Git 项目要重搭整套环境。由下次目检覆盖。
