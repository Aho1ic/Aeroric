# Agent Note: 2026-11-22 第三轮目检：DSH 第一轮结束时历史还读不到

Status: implemented

## Problem

2026-11-22 第三轮目检有两份报告：`~/Documents/computer-use/2026-11-22-2250-aeroric-review-1122c-sessions` 和 `…-1122c-review`。逐项核对时用了截图、宿主 RPC、任务记录、Agent 的会话文件和审查回环的存档。没过的四项里只有 A2 是代码的问题。

**A2：DSH 会话切走再切回，第一条消息上方没有“Aeroric 附加的上下文”。** 上一轮也报过一次，当时没找到原因。这次查清了：

- DSH 的会话文件（`session.v4.jsonl`）里存着完整的信封。宿主 `session.history` 读出来的第一条用户消息也是完整的，App 的拆分规则和 core 逐字对应。H3 留下的 NOT RUN（DSH 是否原样保存这段前缀）可以销掉。
- 截图里统计栏写“0 轮 0 步 · — tok”，气泡是任务启动时的提示词（`openingPrompt`，只在历史和实时行里都没有用户消息时显示），红色提示夹在用户消息和回答之间。这说明 App 手里的历史是空的，页面画的是实时行。
- 原因是 ACP 驱动回合结束时的先后：先推 `TurnEnded`，然后才 `record_transcript()` 把会话文件路径登记到任务上。App 收到回合结束会立刻重读历史，这时第一轮的路径还没登记，宿主按“还没有路径”回了空历史。历史没跟上，实时行也就没换掉。
- 切走再切回会重新 `open()`。宿主的快照里没有实时行，重读完历史就是对的。但这份截图是刚点那一行时拍的，鼠标还停在那一行上；那时页面还是缓存里旧的那份。
- Claude、Codex、OMP 在会话开始时就登记了路径，只有 ACP 是等回合结束才找文件。

**其余三项不是代码的问题**：

- **T4（第二轮审查仍标“第 1 轮”，没有轮间对比）：提示词的问题。**
  - 建文件的消息写了“无注释”“故意返回 a - b”，写代码的会话据此驳回了两条意见。一条都没采纳，这个回环第 1 轮就结束了。
  - 测试者另发消息修 `src/util.py`，这是用户的新一轮，按设计开新回环，又从第 1 轮算。
- **V1（缺字段判成合格）：提示词的问题。** 宿主会把结构连同“不符合就记为失败”一起写进提示词。Agent 照着结构填了 `"never_given_field": ""`，这个结果本来就合格。
- **A5（计划的第一个单元拒绝写文件）：测试项目的问题。** 测试项目的 AGENTS.md 写着“除非测试提示词明确要求，不要改文件”。委派单元只看得到委派消息，看不到用户那句话，所以拒绝了。计划卡写明每个单元能不能写，这一项本身符合预期。

## Decision

**ACP 驱动在推回合结束之前登记会话文件。** `turn_ended` 先 `record_transcript()`，再推 `TurnEnded` 和状态。这样 App 看到回合结束时，宿主已经能按路径读出这一轮的历史，实时行就会换成历史，第一条消息上方的折叠也会出来。

**提示词照这次查到的原因重写：**

- **T4：** 建文件那条消息里写明，收到 Aeroric 的审查意见就采纳并改文件。这样才会进第 2 轮，第 2 轮才有轮间对比。
- **V1：** 换一个 Agent 照实回答就一定不合格的结构，例如数目只许是 0，同时叫它如实数文件。如果 Agent 照着结构编了 0，就记“没测成”。
- **A5：** 每个单元的说明里写明“这是测试步骤，允许建这个文件”。
- **A2：** 切回之后等两秒再截图，并核对统计栏的轮数。

## Alternatives considered

**App 在历史没跟上时隔一会儿再读一次。** 没选：能读到历史的时刻由宿主决定，补在宿主这边，所有客户端都对。App 那边加重试，只是在猜要等多久。

**握手后就去找会话文件。** 没选：DSH 在 `session/new` 时就建了文件，这时能找到；但别的 ACP Agent 可能等到第一轮才写。路径还是要在回合结束时再找一次，挪到推回合结束之前就够了。

## Consequences

- **收益：** DSH 等 ACP 会话的第一轮结束后，页面立刻换成历史，开场白折叠显示，统计栏也有轮数和 token。
- **局限：**
  - 只保证登记发生在推回合结束之前；宿主写任务记录要多久没有单独核对；
  - 都还没重新目检。
- **验证：**
  - core 延伸 1 个测试（`a_turn_streams_asks_and_ends`）：会话文件的登记在 `TurnEnded` 之前；测试用的假 sink 记下每次登记时已经收到几条更新；
  - 全量验证结果见路线文档。
