**查出的几处：**

1. **手机停止以后，Mac 上的会话一直“运行中”。**
   - **原因：** 一轮跑着时手机发来的话，Claude Code 没有另开一轮，而是并进了正在跑的这一轮。Claude 的记录里它是 `queued_command`。这一轮只出一个 `result`。
   - **驱动的算法：** 写进去几条，就等几个 `result`。第一个 `result` 到了以后还差一个，驱动就马上开了下一轮。这一轮永远等不到 `result`。
   - **停止也没用：** 手机点停止时，第一轮已经结束了。中断请求发给的是空闲的 Claude，它不会再出 `result`。所以 Mac 上那一轮写“已完成”，顶栏却一直“运行中”，后来又提示“9 分钟没有新输出”。
2. **手机任务页看不到“会话”，Mac 上发的消息也看不到。**
   - **原因：** App 没有启动屏配置（`UILaunchScreen`），iOS 把它当成老 App，按旧机型的尺寸缩在屏幕中间显示。
   - **结果：** 截图里整个 App 只占屏幕中间一块。“会话”一节排在“改动”后面，被挤出了屏幕。
3. **手机任务标题显示成任务 ID。** 大多数任务记录没有 `name` 和 `title`，只有 `prompt`。手机只认前两个，找不到就退回 ID。
4. **手机配对以后，Mac 设置里的设备列表不更新。** 列表只在页面出现时读一次，要切到别的页再回来才看到。
5. **文件与 Git 一直写“没读到：和 Mac 的连接断开了”，页顶却写着在线。**
   - **原因：** 重连以后，连接先把快照交给页面，页面据此重读；连接却在这之后才把自己标成已连上。
   - **结果：** 连接器不发没连上时的读请求，于是这次重读被丢掉。上一次断线时失败的页面就一直停在失败。
   - **为什么断线：** 审计日志里 20:08 到 20:24 之间重新认证了 4 次，原因不明，待下次目检观察。
6. **在 Mac 上直接新建的文件，手机上不出现。** 这一条不是错误：Mac 只在任务的一轮开始和结束时推送。目检提示词写的“几秒到一分钟内出现”是我写错了。

## Decision

**Claude 驱动的下一轮，等 Claude 自己说开始了才开。**
- 一轮的 `result` 到了，驱动只结束这一轮，不看还差几个 `result`。轮与轮之间只有 Claude 的 `system/init` 能开新的一轮。
- 新开的这一轮，如果还有写进去没等到 `result` 的消息，就算我们的；否则算 Claude 自己开的。
- Claude 报空闲（`session_state_changed: idle`）时如果没有进行中的一轮，说明写进去的都已经被并进上一轮，计数清零。

**手机 App 加启动屏，任务页“会话”排在“改动”前面。**
- `project.yml` 和 `Info.plist` 加 `UILaunchScreen`（空字典，用系统默认）；
- 任务页的顺序：状态、待审批、发给这个任务、会话、改动；
- 任务页和文件与 Git 页都能下拉刷新。文件与 Git 的“Git 改动”下面写明：任务每轮开始和结束时自动更新，在 Mac 上直接改的文件要下拉刷新。

**手机任务标题按 `name`、`title`、`prompt` 的顺序取第一行非空的**（`CompanionTask.title(of:fallback:)`），都没有才用 ID。

**Mac 的远程页开着时，每 3 秒读一次设备列表**（`RemoteStore.watchDevices`）。读到的和现在的不一样才更新，页面消失时停。

**连接先标成已连上，再交快照**（`CompanionLink.synchronize`）。这样快照触发的重读能发出去。

## Alternatives considered

**按回显判断消息是否被并进了这一轮。** 没选：`--replay-user-messages` 的回显在两种情况下都会来，从回显看不出 Claude 是并进这一轮，还是排到下一轮。`system/init` 是 Claude 开新一轮时一定会发的。

**手机任务页把“会话”放最前面。** 没选：会话可能很长，放在最前面，发消息和停止就要滑到底才找得到。

**Mac 在项目文件变化时推送给手机。** 没选：这要在宿主里给每个项目挂文件监听。手机上下拉刷新就够了，以后需要再加。

**设备列表改成宿主推送。** 没选：设置页是唯一需要它的地方，开着时轮询的开销很小。

## Consequences

- **收益：**
  - 手机插话后再停止，Mac 上的会话会结束，不会卡在“运行中”；
  - 手机 App 全屏显示，任务页能看到会话；
  - 任务标题可读；
  - 配对后设备马上出现在 Mac 设置里；
  - 断线重连以后，打开着的页面自己恢复。
- **局限：**
  - Claude 在一轮结束和下一轮的 `system/init` 之间，状态会短暂显示“完成”；
  - 一条消息被并进上一轮、Claude 又没报空闲时，计数会留着。之后 Claude 自己开的一轮会被当成我们的，只影响它靠 `result` 结束还是靠空闲结束；
  - 手机断线的原因没查出来；
  - 远程页每 3 秒读一次设备文件。
- **验证：**
  - Rust：`a_message_folded_into_the_turn_leaves_no_turn_open`；`a_message_during_a_turn_is_claude_s_next_turn` 改成第二轮由 `system/init` 开；
  - 手机：
    - `testAPageOpenWhileOfflineIsReadOnceConnected`（不改连接时这条过不了：读请求被丢掉）；
    - `testATaskIsTitledByItsNameOrTheFirstLineOfItsPrompt`；
  - Mac 设备列表的轮询、App 全屏、下拉刷新，都留给下次目检。
