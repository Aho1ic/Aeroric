# Agent Note: 回合分级（R5-1）：没跑成、产品失败、完成分开记

Status: implemented

## Problem

R5 要做"换模型从同一起点重跑、并排比较"。比较之前要先分清一次运行是哪种结果：模型做错了，还是根本没跑起来。[R4-3 评测](../testing/2026-11-10-wiki-agent-eval.md)里这两种情况混在一起，W2 和 W3 的几轮先后卡在 404、Lite 400 和"没有工具"上，只能逐个读会话记录分辨。

现状：

- Codex 回合以 `task_complete` 结束，接口出错时它带一个 `error` 字段，以前没人读，这一轮照样显示"已完成，用时 2.7 秒"。
- Claude 只要出现一行 `isApiErrorMessage`，整轮就标成 `failed`；Claude 遇到 429 会自己重试，重试成功的回合也被标成了失败。
- 自动检查的结果只存在会话的内存日志里，App 重启就没了。

用户 2026-11-11 定了 R5 的 5 条，全部按推荐：

- 拆成 R5-1 回合分级和 R5-2 换模型重跑、并排比较，先做分级；
- 重跑从任一改过文件的回合开始，代码回到这一轮开始前的快照；
- 每个重跑放进自己的独立副本，一次最多 3 个；
- 默认只带这一轮的消息和已确认的决定；
- 比较时只并排列出各项数据，不让模型打分，由用户挑一个带回。

## Decision

**分级**（core `sessions/turn_outcome.rs`）

每个回合属于下面一种：

| 级别 | 依据 | 记在哪里 |
|---|---|---|
| 没跑成 | 这一轮停在 Agent 的 API 错误上 | `TurnStat.not_run`（同时置 `failed`） |
| 已中断 | 用户点了停止 | `interrupted`（不变） |
| 产品失败 | 跑完了，但用户撤销了这一轮，或者项目检查没过 | `TurnStat.product_failure` |
| 完成 | 以上都不是 | 不标 |

- **Codex**：`task_complete.error` 的 `codex_error_info` 是一个词（如 `usage_limit_exceeded`、`server_overloaded`），或者 `{http_connection_failed: {http_status_code}}`。
- **Claude**：错误行上有 `error`（如 `rate_limit`、`authentication_failed`）、`apiErrorStatus`，正文写明原因。这一轮后面如果又出现了正常的 assistant 行，说明 Claude 重试成功，就清掉 `not_run` 和 `failed`。`api_errors` 记下这一轮所有的 API 错误行，界面据此显示"途中 N 次 API 错误"。
- **没跑成的原因**，按下面顺序判断，前一条命中就不再往下：
  1. 登录：正文提到登录失效。网关会把上游的登录过期报成它自己的 503，所以这一步放在状态码之前。
  2. 额度或限流：429、`usage_limit`、`rate_limit`、余额不足。网关余额不足时回 403（"Insufficient account balance"，R5 目检 2026-11-12 遇到），所以额度词要先于 401/403 判断。
  3. 登录：其余的 401/403。
  4. 模型不可用：404、`model_not_found`。
  5. 连不上：ECONNREFUSED、EPROTO 一类。Claude 把这类错误归在 `server_error` 下，所以要排在服务出错之前。
  6. 服务出错：5xx、满载。
  7. 请求被拒：400、`invalid_request`。
  8. 其他。
- 错误原文最多保留 300 字。
- **产品失败**：宿主在 `session.history` 里读回合账本，用开始时间和每个回合对上，规则与改动成本相同：相差 60 秒以内，取最近的一条（`change_cost::nearest`）。被撤销（`Undone`）或检查没过的，记为产品失败。没跑成和已中断的回合不参与这一步。

**检查结果存进账本**

- `TurnRecord` 新增 `check: {passed, summary}`。
- `AutoChecker::record_into` 拿到回合账本。一次检查跑完（通过或失败）后，结果写进这一轮的记录（`TurnLedger::set_check`）；没改文件的回合不在账本里，跳过。

**界面**

- 回合标题：没跑成的写"没跑成（额度或限流），用时 …"，不再写"已完成"。
- 答复下方、账单旁边的胶囊：
  - "没跑成 · 原因"，红色。悬停显示"不算模型答错"、HTTP 状态和错误原文。
  - "产品失败 · 已撤销"或"产品失败 · 检查没过"，黄色。悬停显示检查摘要。
  - "途中 N 次 API 错误"，灰色。
- 正常完成的回合不加胶囊。
- 没有答复的回合（大多数没跑成的都是）没有答复下面那一排，胶囊放不上去，原因就看不到了（Codex 目检 2026-11-11 发现）。这种回合在标题下方单独一行：红色胶囊加"HTTP 状态 · 错误第一行"，最多 120 字，悬停看全文；错误是 `{"error":{"message":…}}` 这样的 JSON 时只显示里面那句话。

## Alternatives considered

- **把"0 步工具调用"也算没跑成**：W2 的会话就是 0 步，模型说自己没有工具。没选：很多纯问答回合本来就不用工具，按步数判断会把正常回答误判成失败；W2 那种情况的根因是路由丢工具，已经[修掉了](../bug-fix/2026-11-11-codex-0167-bridged-tools.md)。
- **产品失败交给模型判断（看答案对不对）**：能覆盖不改文件的回合。没选：R5 已定不让模型打分；撤销和检查失败都是用户或项目给出的明确信号。
- **检查结果另存一个文件**：账本格式不用改。没选：检查本来就是针对改过文件的那一轮跑的，和账本记录一一对应，放在一起读的时候不用再匹配一次。

## Consequences

- **收益**：
  - 回合标题和胶囊直接说明是哪种失败、原因是什么，不用再去读会话记录。
  - R5-2 并排比较时可以直接用这套分级；以后统计改动成本、做评测，也可以先把"没跑成"的回合排除掉。
  - Claude 重试成功的回合不再被误标为失败。
- **代价**：
  - 产品失败只覆盖改过文件的回合。纯问答答错了，这里看不出来。
  - 原因靠状态码和关键词判断，网关自定义的错误文字可能落到"其他"。
  - 这次之前跑过的检查没有存结果，旧回合只能从撤销状态判断产品失败。
- **验证**：
  - core 单测（`sessions::turn_outcome`）：
    - 2026-11-10/11 会话记录里的真实错误逐条归类：额度用尽、404、401、网关 503 里的登录过期、满载、Lite 400、Claude 的 429、EPROTO、未登录、502，以及原文截断到 300 字；
    - Codex 回合停在错误上时记为没跑成，下一轮正常；
    - Claude 两次 429 之后重试成功，这一轮不算失败，`api_errors` 为 2；最后一轮停在 429 上，记为没跑成；
    - 撤销、检查没过记为产品失败；已接受且检查通过的、没有账本记录的、用户中断的，都不算。
  - 账本单测：检查结果存进对应回合的记录，账本里没有的回合不受影响。
  - core 全部 2419 个测试、host 全部集成测试通过，clippy 没有警告。
  - Swift 单测（`TurnBillTests`）：新字段的解码、标题文字、胶囊的文字和颜色、正常完成的回合不加胶囊。
