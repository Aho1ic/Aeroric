# Agent Note: 会话失控提醒（最小版）：超量 token、长时间活跃、空转回合

Status: implemented

## Problem

backlog A13 要求失控时提醒用户（P1），路线图 R3"账单与上下文透视"排在下一批。会话页已经有回合内的两种提示：同一调用连续重复（`LiveLoop`）和长时间没动静（`LiveStall`）。但整个会话层面没有提醒：会话花掉几亿 token、连跑几天、或者一直在等待和轮询却不推进，用户都看不出来。New-addition-1102 复核研究建议直接采用 gstack `lib/runaway.ts` 的阈值和"空转"定义。

## Decision

- `LiveRunaway.alerts`（Swift 纯函数）从会话页已有的数据算提醒，不改协议、不改宿主：
  - 会话累计 token：历史统计的 `inputTokens + outputTokens` 超过 4 亿；
  - 委派：会话里委派卡片的 `tokens` 超过 1 亿；
  - 持续活跃：从历史统计里第一个回合开始算，超过 3 天；
  - 空转：最近 40 个回合里空转超过 25%，可判断的回合不少于 20 个。
- **回合与空转**：
  - 回合按历史里用户自己打的消息切开（工具结果不算）。
  - 空转：有工具调用，而且全是等待、轮询或读状态（`wait`、`wait_agent`、`list_agents`、`sleep`、`write_stdin`、`BashOutput`、`TaskOutput`、`get_goal`、`TodoRead`，以及工具为这些的 Codex `Agent` 卡），并且助手文字不到 200 字。
  - 没有回复也没有工具调用的回合记为未知：不算空转，也不算正常，不进分母（gstack：扫描没结果就是扫描失败，不能当成干净）。
- **提示条**：输入框上方一条胶囊，显示最该看的一条（空转、累计 token、委派、活跃时长的顺序），多条时标"还有 N 条"、点开看全部。
  - "请它先总结"发一条消息（回合进行中就是插话），请 Agent 先总结做完了什么、还剩什么、卡在哪里，再判断要不要继续。
  - "×"（知道了）按会话和种类记在 `UserDefaults`，重启后也不再出现。
  - 这四种不进"需要我处理"，不停止、不轮换会话；R3-2 加的"在重试"一种排在最前，另进"需要我处理"（见 [本次带入的上下文与无新证据重试](2026-11-09-turn-context-and-retry.md)）。
- **目检用的阈值**：应用偏好里的 `RunawayTestLimits`（字典）可以覆盖各项默认值，只给审阅版目检用。

## Alternatives considered

- **在 core 里加一层记账 sink，按回合落盘并发协议更新**：能看到每个工具调用和改动，数据最全。没有采用（这批只做最小版）：要改协议和契约；会话页已经有整段历史和每回合的 token 统计，足够判断。完整 R3 做账单时再下沉到 core。
- **按 gstack 自动轮换会话、停掉超量子代理**：没有采用（用户选了只提醒）：Aeroric 的候选库约定失控检测只提醒、不替用户做决定。
- **审查轮次上限**：gstack 每个 PR 超过 2 轮就提醒。Aeroric 的审查循环本身封顶 3 轮，不另加。

## Consequences

- **收益**：烧钱、长跑、空转三种情况会被看见，并且一键就能让 Agent 停下来回顾。
- **代价与上限**：
  - 只在会话页打开时算，用的是已经载入的历史；没打开的会话不提醒。
  - 空转按工具名判断，Codex 的 `exec_command` 轮询（比如反复 `sleep 30`）不算等待类，会漏报；宁可漏报也不误报。
  - 委派只看当前会话页上还在的委派卡片。
- **需要重访的信号**：R3 开始做账单（记账下沉到 core、按回合落盘）；用户觉得提醒太多或太少；Agent 的轮询方式变了。
- **验证**：`LiveRunawayTests`（回合判定含未知、空转门槛与比例、token 与活跃与委派三种文字、数字读法）。
