# Agent Note: Git 页写操作（第一批）

Status: implemented

## Problem

Git 页只接了只读：写操作按钮一直禁用，界面还是早期的英文按钮。宿主早就有全部 git 写方法。owner 要能在 App 里直接暂存、提交、切换分支和贮藏（Trellis 任务 `10-26-git-files-writes`，Q1–Q5 按推荐，设计稿 2026-10-30 通过）。

另外，App 的 `GitClient.checkoutBranch` 少传了宿主必填的 `isRemote`，所以侧栏切分支一直失败。

## Decision

**范围**
- 第一批：暂存与取消暂存（单个和全部）、提交、生成提交信息、新建并切换分支、切换分支、贮藏（含未跟踪文件）、恢复贮藏、删除贮藏、放弃单个未暂存文件。
- 推送、拉取、全部放弃留到第二批。界面先显示灰色的「拉取 · 推送（下一批）」。

**界面**（新视图 `GitPage` 替换 App 里的 `GitPanel`）
- 顶部：分支胶囊（菜单里切换或新建）、「更改 / 历史 / 贮藏」滑块带数量、有上游时显示 ↑领先 ↓落后。
- 改动列表分「已暂存」「未暂存」两组，悬停出现 ＋ / － / ↶。提交按钮写明提交几个文件。
- 放弃改动和删除贮藏都先确认。放弃未跟踪文件时说明文件会被删掉。

**接线**
- `GitClient` 加写方法，并修正 `checkoutBranch` 补上 `isRemote: false`。
- `AppServices.performGit` 一次只执行一个写操作。执行中在页头显示进行中，失败原因显示在页内，结束后整页刷新。
- 刷新后保留所选文件：它在两组之间移动时跟着走，并重新读取它的改动。
- 切换分支沿用 `BranchSwitch`：工作区有改动时拒绝切换。
- 宿主不改。

## Alternatives considered

- **在旧 `GitPanel` 上直接启用按钮**：不选。它是早期的英文、列表样式，和 owner 定的胶囊风格不一致，按钮放在哪也和设计稿不同。
- **一次放开推送、拉取**：不选（Q1）。这两个操作会碰远端，等第二批加上二次确认再接。
- **提供「全部放弃」**：不选（Q2）。误点代价太大。

## Consequences

- 旧的 `GitPanel`、`ChangeList`、`StageActions` 不再被 App 使用，留待以后清理。
- 生成提交信息走宿主现有实现：用本机 Codex 读已暂存的 diff。没装 Codex 时，页内显示宿主给的原因。
- 测试：客户端解析贮藏和领先落后计数；页面文案、状态标记、路径拆分、改动 id 还原路径。
- 用临时数据目录和临时仓库起了一个独立宿主，把 13 个宿主方法逐个跑通，没有碰真实数据和正在运行的宿主。
