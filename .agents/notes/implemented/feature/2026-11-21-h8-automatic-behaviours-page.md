# Agent Note: H8 第三步：Agent 配置 → 自动行为页

Status: implemented

## Problem

[各 Harness 原生融合](../../proposed/architecture/2026-11-16-harness-native-capabilities.md) H8 要用户能看到两件事：

- 设置里能看到每种 Aeroric 能力在每个 Harness 上“该用的时候用了几成”；
- 新的自动行为先以“候选”出现，能一键退回。

动手前（`main@20d359c2`）核对的事实：

- **宿主侧已经有接口。** [H8 第二步](2026-11-21-h8-three-tiers-and-revert.md)做好了档位表和三个接口：`rollout.list`、`rollout.set`、`rollout.revert`。每个自动行为带当前档位、换档历史、判断次数和本来会触发的次数。
- **App 里还看不到。** 没有任何界面显示这些，只能用 RPC 改。
- **“每个 Harness 上用了几成”现在没有数据。**
  - [H8 第一步](../testing/2026-11-21-h8-trigger-records-and-comparison.md)的评测记录只在测试里生成，用的是假 Harness；
  - 真实 Harness 的评测没跑；
  - 档位表里的计数是宿主侧的判断，不分 Harness。
- **能力包页（H6）是同类页面的现成写法。** 页面放在 Agent 配置下，各层分开：协议模型、客户端、`@Observable` 状态对象（调用可替换，方便测试）、文字、页面。

## Decision

**新页 Agent 配置 → 自动行为**，紧跟在“能力包”后面：

- **页头：** 一段说明：三档各是什么意思，先看“本来会触发”的比例再决定升不升，任何一档都能退回，改动从下一条消息或下次启动起生效。
- **卡片：** 每个自动行为一张：
  - 标题：“按消息召回记忆和 Wiki”，或“学到的技能 <名字>”；
  - 右侧是档位的分段选择。召回有关、候选、只挂描述、默认生效四档；学到的技能只有后三档，关掉它用技能自己的停用；
  - 一句话说明这一档对这个行为意味着什么，召回和技能各写各的；
  - “本来会触发 3/10 次（30%）”。没判断过的写“还没有判断过”；
  - “退回到‘…’”按钮：目标是上一次换档之前的档位，没有历史时是低一档；已经在最低一档时不显示。
- **分层：**
  - 协议模型 `LiveRolloutFeature`：历史只留档位，不留时间；
  - 客户端 `RolloutClient`；
  - 状态对象 `RolloutBook`：换档和退回之后重读列表。选的就是当前档位时不发请求；出错时写“换档失败：…”，列表保持原样；
  - 文字 `RolloutText`；
  - 页面 `AutomaticBehaviorsPane`。

**“每个 Harness 上用了几成”这一步不做。** 页面只显示宿主侧的“本来会触发几成”，这是所有 Harness 合在一起的数。按 Harness 分的触发率，要等真实 Harness 的评测记录。到时再把第一步的 `by_harness` 表搬到这一页。

## Alternatives considered

**放进“设置”窗口，不放 Agent 配置。** 最强的理由是方案写的是“设置里能看到”。没选：
- 学到的技能、能力包、内置技能都在 Agent 配置下，自动行为管的正是这些东西怎么挂给 Agent；
- 设置窗口里的是 App 本身的偏好。
放在能力包旁边，用户找挂载相关的东西只去一处。

**用“升一档 / 降一档”两个按钮，不用分段选择。** 最强的理由是方案强调逐档上线。没选：
- 用户可能确有理由直接跳档，比如已经确认没用，直接关掉召回；
- 退回本来就按换档历史走，跳档后退回一次就能回到原来的档位。

**页面直接显示假 Harness 的评测数字。** 没选：假 Harness 只是关键词匹配，数字不代表任何真实 Agent 的行为，放在设置里会被误读。

## Consequences

- **收益：** 用户能在 App 里看到召回和每个学到的技能的档位和触发比例，并换档和退回，不用记 RPC。
- **代价：**
  - Agent 配置多一个标签；
  - 每次进这个标签都读一次 `rollout.list`，宿主侧会读一遍技能索引。
- **局限：**
  - 触发比例不分 Harness，也不分项目；
  - 换档时间没显示；
  - 页面没有自动刷新，比例要切走再切回来才更新。
- **验证：** Swift 新增 `AutomaticBehaviorsTests` 2 个测试，全部通过：
  - 列表解码后按页面的样子读：标题、比例、可选档位、各档说明、退回的目标（有历史时、没历史时、最低一档时）；缺 id 的条目丢掉；
  - 状态对象：换档、退回后都重读列表；选同一档不发请求；被拒时写明失败，列表不变。
- **待目检：** 已记进路线文档 §8 待目检清单。
- **NOT RUN：**
  - H8 第 2 条的收益对照：同一批录好的任务跑关掉、打乱、正常三种条件，需要录好的任务和真实 Harness；
  - 按 Harness 分的触发率。
