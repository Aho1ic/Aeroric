# Agent Note: 宿主重启后续跑：被 Aeroric 重启打断的会话能"继续"，无人值守的可自动续一次

Status: implemented

## Problem

宿主（`aeroric-cli`）重启时，上一个进程里还在跑回合的会话没有了驱动。ADR-043 在启动时把它们收尾成 `interrupted`，并标为需要关注，于是"需要我处理"里会出现 24 小时"被中断"。缺口有三个：

- **分不出原因**：别的路径也会写 `interrupted`。只看状态，分不出是宿主重启打断的，还是用户自己停的。
- **没有继续入口**：用户只能进会话手动再发一句。
- **没人看着的会话会停在那里**：[定时任务](2026-11-14-scheduled-tasks.md)半夜开出的会话、委派出去的子会话被重启打断后，不会有人去手动继续。

[推迟提案](../../proposed/feature/2026-11-08-new-addition-deferred.md)第 16 项"宿主重启后续跑"的触发信号是"无人值守的委派或定时任务上线"，定时任务上线后这个信号出现了。

用户 2026-11-14 说"全部按推荐"，定了 5 条：

1. 下一项做第 16 项。
2. 识别：宿主启动收尾孤儿会话时，给记录写 `interruptedBy: "hostRestart"` 并记下时间；只有带这个标记的给"继续"，用户停止的、失败的都不算。
3. "继续"：在"需要我处理"那一行和会话页顶部各放一个胶囊按钮；点了用原会话（Harness 自己的 resume）发一条固定的续跑消息，续跑是新的一轮。
4. 自动续跑：设置里加一个开关，默认关闭；打开后只对无人值守的会话生效（定时任务开的、委派的子会话），手动会话仍然只给按钮；同一会话最多自动续一次。
5. 被打断的那一轮记为"没跑成 · 宿主重启"；它改过的文件不自动撤销；定时任务的运行记录里注明结果。

## Decision

**标记**（core `tasks::reducer::settle_orphaned_sessions`）

- 收尾时，如果记录带着 `failureReason`，仍按原规则记为失败，不加标记。
- 其余写成 `interrupted` 的，另写两个字段：
  - `interruptedBy: "hostRestart"`；
  - 在 `hostRestarts` 数组末尾追加这一次的时间，最多保留 20 次。
- 之后任何不是 `interrupted` 的状态切换（`apply_status_transition`，例如继续之后变成运行中）都会删掉 `interruptedBy`。`hostRestarts` 保留，用来给回合分级。
- 判断"被重启打断、还没继续"的条件是：状态是 `interrupted`，并且 `interruptedBy` 是 `hostRestart`（宿主 `restart::cut_by_restart`）。

**继续**（宿主 `session_live_services/restart.rs`）

- RPC：`session.continueAfterRestart {taskId}` → `{continued: true}`。
  - 会话不存在：返回 `NOT_FOUND`；
  - 不是被重启打断的，或者已经继续过：返回 `INVALID_ARGUMENT`。
- 做法：驱动还在就直接用；不在就 `reopen_quiet`，走正常的 resume 路径，代数和防护照常生效。然后发 `CONTINUE_TEXT`："上一轮被 Aeroric 重启打断了。先看看工作区现在的状态，再从中断处接着做，做完的不要重做。"
- 发出之后，会话进入新的一轮，状态切换时 `interruptedBy` 被清掉，按钮随之消失。

**自动续跑**

- 设置项：`resume_after_restart`（core `preferences::PreferenceUpdate::ResumeAfterRestart`），缺省为关。RPC 是 `session.resumeAfterRestart.get` 和 `session.resumeAfterRestart.set`。
- 时机：宿主在 `register_session_live_services` 里收尾孤儿会话时拿到这次收尾的 id，等全部服务装好之后，延迟 5 秒（`AUTO_DELAY_MS`），在阻塞线程上逐个处理（`resume_settled`）：
  - 已经不是"被重启打断"的（比如用户在这 5 秒里点了继续），跳过；
  - **无人值守**：记录带 `delegateOf`，或者定时任务的运行记录里有它（`Schedules::knows_task`），或者（2026-11-15 起）某个待办交办出去的就是它（`todo::knows_task`，见[待办第二批](2026-11-15-todos-second.md)）；
  - 开关打开、无人值守、并且还没有 `autoResumedAt`：先在记录上写 `autoResumedAt`，再继续。先写标记，即使继续过程中宿主又崩了，这个会话也不会被续第二次。
- 定时任务开的会话，运行记录的说明里追加一行（`Schedules::note_task`），四种之一：
  - "被 Aeroric 重启打断，已自动继续"；
  - "……自动继续失败：原因"；
  - "……等你点继续"；
  - 你手动点了继续时，"……你点了继续"。

**被打断的那一轮**（core `turn_outcome::mark_restarts`）

- 判定：会话记录里的 `hostRestarts` 只要有一次重启时间不早于某一轮的开始时间，而这一轮在转写里没有结束，就把它标为没跑成，原因是 `NotRunReason::HostRestart`。
- 另外，每次重启时正在跑的那一轮（重启时间之前最后开始的那一轮），如果转写里写的是"中断"，也按重启算：标为没跑成，并去掉"用户中断"（`interrupted`）。2026-11-15 目检发现，Codex 进程跟着宿主退出时会把那一轮写成中断、带上结束时间，原来的判定因此漏掉了它，标题显示成"已中断"。重启时间只记给重启时还在跑的会话，所以用户更早自己停下的那一轮不会是"重启时正在跑的那一轮"。
- 两处计算回合的地方都在 `grade` 之后调用它：会话历史的统计栏（`services.rs`），以及换模型重跑读回合（`rerun.rs`）。
- 界面上显示"没跑成 · Aeroric 重启"。
- 这一轮改过的文件不动，用户照常在改动审查里决定接受还是撤销。

**界面**

- **需要我处理**：被重启打断的会话行，说明写"Aeroric 重启打断"，行尾有一个胶囊按钮"继续"。整行仍然点开会话；"继续"是单独的按钮，不嵌在整行按钮里。
- **会话页**：结构化会话的上方加一条胶囊提示（`RestartCutBanner`）："Aeroric 重启时这个会话还在跑，上一轮被打断了。"带"继续"按钮。
- 两处都调 `AppServices.continueAfterRestart`，失败时显示原因，然后刷新任务列表。
- **设置 → 通用 → Agent 进程**：在"空闲后释放 Agent 进程"下面加一行开关，说明文字随开关变化。2026-11-14 起这个开关也管没跑成的回合，改名为"无人值守的会话被打断或没跑成时自动继续"，见[无人值守自动重试](2026-11-14-unattended-auto-retry.md)。
- **任务镜像**：`WorkspaceClient.parseTask` 读出 `interruptedBy`；`TaskEntry.restartCut` 在状态是 `interrupted` 并且标记是 `hostRestart` 时为真。

## Alternatives considered

- **只看 `interrupted` 状态，不加标记**：不改 core。没有采用（第 2 题）：用户自己停下的会话也会出现"继续"，点了等于违背用户刚做的决定；无人值守的判断也会把用户停的会话续起来。
- **所有被打断的会话都自动续跑**：省掉一次点击。没有采用（第 4 题）：用户自己开的会话，重启时人往往就在电脑前，自动续跑可能接着做一件他已经不想做的事；无人值守的会话才真正需要。
- **不限制自动续跑的次数**：没有采用：如果续跑本身让宿主崩溃（例如某个工具每次都把进程搞挂），会陷入"重启 → 续跑 → 崩溃"的循环。
- **续跑时撤销被打断那一轮的改动**：工作区更干净。没有采用（第 5 题）：那一轮可能已经做完了大半，撤销会丢掉有用的工作；续跑消息让 Agent 先看工作区现状，接受还是撤销交给改动审查。
- **把"继续"做成投递队列里的一条消息**（R1-2）：可以复用送达回执。没有采用：投递队列是"等会话空下来再送"，被打断的会话没有驱动，要先重开；直接重开再发更直接。代价是继续这条消息没有送达回执。

## Consequences

- 收益：
  - 宿主重启打断的会话和用户自己停的会话分开了，前者在"需要我处理"和会话页都有一键"继续"；
  - 定时任务和委派在无人值守时被重启打断，可以选择自动接着做，最多一次；
  - 被打断的那一轮在回合分级里如实标成"没跑成 · Aeroric 重启"，不算模型的失败，换模型比较时不会被误算。
- 代价：
  - 只认宿主启动时收尾的那一批；驱动在宿主运行期间自己崩掉的会话，不走这条路；
  - 自动续跑判断"无人值守"只看委派标记、定时任务的运行记录和待办的交办记录，侧支、审查、讨论成员都不算；
  - 续跑消息是固定的一句话，Agent 要自己从工作区和对话里判断做到了哪里，可能重复做一部分；
  - "没跑成"的判定按时间匹配：转写里没有结束的回合，开始时间早于某次重启，就算被打断；如果转写本身没写回合结束（某些 Harness 的异常退出），也会被算进去；
  - 自动续跑在宿主启动 5 秒后执行；那时 Agent 的登录或网络还没就绪，就记为"自动继续失败"，需要手动再点。
- [推迟提案](../../proposed/feature/2026-11-08-new-addition-deferred.md)第 16 项由这篇实现，那篇里已注明；第 24 项"配额感知调度"仍未做。
- 待目检（已记进路线图的待目检清单）：
  - "需要我处理"里被重启打断的行、说明文字和"继续"；
  - 会话页顶部的提示与"继续"；
  - 设置里的开关和说明；
  - 一次真实的宿主重启后手动继续和自动继续，以及定时任务运行记录里的说明。

## Testing

- core `tasks::reducer` 新测试：重启收尾写上标记并追加时间，最多保留 20 次；之后切到运行中，标记被清掉、时间保留；有驱动的不算孤儿。
- core `sessions::turn_outcome` 新测试：没结束、并且早于重启的那一轮记为没跑成（宿主重启）；已结束的、重启之后才开始的不算；从记录里读出重启时间，跳过不是数字的值。
- core `schedule` 测试补充：认得定时任务开的会话；说明追加在打开这个会话的那条运行记录后面。
- 宿主集成测试 `a_restarted_host_settles_native_tasks_left_running` 补充：
  - 收尾的会话带 `interruptedBy` 和一次重启时间，失败的没有；
  - 继续一个没被打断的会话返回 INVALID_ARGUMENT，不存在的返回 NOT_FOUND；
  - 自动续跑的开关默认关，能打开。
- Swift `RestartCutTests`：被重启打断的行带说明、用户停止的没有；"Aeroric 重启"的没跑成文字；记录里的标记能解析；开关能读、能切，保存失败时恢复原值并给出原因。
- 没有自动化验证真实的重启后继续：需要真实的 Agent 回合并重启宿主，列进了待目检清单。
