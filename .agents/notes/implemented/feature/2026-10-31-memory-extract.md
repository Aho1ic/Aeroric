# Agent Note: 会话结案抽取（B5-2）：分析模型、历史线索、待确认候选、整理记录

Status: implemented

## Problem

B5-1 之后，记忆只有两个来源：用户 `/记住`，和 Agent 主动 `memory_propose`。多数有价值的信息说过就散在会话里：用户随口提的偏好、一次会话里定下的约定、这次做了什么。路线文档 §6.2 要求在会话结案时抽取候选，每条带证据，模型只能提议。owner 2026-10-31 定了 Q-M9–Q-M15，全部按推荐。

## Decision

**分析模型**（Q-M9）

- 用户在记忆页的"整理设置"里，从已启用、支持 Chat Completions 的连接里选一个连接加模型。
- 调用走 `settings::model_detect::chat_once`：和"测试连接"同一套 reqwest 客户端与代理规则，直接用连接里存的密钥，不经本机网关。
- 参数：`temperature 0`，`max_tokens 1200`。

**何时整理**（Q-M10、Q-M15）

- 宿主每 2 分钟扫一遍（`sweep`）。一个会话要同时满足以下条件才会整理：
  - 所在项目开启了记忆，而且是本机的 Claude 或 Codex 原生会话；
  - 已经归档，或者状态是"已完成"并且安静了 30 分钟（`SETTLED_AFTER_MS`）；
  - 归档或完成发生在打开"自动整理"之后（`enabled_ms`）；
  - 还没有整理过。
- 和决定的偏差：原定"完成就整理"。实际原生会话每跑完一个回合，状态都会变成"已完成"，所以改为"完成且安静 30 分钟"。
- 打开开关之前结束的旧会话不会补整理，免得一打开就花一大笔钱。
- 会话菜单里的"整理这次会话"，以及整理记录里的"重试"，都会强制整理：发言 1 条也整理，整理过的再整理一次。
- 菜单项始终写"整理这次会话"，没有按"整理过没有"切成"重新整理"，因为界面拿不到整理标记。

**发什么、收什么**（Q-M11、Q-M12）

- 发出去的内容：
  - 对话只取文字部分，复用 `context_messages`，按"用户：/Agent："拼接；不含工具输出；
  - 保留最近 24000 字，再用诊断报告的脱敏规则遮掉密钥和 home 路径；
  - 附上本项目和全局已生效的 profile、fact，最多 40 条，带 id。
- 要求模型只输出一个 JSON：`sessionFact` 加 `candidates`。
- 校验规则：
  - 候选的 `quote` 规范化后，必须是对话（规范化后）的子串，否则丢弃（A08 无引用就降级）；
  - `supersedes` 必须是附上的 id 之一；
  - 每次最多 5 条候选；
  - 类型不对的丢弃。
- 写入：
  - 会话线索的 kind 是 sessionFact，直接 active，标"模型整理"，进"历史线索"；`recall` 能检索到，画像不注入；
  - 候选是 pending：profile 写到全局，fact 写到本项目；
  - 带 `supersedes` 的候选，确认时才把旧条目标为已取代（`store.activate`）。B5-1 的 `insert` 原来在插入时就执行取代，现在只在 state 为 active 时执行。

**记账与上限**（Q-M13）

- 每次整理都记一行 `MemoryRun`（在 memory.db 的 `runs` 表）：模型、token、估算费用、产出条数、原因。
- 费用用 `metrics::analytics::estimate_cost_usd`，按价目表估，价目表里没有的按名字推测。
- 跳过的不算次数。做完和失败的都算，每天上限默认 30，按本地日界计算；到上限后自动整理停下，手动整理报错。
- 整理过的会话记在 `extracted(task_id, hash)` 表里。失败也记，所以不会每次扫描都重试花钱，要重试得手动点。

**原生导入**（Q-M14）

- `memory.importNative {path, projectId?}`：
  - 只接受 `memory.native` 刚列出的路径；
  - 本地按行拆：跳过标题、空行和代码块，去掉列表前缀；
  - 每行走 `propose`：给了项目就作为项目事实，没给就作为全局画像。
- 不调用模型。屏障和去重沿用 B5-1。

**界面**

- 记忆页标签行的右侧有"整理设置"按钮，弹窗里有三项：
  - 分析模型（CapsulePicker）；
  - 自动整理（CapsuleToggle），没选模型时打开会提示；
  - 每天最多（CapsuleSlider：10、30、60、100）。
- "历史线索"列出 sessionFact，⋯ 菜单里有打开会话、归档、永久遗忘，没有添加行。
- "整理记录"顶部汇总"本月 N 次 · 约 $x · 今天 a/b"。每行有状态徽标、时间、会话、模型、token、费用、原因和产出；失败的有"重试"，每行都能打开会话。
- 原生文件行加"导入为候选"，导入后一行小字显示结果。
- 会话菜单加"整理这次会话"，整理完跳到记忆页的整理记录。

## Alternatives considered

- **走本机网关调用分析模型**：网关只认 claude 和 codex 两种代理身份，要令牌或任务授权；用量表也没有用途列。直接走连接更简单，记账放在 memory.db，不混进网关用量。
- **每个回合都整理**：花费太大，而且同一会话会重复产出（Q-M10 否决）。
- **整理以前所有已完成的会话**：一打开开关就是一笔不小的花费，改为只整理之后结束的。
- **候选不核对原话**：模型可能编造用户偏好，A08 要求无引用就降级。
- **候选里的取代立即生效**：违背"模型只能提议"。

## Consequences

- 已知限制：
  - 读不到对话的会话（omp、DSH、远程，或文件超过 32MB）记为跳过，并写明原因；
  - 分析模型只支持 Chat Completions；
  - 估算费用依赖价目表，未列出的模型按名字推测。
- 测试：
  - core：抽取 2 个（裁剪、脱敏、计数；回复校验）、整理流程 2 个（用假模型：线索与候选、只整理一次；跳过、失败、坏 JSON、上限、没选模型）、存储 2 个（取代提议等确认、线索不进画像；设置、记录、标记持久化）、导入 1 个、`chat_once` 回环 1 个（cline 外包的回复与 usage）；
  - 协议 1 处；
  - 宿主端到端 1 个：没选模型被拒、跳过原因、记录与次数、扫描、导入路径被拒；
  - Swift：整理设置、记录文字、导入、重试、解码。
- 2026-10-31 目检报告（computer-use `2026-10-31-1209-aeroric-b5-memory-consolidation`）后修复了三处：
  - **F1 重新整理同一会话会多出一条线索**：`add_session_fact` 先按证据里的 task id 找到这个会话现有的线索（`store.session_fact_of`），新线索把它取代。每个会话始终只有一条线索。
  - **F2 整理记录看不到细节**：每行改为时间、会话标题（可截断）、"模型 · token · 费用"（固定宽度）、失败或跳过原因（红色，最长 260pt）。原因去掉了重复的"调用分析模型失败："前缀；整行悬停仍显示完整文字。
  - **F3 零费用显示成 "$-0.0000"**：Rust 对空的 f64 序列求和得到 -0.0。现在宿主用 `fold(0.0, …)` 求和，Swift 的 `costText` 遇到不大于 0 的值显示 "$0"。
- 这次目检真实调用了模型：两次成功、一次 HTTP 500 后重试成功，合计约 $0.0012。MEMORY.md 导入被截屏工具故障卡住，还没有测。
