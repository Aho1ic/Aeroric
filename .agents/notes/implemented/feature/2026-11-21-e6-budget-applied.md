# Agent Note: E6 第二步：开始无人值守的工作前检查用量，暂停所有 Agent

Status: implemented

## Problem

[E6 第一步](2026-11-21-e6-budget-rules.md)写好了用量上限的规则（`main@38bcb3f4`），但规则不挡住任何工作。方案的做法要求：

- 只在开始新工作前检查，从不在回合中途截断；人自己发的消息照常执行；
- 被跳过的定时任务，在运行记录里只记一行；
- 暂停时停掉所有进行中的回合，拒收新消息，定时任务到点后安静跳过。

核对的事实（开始无人值守工作的入口）：

- **定时任务：** 到点由 `ScheduleEnv::start` 开会话。返回错误时，core 把这一次运行记成一行，错误写在详情里。
- **Agent 发起的委派：** 走 `context.delegate`，来源记为会话。用户从 App 发起的委派是有人在看的，计划确认后开的单元也是用户确认过的，这两种都不算。
- **审查者：** 由审查循环自动开，走 `HostReviews::start_reviewer`，返回错误时审查卡写明原因。
- **无人值守的自动重试：** `retry::look`，每个回合结束时看一次。
- **重启后的自动继续：** `restart.rs`，每个被打断的无人值守任务看一次，不继续时在定时任务的记录里留一句。
- **用户发消息：** `session.prompt` 先进投递队列，再由 `send_user` 送进会话。
- **用量：** 回合账单从会话转写读，讨论模式已经这样读过成员的每回合用量。

## Decision

**宿主模块** `session_live_services/budget.rs`。

**哪些算无人值守：** 定时任务开的会话、委派出来的子会话、交办出去的待办（沿用 `restart::unattended`），再加上审查会话（`reviewOf`）。

**用了多少：**

- 只读本月动过的无人值守会话的转写，看 `updatedAt`、`completedAt`、`createdAt` 里最晚的那个；
- 取每个已结束回合的输入加输出 token 和估算金额，交给第一步的 `spent_since`；
- 没有设上限时，什么都不读。

**`hold(task)`，现在能不能开始无人值守的工作：**

- 暂停了 → “已暂停所有 Agent”；
- 有上限到顶 → 第一步给的原因；
- 否则可以开始。
- 到顶时，同一个周期只在会话里提示一次：
  - 按第一步的 `notice_key` 记在 `<数据目录>/budget-notices.json`；
  - 第一次到顶时，往发起这件工作的会话推一条警告提示。定时任务没有会话，只写宿主日志和那一行运行记录。

**接到五个入口**，到顶或暂停时不开始：

- 定时任务：这一次运行记成一行，详情写“没有开始：原因”；
- Agent 的委派：工具回答“委派没有开始：原因”；
- 审查者：审查卡写“审查没有开始：原因”；
- 自动重试：这一轮不安排重试；
- 重启后自动继续：不继续，定时任务的记录里写“被 Aeroric 重启打断；没有自动继续：原因，等你点继续”。

**暂停所有 Agent：**

- `session.prompt` 在入队之前就拒绝，回“已暂停所有 Agent：在设置里恢复后再发”；`send_user` 也挡，防止已经在队列里的消息在暂停后送出去；
- `budget.set` 把暂停从关切到开时，打断所有正在跑的回合，回答里带上打断了几个。

**接口：**

- `budget.status {}`：返回设置、今天和本月的用量、门的状态；
- `budget.set {settings}`：保存设置，规则同第一步。

## Alternatives considered

**在 `task.run` 这一层统一挡住无人值守的会话。** 最强的理由是只挡一处。没选：

- `task.run` 分不出这次开会话是不是无人值守，定时任务、待办交办、用户点“新会话”都走它；
- 在每个入口挡，原因能写到用户会去看的地方：运行记录、工具回答、审查卡。

**暂停时也挡 `task.run`，不让开新会话。** 最强的理由是“全部暂停”更彻底。没选，这一步不做：开新会话总是要先发第一条消息，而消息会在 `session.prompt` 和 `send_user` 被挡住。新会话的界面在第三步一并处理。

**每个回合结束时把用量写进一个账本，检查时只读账本。** 理由同第一步：回合账单已经算好了，再记一份会出现两份对不上的数字。代价是每次检查要读本月动过的无人值守会话的转写，而检查只在开始无人值守的工作前做。

## Consequences

- **收益：**
  - 到上限后，定时任务、Agent 委派、审查者、自动重试和续跑都不再开始，并且在用户会看的地方写明原因，到顶时只提醒一次；
  - 一键暂停能停下所有正在跑的回合，并挡住新消息。
- **代价：**
  - 设了上限时，每次开始无人值守的工作前要读本月动过的无人值守会话的转写；
  - 无人值守的会话每个回合结束时也要读一次，用于决定要不要自动重试。
- **局限：**
  - 没有界面，用量页不变色，侧栏也没有开关；
  - 没设会话的定时任务到顶时，提示只记在宿主日志和运行记录里，没有系统通知；
  - 暂停不挡用户自己点“新会话”，但第一条消息会被挡住；
  - 金额是估算的，价目表里没有的模型不计金额。
- **验证：**
  - 宿主新增 1 个测试，通过：
    - 没设上限时可以开始，今天的用量是 0；
    - 上限为 0 拒绝保存；空的上限被丢掉；月金额上限保存后照常放行；
    - 暂停后状态是暂停，发消息在入队前就被拒，回答写明“已暂停所有 Agent”；
    - 恢复后又能开始。
  - 到顶时各入口的拒绝，规则由第一步的 5 个测试覆盖；入口本身只多了一行判断，没有单独起真实的定时任务和审查去测。
- **NOT RUN：** 真实无人值守工作跑到上限的整条流程。
