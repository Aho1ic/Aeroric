# Agent Note: B6 产物登记（第一步：登记与只读）

Status: implemented

## Problem

[调研落地批次 B](../../proposed/feature/2026-11-15-adoption-b-acceptance-and-artifacts.md) 的 B6。回合改出来的文件只存在于[回合撤销](2026-11-04-turn-undo.md)的变更记录里：

- 想问"这个任务交付了哪些文件、各自哪一版通过了哪次检查"，没有可查的对象；
- 回合账本每个仓库只留 50 个回合、30 天，旧回合的快照引用随之删掉，早先的版本会被 `git gc` 回收；
- 现有的 `TaskDeliverablesReviewStore` 只在 DEBUG 构建里出现，读的是虚构夹具，还带着一整套反馈和返工流程，接不到真实数据。

## Decision

**登记**（`core/crates/aeroric-core/src/sessions/live/artifacts.rs`）：

- 改了文件的回合被记进回合账本的同时，由 `ArtifactRegistry::register` 登记：
  - 该轮新增或修改的文件，各成为对应交付物的新一版；
  - 被删的文件，交付物标"已删除"，旧版本保留；
  - 同一路径就是同一个交付物，删除后再建也接着编号。
- 被打断的回合也登记。它留下的文件确实在磁盘上；跳过的话，下一轮的差异里不会再出现这次改动，版本链会断。这一点和方案原文（只登记 `Completed`）不同。
- **只记引用，不复制字节**：每版记 Git blob id（它本身就是内容哈希）和大小。blob 用 `refs/aeroric/artifacts/<任务>/<交付物>/v<n>` 钉住，回合账本放掉那一轮之后也不会被回收。
- 不算交付物的文件：
  - `tmp`、`temp`、`.cache`、`node_modules`、`__pycache__` 等临时目录下的文件；
  - `.swp`、`.orig`、`.rej`、`~` 结尾的文件和 `.DS_Store`；
  - 符号链接和子模块；
  - 被 Git 忽略的文件本来就不进快照。
  - 用户还可以把某个文件标为"不算交付物"（`artifacts.exclude`），它仍然登记，只是收在列表下面。不做自动的重要性判断。
- 上限：每个任务最多 500 个交付物，超出时放掉最久没改的，并记下放掉了几个；每个交付物最多 20 版，超出时放掉最旧的。放掉的版本连同引用一起删除。
- 存储：`<数据目录>/artifacts/<任务>.json`，读改写在同一把锁里完成，通过共享的原子写入落盘。方案原文写的是"任务数据库新增两张表"，实际上回合账本、委派、审查都是这样按任务存 JSON，这里保持一致。

**读取时推出来、不存的字段**（全部来自回合账本）：

- `withdrawn`：产生这一版的回合被撤销了。撤销被撤回后，这一版重新成立；
- `current`：最新的、没有被撤回的一版；
- `superseded`：后面已有成立的新版；
- `checks`：这一版成立期间跑过的检查，即从它的回合开始、到下一个成立的版本之前的回合，每条带 `autoCheck` 依据（`detail` 是跑检查的回合）、通过与否、摘要和"结果可能不完整"标记。

**宿主方法**：

- `artifacts.list(taskId, cursor)`：每页 100 个，最近改过的在前，带 `nextCursor` 和 `dropped`。一个都没有、且任务工作目录不是 Git 仓库时，返回 `unavailable`："这个目录不是 Git 仓库，无法记录交付物的版本"。
- `artifacts.versions(taskId, artifactId)`：新的在前。
- `artifacts.read(taskId, artifactId, version?, offset?, limit?)`：
  - 默认读 64 KB，最多 256 KB；
  - 文本在字符边界切开，按 `utf8` 返回；其他内容按 `base64` 返回；
  - 没读完时带 `nextOffset`；
  - 对象已不在仓库里时，返回错误"这个版本的内容已不可用"，不返回空内容。
- `artifacts.exclude(taskId, artifactId, excluded)`。

**App**：

- 右侧"进度"页加"交付物"一栏：每行是文件名、所在目录、当前第几版，以及最后一次检查的结论（检查通过 / 检查未过 / 检查通过（可能不完整）/ 未检查 / 已撤回 / 已删除）。
- 点开一行列出全部版本；每版可以"打开"，也可以和上一版"比较"（逐行，长段相同内容折叠）。二进制文件只显示大小。
- 右键菜单："打开当前版本"、"不算交付物 / 算作交付物"。
- 默认显示 8 行，其余收在"显示全部"里。
- DEBUG 下的 `TaskDeliverablesReviewStore` 样张不复用，原样保留。

## Alternatives considered

**复用 `TaskDeliverablesReviewStore`。** 最强的理由是它的界面已经设计过版本、检查和反馈。没选：它的模型（反馈、返工、记录、操作意图）比 B6 第一步大得多，数据全是虚构夹具；改它的数据来源，等于重写模型，还得保留一半用不上的流程。

**登记时把检查结论和撤回状态一起存下来。** 最强的理由是读取时不用再查回合账本。没选：撤销、撤回撤销、检查结果都在登记之后才到，存下来就得在每个变化点同步，漏一处就会显示错误的状态。B3 的判旧也是读取时算，不存。

**按任务存两张 SQLite 表。** 方案原文的写法。没选：同一层的其他记录都按任务存 JSON，单独引入一张表要多一套迁移和单写者约束；500 个交付物、每个 20 版的规模用 JSON 足够。

## Consequences

- **收益**：任务页能回答"交付了哪些文件、各自哪一版经过了哪次检查"；任何一版都能按字节读回，回合账本放掉旧回合后也读得到。
- **代价**：
  - 每登记一版多一次 `git update-ref`；一次改几百个文件的回合会多花几秒。
  - 任务被删除后，它的产物引用不会自动清理（回合账本也是这样），留在仓库里直到超过上限被放掉。
  - 回合账本放掉的旧回合，其撤回状态和检查结论读不到了：那些版本显示"未检查"，撤回状态按"没有撤回"算。旧回合本来也不能再撤销。
  - 验收结论（B3 的义务）还没有挂到版本上，只挂了检查。
- **没做的部分**：
  - 方案的第二步：Context MCP 的 `artifact_list` / `artifact_read`，以及委派结果改为引用 `artifact_id@version`。
  - 方案要求 `artifacts.*` 进 `contracts/native/v1/methods.schema.json`。没有照做：那份文件是旧命令表的迁移面，`turns.*`、`delegation.*` 等实时方法都不在里面；这里和它们一样，方法名常量放在 `aeroric-protocol/src/artifacts.rs`。
- **验证**：
  - `artifacts_tests.rs` 新增 10 个测试：
    - 三个回合三版，每版按字节读回，并且都被引用钉住；
    - 撤销后那一版标为已撤回，上一版重新成立，撤回撤销后恢复；
    - 删除后同名重建是同一个交付物的新一版，旧版仍可读；
    - 每版列出它成立期间的检查（包括别的文件变化的回合跑的检查）；
    - 临时目录、临时文件和符号链接不登记；
    - 对象不在时报"这个版本的内容已不可用"，没有这一版或这个交付物也各有说法；
    - 分片读取在字符边界切开，拼起来与文件一致；二进制按 base64 读回逐字节一致；
    - 列表分页带游标，重启后从磁盘读回，"不算交付物"也保留；
    - 超过 500 个时放掉最久没改的，并报出个数；
    - 不是 Git 仓库的目录给出原因。
  - Swift 新增 `ArtifactPanelTests` 4 个测试：每行的结论文字、逐行比较和折叠、解码宿主返回、store 的列出 / 排除 / 打开 / 比较 / 读不到。
  - 界面待目检，记在路线文档 §8。
