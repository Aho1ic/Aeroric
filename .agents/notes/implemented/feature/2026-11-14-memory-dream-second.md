# Agent Note: 后台整理（做梦）第二批：过时检测、画像压缩、整理建议进"需要我处理"

Status: implemented

## Problem

[第一批](2026-11-13-memory-dream.md)只处理"字面相近的几条之间"的关系（重复、矛盾），留下了四个缺口：

- **过时**：项目改了名、删了文件，记忆里"超时在 `src/ssh.rs` 的 `connect` 里设"还生效，Agent 召回后会去找一个不存在的地方。
- **画像太长**：新会话带入的画像和项目事实有 1200 字预算（`PROFILE_BUDGET_CHARS`），超出的条目直接不带，只在末尾写"还有 N 条未列出"。被挤掉的往往是较早、较重要的偏好。
- **建议没人看见**：整理建议只在记忆页上，"需要我处理"和侧栏"记忆"的数字都不算它们。
- **采纳了收不回**：第一批的"撤销这次整理"只收回做梦自己合并的和还在待确认的；用户采纳过的建议没有恢复入口。

用户 2026-11-14 说"全部按推荐"，定了 5 条：

1. 这一批做过时检测、画像压缩、整理建议进"需要我处理"；用 FTS 或 embedding 找换了说法的重复，归到 B6 的"可选 embedding"，后来做成了[可选 embedding](2026-11-14-memory-embedding.md)。
2. 过时用确定性规则判断，不调用模型：从记忆正文和经验的问题、解法里抽出文件路径和反引号里的标识符；路径看项目里还在不在，符号用 `git grep -w` 查。提到的全都找不到才算过时。只查项目事实和经验。
3. 过时一律进整理建议，用户点"归档"或"还有用"，不自动归档；点过"还有用"的，同样的名字仍然找不到时不再提。
4. 画像压缩只在带入新会话的内容超出预算时做；让分析模型把这个范围里未置顶的画像改写成更短的几条，作为建议，用户采纳才生效，可以撤回。
5. "需要我处理"加一种不挂会话的行"记忆整理待确认 N 条"，点开跳到记忆页对应标签；侧栏"记忆"的数字也算上建议。

## Decision

**过时检测**（core `memory/stale.rs`，不调用模型）

- **抽名字**（`refs`）：从记忆正文，以及经验的问题和解法里抽取。
  - **路径**：在正文任何位置都算。条件是相对路径、带常见代码或配置扩展名（`EXTENSIONS`），不是 URL，不以 `/` `~` `.` `$` 开头，不含 `..`。不带 `/` 的文件名只在反引号里算。
  - **代码名**：只在反引号里算。必须"像代码"：含 `::`、下划线，或首字母之后有大写，并且最后一段至少 3 个字符。`cargo`、`ls` 这类工具名不算，否则一条只提到命令的记忆会被判成过时。`Foo::bar`、`store.putChanges()` 只查最后一段。
  - 每条最多取 20 个名字。
- **查找**（`check`）：
  - 文件清单来自一次 `git ls-files -z --cached --others --exclude-standard`，即已跟踪和未跟踪的文件，被忽略的不算。记忆里的路径等于清单里的某个路径，或者是它的结尾（`net/ssh.rs` 能匹配 `src/net/ssh.rs`），就算还在。
  - 代码名用 `git grep --untracked -I -w -o -h -F`，每 200 个名字一次。
  - 不是 git 仓库或 git 出错时返回 `None`，这次不判断任何一条。
- **判定**：一条记忆提到了名字，并且全部找不到，才算过时；只要还有一个能找到就不算。
- **成为建议**（`dream::stale_items`）：
  - 只查这个项目里生效中的项目事实和经验。
  - 已有一条待确认的过时建议的条目跳过。
  - 用户点过"还有用"或撤回过的，如果缺失的名字列表完全相同，也跳过；名字列表变了才再提。
  - 建议写成 `DreamRelation::Stale`：`ids` 和 `keep` 都是这一条，`missing` 是找不到的名字。

**画像压缩**（`dream::compressible`、`COMPRESS_SYSTEM`、`parse_compress`）

- **触发**：`profile::overflows` 按新会话真正的带入方式渲染一次。全局范围渲染全局；项目范围渲染全局加项目。有画像或事实被挤掉，才考虑压缩。
- **改写范围**：只改写这个范围里未置顶的画像，至少 3 条（`COMPRESS_MIN_ITEMS`）。项目事实不压缩。
- **不再提的情况**：已有一条待确认的压缩建议；或者用户对"同样这几条"拒绝过、撤回过。
- **模型调用**：一次单独的调用。提示要求只合并、精简措辞，不新增信息，不丢限制和偏好；回复是 `{"items": [{"text", "category"}], "reason"}`。
- **校验**：
  - 每条非空，不超过 500 字（`MAX_TEXT_CHARS`），不像密钥（`secrets::looks_secret`）；
  - 条数和总字数都必须比原来少。
  - 不满足就整份不用，原因写进整理记录："画像改写没有用上：……"。原因分开说是条数没变少，还是字数没变短（2026-11-15 目检：26 条 1153 字对 20 条 2226 字，原来笼统地写"没有变短"）。
- **成为建议**：`DreamRelation::Compress`，`ids` 是原来那几条，`rewrite` 是改写后的文字。
  - 这是做梦唯一会写出新文字的地方，并且只在用户采纳之后才写；第一批"做梦从不写自己的文字"的原则对自动生效的部分仍然成立。
- **采纳**（`accept_rewrite`）：
  - 原来那几条必须都还生效中，否则报 `WrongState`。
  - 每条改写用 `store.insert` 写成生效中的画像，断言为 `agentConfirmed`（用户点了采纳），证据写"整理时由 N 条画像改写"。
  - 原来几条标为已取代，指向第一条新写的。
  - 新写出来的 id 记在 `created`，撤回时删除。
  - 和已有条目文字完全相同的会并到那一条，不算新写。

**一次做梦现在怎么走**（`Memory::dream_locked`）

1. **准备**：取范围内生效中的条目和全部建议，算出相近的组、要不要压缩、哪些过时。
   - 过时检测需要 `DreamScope.root`，即本机项目的目录。宿主用 `project_dir` 给出；全局范围和远程项目没有目录，不做。
   - 每次做过过时检测，都在 kv `stale:<项目>` 记下时间。
2. **什么都没有**：
   - 只做过时检测时（`free_only`），什么都不记；
   - 自动做梦时，只更新整理时间；
   - "现在整理"时，记一行"跳过 · 没有字面相近的记忆，画像也没超出，不用整理"。
3. **需要模型**（有相近的组或要压缩）时，先查当天上限：
   - 到了上限、但有过时的：照样写过时建议，原因里写"到上限了，这次只查了过时"；
   - 到了上限、也没有过时的：和第一批一样报错。
4. **调用模型**：分组判断和画像改写各调一次，token 和费用累加到同一行整理记录。
   - 一次失败不影响另一次；
   - 有产出又有失败的记"部分完成"，没有产出只有失败的记"失败"。
5. **应用前的快照检查**：分组判断、压缩、过时三种都做，模型思考期间被改过的条目这次不动。压缩时只要原来几条里有一条变了，整份不改写。
6. **计入当天上限**：只有调用了模型的做梦才计入（`store::add_run` 里 `kind = dream` 且没有 `model` 的不计）。只查过时的记录不占当天次数。

**自动触发**（宿主 `dream_due_scopes`）

- 前提从"打开了自动整理并选了模型"放宽为"打开了自动整理"，以及所有会话安静 10 分钟。
- 对每个范围：
  - 选了模型、`dream_due` 为真时，做一次完整的做梦，里面已经包含过时检测；
  - 否则如果这是项目、并且 `stale_due`（今天还没查过），就做一次只查过时的（`free_only`）。
  - 到上限或没有模型时，后面的范围不再做完整的做梦，过时检测照常。

**撤回一条已采纳的建议**（`Memory::revert_dream`，`memory.dreamRevert {id}`）

- 只能撤回已采纳的：
  - 重复和矛盾：其余几条从已取代恢复为生效中，前提是仍然指向留下的那条；
  - 过时：已归档的那条恢复为生效中；
  - 压缩：原来几条恢复，新写的几条删除，不留遗忘签名。
- 撤回后状态是 `reverted`。它和"拒绝"一样，同样的组、同样的名字列表以后不再提。
- 这补上了第一批"采纳了收不回"的缺口。第一批的"撤销这次整理"不变：它不动用户已经采纳的。

**"需要我处理"与侧栏数字**

- `memory.dreamPending {}`：返回所有范围里待确认的建议（`store.pending_dream_proposals`）。
- 应用层每轮轮询时取一次，按范围合成 `AttentionQueue.DreamRow`。
  - 队列顶部每个范围一行"记忆整理待确认 N 条 · 项目名或全局"。
  - 点开调 `openMemory`，打开最新那条建议所在的标签。
  - 这类行不挂在任何会话下：手动"现在整理"和全局范围都没有会话可挂。
- "需要我处理"的数字，以及侧栏"记忆"的数字，都加上这些建议。

**界面**（`MemoryPage`）

- 过时建议卡：
  - 标题"这条可能过时了：提到的文件和代码都找不到了"；
  - 下面是这条记忆，再下面一行"找不到：src/ssh.rs、connect_timeout"；
  - 按钮"还有用"和"归档"。
- 压缩建议卡：
  - 标题"关于你的条目太长，新会话带不全，改写成 N 条？"；
  - 列出改写后的每一条，"原来的 N 条"可以展开看；
  - 按钮"保持原样"和"用改写后的"。
- 重复和矛盾的卡片不变。
- 每个标签的建议下面，列出最近采纳的 5 条，例如"已把 3 条改写成 1 条"，每条都有"撤回"。
- 做梦的产出文字从"待确认 N 组"改为"待确认 N 条建议"，因为过时建议只有一条。没有产出时显示整理记录的原因。

## Alternatives considered

- **让模型判断过时**：能看懂"改了名字"、"挪到了别的模块"这类情况。没有采用（第 2 题）：每个项目每天都要花一次钱，而大部分记忆根本没提到代码名；确定性规则的代价是改名会被当成过时，但只是建议，用户点"还有用"就不再提。
- **只要有一个名字找不到就算过时**：更敏感。没有采用：一条记忆常常同时提到旧名字和仍然存在的模块，部分找不到多半是它的一部分细节变了，而不是整条失效；报得太多会让用户把建议当噪音。
- **过时的、模型整理出的低置信经验直接自动归档**：省用户一步。没有采用（第 3 题）：路线图 §6.5 的权限矩阵要求不因"看起来没用了"自动删除或归档；而且文件找不到也可能只是改名。
- **自动应用画像压缩**：画像始终能带全。没有采用（第 4 题）：画像是用户本人的偏好和限制，模型改写可能丢掉一个细节或改变意思；第一批也是因为这个原因，规定画像一律进待确认。
- **项目事实一起压缩**：事实往往是互不相关的约定，并成一句话会降低可读性，也让单条的撤回和置顶失去意义。保留"超出预算时末尾提示用 memory_recall 检索"的做法。
- **整理建议挂到触发整理的会话下**：可以沿用现有按会话的队列行。没有采用（第 5 题）：手动整理和全局范围都没有会话；挂在一个不相干的会话下面，用户会以为是那个会话的问题。
- **把撤回做成"撤销这次整理"的一部分**：一次做梦的建议可能隔几天才被采纳，按整次撤销会把用户分开做的决定绑在一起。逐条撤回更直接。

## Consequences

- 收益：
  - 提到的文件和代码都不在了的记忆会被摆到用户面前，不再悄悄误导 Agent；
  - 判断过时不花钱，只在项目是 git 仓库时跑，一天一次；
  - 画像超出预算时，有办法让它重新带全，并且每一步都由用户确认、可以撤回；
  - 整理建议第一次出现在"需要我处理"和侧栏数字里；
  - 用户采纳过的任何建议都能逐条撤回。
- 代价：
  - 改名、挪位置会被当成过时：规则只看名字还在不在，不知道去了哪里；
  - 代码名的规则会漏掉全小写、没有下划线的函数名（例如 `connect`），这类记忆不会被判断；路径要带扩展名，目录名不算；
  - 不是 git 仓库的项目、远程项目和全局记忆都不做过时检测；
  - 每个项目每天多一次 `git ls-files`，有代码名时再加一次 `git grep`；大仓库可能要几秒，都在后台的整理线程上；
  - 画像压缩是做梦第一次写出模型的文字，虽然要用户采纳，但用户可能不细看就点了"用改写后的"；撤回可以恢复，但撤回之后同样几条不会再被提议压缩；
  - 压缩只合并画像。如果超出预算主要是项目事实太多，压缩画像帮助有限；
  - 只查过时的做梦也记一行整理记录，标题同样是"整理记忆 · 项目名"。
- 待目检（已记进路线图的待目检清单）：
  - 记忆页的过时建议卡（找不到的名字、"还有用"、"归档"）和压缩建议卡（改写后的条目、展开原来的、"保持原样"、"用改写后的"）；
  - 建议下面"已……"的行和"撤回"；
  - "需要我处理"顶部的"记忆整理待确认 N 条"行，点开跳到对应标签；侧栏"记忆"数字；
  - 真实分析模型下的一次画像压缩。

## Testing

- core `memory::stale` 2 个测试：
  - 路径在正文任何位置都算，代码名只在反引号里算；工具名、URL、绝对路径、项目外路径、目录不算；方法调用取最后一段；
  - 在真实的临时 git 仓库里：未跟踪的文件算在，被忽略的不算；路径结尾能匹配；只要有一个名字还在就不算过时；不是仓库时不判断，没提到名字时不调 git。
- core `memory::dream` 新增 3 个测试：
  - 过时只成为建议、不调模型、不占当天次数；一天一次；待确认的不重复提；"还有用"之后名字不变就不再提；"归档"之后能撤回，只能撤回一次；
  - 画像超出预算时只调一次改写；置顶的不发给模型；采纳后原来的已取代、新写的带入新会话、不再超出；撤回后原来的恢复、新写的删除；同样几条不再提议；
  - 改写校验：更短才收，条数或字数没变少、不是 JSON 都拒绝。

- 宿主集成测试 `a_dream_needs_a_model_and_a_scope_with_nothing_alike_costs_nothing` 加上：`memory.dreamPending` 为空；撤回不存在的建议返回 NOT_FOUND；跳过行的新原因文字。
- Swift `MemoryTests`：过时和压缩建议的解码与标题、"找不到"一行、已采纳的建议按标签列出并能撤回；"需要我处理"按范围合行、取最新那条的种类、已拒绝的不算。
