# Agent Note: H6 第二步：能力包的技能、命令、角色、事件处理投到各家

Status: implemented

## Problem

[H6 第一步](2026-11-21-h6-capability-packs-mcp.md)定了能力包清单、信任和投影计划，只投了 MCP 服务器；技能、角色、命令、事件处理在清单里写的是“还没有投影”。这一步把它们投过去，完成方案 H6 第 2 条的表格。

动手前（`main@1e93c056`）核对的事实：

- **内置技能的挂载**（`builtin_skills::mount`）已经按去处处理好了，每次启动在宿主里调一次：
  - Claude 直连：会话插件 `--plugin-dir`，插件目录按内容摘要共用；
  - Claude 走配置、OMP、DSH：受管目录 `skills/` 下的链接；
  - Codex 直连：项目 `.agents/skills` 里带标记的副本；
  - Codex 走配置：受管目录放内置技能，项目里只放学来的技能。

  能挂的东西是一个 `Offer`（名字、目录、版本）。学来的技能（B5-3b）就是这么接进来的。
- **哪些链接算 Aeroric 的**（`points_into_store`）：链接目标的路径里有 `builtin-skills` 这一级。只有算 Aeroric 的，过期时才会被清掉。
- **H5 的角色投影**在同一次挂载里，读 `native_roles::library`。
- **事件处理**：
  - Claude 会话插件的 `hooks/hooks.json`，无界面模式是否生效是 H1 第二步的 NOT RUN；
  - OMP 的 `--hook` 只收 `.js`、`.ts` 模块（`extensions/hooks.rs` 的扩展名守卫），要用 OMP 的 Hook API 写；
  - Codex 能经会话 `config` 下发 Hook，但要带信任哈希，真实会话 NOT RUN（H1 第二步待实测第 2 条）；
  - DSH 没有入口。

## Decision

**技能和命令随内置技能一起挂载。**

- `packs::skills` 按包、按顺序列出每个技能和命令，以及它的来源或不给的原因：
  - 包已停用；
  - 名字不合规；
  - 和内置技能同名（用内置的）；
  - 已被前面的包占用；
  - 没有 `skills/<名字>/SKILL.md`；
  - 命令正文为空。
- `packs::materialize` 把技能按内容复制进技能仓库 `builtin-skills/packs/<包>/<名字>-<内容摘要>/`，完成标记放在旁边，不放进技能目录。命令写成一个 `SKILL.md`（frontmatter 带名字和说明）。
- 挂载时排在内置技能之后、学来的技能之前。你自己的同名技能仍然优先；学来的技能不能占包的名字。
- 计划和挂载用同一个 `skills` 函数，两边的结论一致。计划里写明去处，并注明“你自己有同名技能时用你的”。计划不读用户的技能目录，这一条只能这样提示。

**命令一律作为技能。** 方案表里 Claude 一栏写的是插件 `commands/`，这里没这么做：Claude Code 插件里的技能本身就能用 `/aeroric:<名字>` 调用，一种形式就够，也不用让插件目录多一套按内容摘要失效的东西。

**角色并进原生子代理的角色库**（`native_roles::library`）。

- 只收 id 在角色库里还没有的；投不投影仍按 H5 的规则。
- 计划里各家的结论：
  - Claude、OMP 写明投影出去的名字；
  - Codex 写“自定义代理不能收窄父会话的沙盒”；
  - DSH 写“没有原生子代理定义”。
- 包里的角色不进 `delegate` 的角色库，那是另一份要持久化、能编辑的东西，留给第三步一起考虑。

**事件处理只投给直连 Claude 的会话插件。**

- 只投可信、启用的包里的事件处理。
- 事件名映射成 Claude 的名字（`sessionStart` → `SessionStart` 等）；Claude 没有的事件不投。
- 工具事件加 `matcher: "*"`。
- 插件目录的摘要算上 hooks 的内容；没有事件处理时删掉 `hooks.json`。
- 其余各家写明原因：
  - Claude 走配置：没有会话插件；
  - Codex：没在真实会话里验证过；
  - OMP：JS/TS 模块，不接受命令；
  - DSH：没有入口。

**计划需要知道更多**：`Target` 加 `managed`，表示会话跑在 Aeroric 管理的目录里，由路由给出（`Route::managed_home`）。`plan` 也多了数据目录参数，用来查技能文件夹和角色库。

## Alternatives considered

**给 OMP 生成一个 TS 模块包住命令。** 最强的理由是表里 OMP 那格就有了。没选：

- 要按 OMP 的 Hook API 写事件名映射、参数和返回值，静态读得出接口，但真实行为没跑过；
- 生成的模块会在 OMP 进程里执行，出错时比一条命令难查。

先如实写原因，等 OMP 的真实会话评测（H8）跑过再说。

**Codex 经会话 `config` 下发 Hook，连同信任哈希。** 源码上可行（H1 第二步）。没选：真实 Codex 是否按会话层的信任哈希运行 Hook，NOT RUN。事件处理会运行命令，猜错的代价比少一项能力大。

**让 `points_into_store` 也认包的原目录**（`<数据目录>/packs/…`）。最强的理由是不用再复制一份。没选：

- 只凭路径里有 `packs` 这一级，用户自己的链接可能被误认，进而被清掉；
- 复制到仓库后，内容一变就是新文件夹，正在用旧版本的会话不受影响，和内置技能按版本分文件夹是同一个做法。

## Consequences

- **收益**：
  - 一个可信的能力包，在 Claude、Codex、OMP、DSH 的本机会话里都能用上它的技能和命令；
  - Claude、OMP 能用上它的角色，直连的 Claude 能用上它的事件处理；
  - 每一项给了没有、为什么，都在启动的工具清单里。
- **局限**：
  - 管理界面和接口还没有，要手写 `pack.json`；
  - 包里的角色不进 `delegate`；
  - 事件处理只覆盖直连 Claude；
  - 技能仓库里按内容分的旧文件夹不清理（内置技能的旧版本也不清理，同一问题）；
  - 真实 Harness 里包的技能能否被调起、插件的事件处理在无界面模式下是否运行，NOT RUN。
- **验证**（在 Mac mini 上跑）：
  - 计划：一个五类俱全的可信包，在六种去处（Claude 直连和走配置、Codex 直连和走配置、OMP、DSH）上每一项都有结论和正确的位置；
  - 技能不给的六种原因，以及远端会话什么都不给；
  - 技能按内容放进仓库，命令写成 `SKILL.md`，内容不变用同一个文件夹，改了就换；
  - `hooks.json` 只收可信包里 Claude 有的事件；
  - 包里的角色只在 id 没被占用时并进角色库；
  - 挂载结果和计划一致：
    - 插件里有技能、命令、角色和 `hooks.json`；
    - OMP 受管目录有技能和角色，没有事件处理；
    - 包停用后，这些都撤掉。
