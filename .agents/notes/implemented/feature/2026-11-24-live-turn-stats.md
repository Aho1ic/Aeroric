# Agent Note: 一轮跑着时，统计栏实时显示用时、速度、步骤和输出

Status: implemented

## Problem

用户 2026-11-24 要求：每次运行时都要实时显示用量、速度、步骤等内容。

[Claude 长回合那一步](../bug-fix/2026-11-24-claude-long-turn-readout.md)已经让 Claude 的 token 和上下文随每次模型回答更新，但统计栏里还有几项要等一轮结束才有：
- **模型用时、输出速度：** `SessionStats` 在 `turnEnded` 时才把这一轮的时间加进去，输出速度从模型用时算；
- **统计卡：** 优先显示会话文件的统计（`SessionStats(transcript:)`）。会话文件在打开页面时读一次，之后要等一轮结束才重读；
- **没有一处写“这一轮”：** 一轮跑了多久、走了几步、出了多少 token，都看不到。

## Decision

**单独算正在跑的这一轮（`RunningTurn`），不和整个会话的统计混在一起。**
- **页面看到了这一轮开始时**，按页面自己收到的更新算：
  - `SessionStats` 记下这一轮的开始时间、已结束工具调用的时间、调用次数、开始时的输出 token 数；
  - 正在跑的调用，从开始算到现在。
- **页面是这一轮中途打开的**，按会话文件补上：
  - 会话文件里最后一轮（打开时读到的）给出开始时间、已有的调用和它们的时长、已有的输出 token；
  - 页面打开后收到的更新再加上去。
- **怎么算：**
  - 已用时 = 现在 − 开始；
  - 工具用时 = 已结束的 + 正在跑的；
  - 模型用时 = 已用时 − 工具用时；
  - 输出速度 = 这一轮的输出 token ÷ 模型用时。模型用时不满 1 秒、或者还没有输出时，不显示。

**统计栏每秒刷新，只在有一轮在跑时。**
- `LiveSessionView` 在 `turnActive` 时用 `TimelineView(.periodic(by: 1))` 包住统计栏；
- 胶囊写“3 轮 42 步 · 2 分 5 秒 · 35 tok/s”，时间是这一轮的，速度用这一轮的；
- 点开“会话统计”卡，上半是“这一轮（进行中）”：已用时、模型用时、工具调用用时、步骤、输出、输出速度；下半是“整个会话”，和原来一样；
- 一轮结束后停止按秒刷新，回到原来的显示。

## Alternatives considered

**把这一轮的数加进整个会话的统计里，只显示一套。** 没选：页面中途打开时，会话文件的统计已经算进了这一轮的前半段，再加页面收到的更新就会重复计算，要拆开很麻烦。分开显示，两边都准确。

**宿主定时推送这一轮的统计。** 没选：时间、调用、输出在客户端都已经有了，按秒在本地算就够，不增加宿主的推送。

## Consequences

- **收益：** 一轮跑着时就能看到跑了多久、模型和工具各花了多少时间、走了几步、出了多少 token、速度多少。
- **局限：**
  - 输出 token 要等 Agent 报告用量才动，Claude 是每次模型回答一次，所以速度一段一段地跳；
  - 页面中途打开时，打开那一刻正在跑的调用只算打开以后的时间；
  - 真实会话上没有目检。
- **验证：** Swift 新增 1 个测试，覆盖两种情况：
  - 页面看到这一轮开始：时间、工具（含正在跑的）、步骤、输出、速度；
  - 中途打开：会话文件补上开始时间、调用和输出。

  胶囊的写法也测了。MacBook 上 AeroricKit 全部测试都过。
