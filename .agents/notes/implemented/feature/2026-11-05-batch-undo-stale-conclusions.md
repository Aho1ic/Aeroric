# Agent Note: 多轮撤销与结论绑定快照（R2-3a）

Status: implemented

## Problem

R2-1 只能一轮一轮撤销。Agent 连着走偏了好几轮时，用户得从后往前一轮轮点，而且每撤一轮，前面那一轮依据的文件就又变了一次。另外，进度页里的“有证据”“检查通过”和侧支结论，都只说明当时成立；之后文件又被改了，它们看上去仍然可信。

## Decision

- 多轮撤销：
  - 协议 `TurnAction` 新增 `undoFrom`，含义是“这一轮及之后所有未撤销的轮次”。`TurnRecord` 新增 `undoGroup` 和 `stateBeforeUndo`；`TurnPlan` 新增 `turns`，列出这次覆盖的轮次。
  - 计划按文件合并：
    - 目标内容 = 这批里最早动过这个文件那一轮的 `before`；
    - 预期的当前内容 = 最晚动过它那一轮的 `after`；
    - 当前内容和预期不一致就跳过，原因写“这一轮之后又改过”。
  - 中间已撤销的轮次不算在内。任何一轮 HEAD 变了，整批拒绝，写“其中一轮提交了 …”。
  - `restore` 作用在某个组员身上时，整组一起撤回；每轮回到撤销前的状态（待验收或已接受）。单轮撤销沿用同一套代码，成员只有它自己。
- 结论绑定快照，只在读取时计算，不另存：
  - 改动 effect：`derive` 把账本里这一轮的 turnId 写进 `TurnChanges` 证据的 `detail`。依据 = 这一轮 `after` 里各个文件的内容。
  - 验收标准通过：`Obligation.passedMs`（自动检查或手动设为通过时写入）。依据 = 到那时为止每个改过的文件，在最后一次改它那一轮的 `after` 里的内容。
  - 侧支结论：子会话有账本记录时，依据它改过的文件；只读子会话改不了文件，依据就用带回结论时主目录的快照（`BranchResult.basis`，钉在 `refs/aeroric/branches/<task>`），这时任何已跟踪文件变了都算过时。
  - `checkpoint.get` 多返回一个 `stale` 列表，每项给出变了的文件和 `sinceTurn`（之后第一个改它的轮次；结论自己那一轮被撤销时，就填它自己）。用 `cat-file --batch-check` 和 `hash-object --stdin-paths` 批量算，进度页每 3 秒刷新时一并带回。
- 界面：
  - 轮标题加一个“⋯”胶囊按钮，弹出的面板里只有“撤销到这一轮之前”，并写明“撤销这一轮和之后 N 轮”；后面没有未撤销的轮次时不显示这个按钮。
  - 确认框标题写“撤销第 a–b 轮的改动？”；整批撤回的按钮写“撤回整批撤销”。
  - 进度页顶部有一条“N 条结论可能已过时”的胶囊；对应的行把标记换成琥珀色“可能已过时”，悬停列出每个文件，以及“第 N 轮起变了”“这一轮已撤销”或“手动修改或已撤销”。

## Alternatives considered

- **把多轮撤销拆成从后往前的多次单轮撤销**：中间任何一轮被跳过的文件，都会让前面的轮次判断出错，而且撤回时要分几次。合并成一份计划，只需比较一次首尾内容。
- **结论生成时就把 `basis` 存进检查点**：`derive` 是纯函数，不能调用 git；而且账本已经存着每一轮的快照。现算的结果始终跟着当前文件走，撤回撤销后标记会自动变回绿色。
- **目标“已验证”也绑定文件**：拷问时这样定过，但实现时发现，目标上的“已验证”只表示这是用户的原话，并不是对结果的验证，文件变了它也不会因此失效。所以改为绑定通过的验收标准，汇报时已经说明。
- **系统菜单（NSMenu）**：菜单项画不成胶囊；用户要求统一用胶囊，所以改用弹出面板。

## Consequences

- 旧会话的 effect 证据里没有 turnId，验收标准也没有 `passedMs`，这些都不判断是否过时。
- 只读侧支的依据是全部已跟踪文件，不相关的改动也会把它标成过时：宁可多报，不要漏报。
- 撤销提醒发给 Agent 时，多轮的写“用户撤销了最近 N 轮改动”；结论过时不会提醒 Agent。
- 目检时顺带修了：
  - 去掉系统顶栏的浅色带之后，滚动的内容会盖到窗口标题上。现在中间那栏的标题栏下面垫一条和画布同色的条，悬停时不会变色。
  - “N 轮待验收”胶囊和右上角的“会话信息 / ⋯”按钮浮在对话上，背景原来是半透明的，现在加了不透明的胶囊底。
  - 窗口窄、会话信息又被用户折叠时，点“会话信息”原来只是把折叠展开，但窄窗口放不下这一栏，所以什么也不显示；现在放不下就直接弹出浮层。

## Verification

- core 单测（临时仓库）：
  - 三轮里撤销后两轮，再整批撤回，状态恢复为已接受和待验收；
  - 中间已撤销的轮次被跳过，手改过的文件被跳过；
  - 批内任何一轮有提交就整批拒绝；
  - 后续轮次让 effect 过时，撤销那一轮后恢复；
  - 撤销结论自己那一轮会标记它，撤回后恢复；
  - 手改文件让通过的验收标准过时；
  - 只读侧支依据整份快照。
- 宿主端到端：两轮改文件后，`checkpoint.get` 报告 u1 过时，`sinceTurn` 为 u2；`undoFrom` 把两轮一起撤销，`restore` 一起撤回。
- Swift：`span`、解码，以及悬停文字。
