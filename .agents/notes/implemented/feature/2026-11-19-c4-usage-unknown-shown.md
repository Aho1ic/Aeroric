# Agent Note: C4 第二步：账单和用量页明说"用量未知"，网关请求可以逐次查看

Status: implemented

## Problem

[C4 第一步](2026-11-19-c4-gateway-attempts.md)让网关按每次尝试记账，区分"上游报告"和"未知"的用量，并加了宿主方法 `gateway.requests`。方案剩下两条：

- 第 4 条：账单和配额节奏读新字段，未知用量的回合显示"用量未知"，不显示 0；
- 第 5 条：App 用量页能按请求展开，带来源标记。

动手前核对了账单和配额节奏实际读什么：

- [回合账单](2026-11-09-turn-bill.md)读的是 Agent 自己的会话文件，不是网关记录。分项用量本来就是可空的，没记时卡片上写"—"，胶囊只写"N 次工具"，不会写 0；但也没说用量未知，看起来像这一轮没花钱。
- [配额节奏](2026-11-10-quota-pace.md)读的是订阅接口给的已用百分比，不汇总 token，和"用量未知"无关。

## Decision

**回合账单**（`TurnBill.swift`）：

- 会话文件没记用量（输入、输出都为空）、也没有金额时，胶囊写"用量未知 · N 次工具"；上游明确报了 0 时照旧只写"N 次工具"。
- 账单卡里输入、输出没有数时写"未记录"，不再写"—"。
- 账单仍然读会话文件，不改成读网关记录。会话文件是这一轮实际发生的事，网关记录还得先和回合对上号；不经过网关的会话（官方登录直连）也没有网关记录。

**配额节奏**：不改。

**用量与成本页**（`ChangeCostPane.swift`）：在"改动成本"下面加一节"网关请求"，打开页面时读 `gateway.requests`（最近 30 个）。

- 汇总一行，例如"共 120 次 · 失败 3 · 5 次用量未知 · 输入 1.2M · 输出 80K · 缓存写入 5 分钟 1.2K / 1 小时 800"。有用量未知的请求时，这一行是警示色。
- 每个请求一行：模型、最后用的连接、成功或"失败 + 状态码"、用量（未知的写"用量未知"）。试了不止一次时写"试了 N 次"，点开逐行列出每次尝试，例如：
  - "第 1 次 · A · 429 · 0.4 秒 · 用量未知 · slow down"
  - "第 2 次 · C · 熔断中，跳过"
- 来源是"估算"的用量前面加"约"。目前还没有地方会写估算值。

## Alternatives considered

**回合账单改读网关记录。** 最强的理由是网关知道每次尝试和用量来源，比会话文件更细。没选：

- 网关记录要先和回合对上号：请求只有会话 id，没有回合号；
- 走官方登录直连的会话没有网关记录；
- 会话文件已经能区分"没记"和"0"，缺的只是把话说明白。

**网关请求单独做一页。** 最强的理由是以后能做筛选和分页。没选：这一版只看最近 30 个，放在"用量与成本"里和额度、改动成本在一处就够；等 E6 用量上限、E7 按用途记账有了更多数据，再考虑单独成页。

## Consequences

- **收益**：
  - 回合没有记录用量时明说"用量未知"，不会被当成没花钱；
  - 第一次能在 App 里看到网关的每个请求、每次尝试，以及哪些请求的用量没人报。
- **代价**：打开"用量与成本"页时多读一次网关数据库。
- **没做**：
  - 网关请求的筛选、分页；
  - 按任务归属请求：网关记录只有会话 id，没有任务号。
- **验证**：
  - Swift `TurnBillTests` 新增 `testATurnWithoutRecordedUsageSaysItIsUnknown`：没记用量写"用量未知 · 2 次工具"，报了 0 的不写；卡片写"未记录"。
  - Swift 新增 `GatewayRequestsTests`：解码带三次尝试（一次 429、一次熔断跳过、一次成功）的请求，汇总行、请求行、每次尝试行的文字，以及用量未知的请求。
  - 界面待目检，记在路线文档 §8。
