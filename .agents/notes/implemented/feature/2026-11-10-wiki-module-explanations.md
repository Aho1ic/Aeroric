# Agent Note: Wiki 模块页的职责与常见坑（R4-2）：模型推断、逐条核对引用、过时标记

Status: implemented

## Problem

[模块页骨架](2026-11-10-wiki-module-pages.md)（R4-1）只写从代码里直接读到的东西：入口、公开符号、依赖。路线文档 §4.2 要求模块页还要写清"职责"和"常见坑"，这两样只能靠读代码去理解，需要调模型。[路线复核](../../proposed/architecture/2026-11-02-roadmap-recheck.md)对它有两条要求：推断出来的内容要和直接读到的分开标明；页面引用的代码变了，内容要标"可能过时"。

用户 2026-11-10 定了 5 条，全部按推荐：

- 复用记忆的分析模型；
- 每条都要有出处，核对不上就丢掉；
- 手动生成和空闲时自动生成都做，自动生成每天最多 20 个；
- 读过的文件一变就标过时；
- 记录每次生成的花费并显示出来。

## Decision

**给模型什么**（`knowledge/explain.rs`）

- 模块的事实，也就是 R4-1 已经写在页上的那些：路径、文件数、入口、依赖。
- 代码片段：入口文件的前 80 行，以及每个公开符号前 4 行到后 16 行的范围，同一文件里重叠的范围合并。每一行前面标上行号。
- 笔记：正文提到这个模块文件的决策笔记，按完整路径或 `src/` 之后的路径匹配，最多 3 篇，每篇最多 1500 字。
- 总长度上限 24K 字符，超出的片段不放进去。

**要它写什么、怎么核对**

- 模型要输出 JSON：`duties`（职责，2–4 条）和 `pitfalls`（常见坑，最多 5 条）。每条一句话，`cites` 里至少有一处引用，写成 `路径:行号` 或 `note:笔记路径`。
- 宿主逐条核对引用：
  - 路径必须是给过的片段，行号必须落在片段范围内；
  - 笔记必须是给过的那几篇；
  - 核对不上的引用删掉，一处引用都不剩的句子整条丢弃；超过条数上限的也丢弃。丢了几条记在 `dropped` 里。
  - 回答不是要求的 JSON 时，记一条出错的运行记录，这次不写进页面。

**存储与页面**

- 每个项目的 `wiki.db` 新增两张表：
  - `explanations`：按模块 id 存，内容包括职责、常见坑、读过的文件及其 blob、模型、token 数和时间；
  - `explain_runs`：每次生成记一条，包括模型、token 数、是不是自动生成、出错原因。
- 编译时，把生成结果作为"职责（推断）""常见坑（推断）"两段，放在"概览"后面：
  - 第一行写"以下由 某模型 根据代码推断，每条都核对过引用。"；
  - 每条后面括号里列出引用；
  - 这两段的来源是模型读过的文件，版本是读的那一刻的版本。
- 过时判断：只要读过的文件里有一个的当前 blob 和生成时不同，这两段开头加一行"可能过时：生成后 `x.rs` 等 N 个文件改过"。用户手改过的段落照旧受保护，来源变了就开 issue。

**什么时候生成**（宿主 `session_live_services/wiki.rs`）

- 用的是记忆的"分析模型"，即记忆页选的连接和模型，单次输出上限 1500 token。没选模型时按钮不可用，界面写明原因。
- `wiki.explain {projectId, slug}`：在后台生成一页，立即返回。生成一次可能超过 App 等宿主回应的 30 秒，所以单页也走后台。第一轮目检时，同步等待会先报"宿主没有及时回应"，过一会儿页面上却出现了结果。
- `wiki.explainAll {projectId}`：后台依次生成所有缺说明或说明过时的模块页（过时的排在前面），立即返回排了多少个。同一项目同时只跑一个生成任务，按钮和空闲自动生成都算在内，已在跑时不再另开；`wiki.explainState` 返回进度、出错原因、还有几个待生成，以及本月的次数和 token 数。整批只扫描一次代码；遇到模型调用失败（比如没有连接、没有密钥）就停下并说明原因。
- 自动生成：Wiki 每 2 分钟巡检一次，同时满足下面这些条件时，每次只生成一个模块：
  - 没有会话正在跑一轮；
  - 没有正在进行的"全部生成"；
  - 今天所有项目的自动生成加起来不到 20 个。

  过时的模块排在缺说明的前面。同一个模块过时后，距上次生成不满 24 小时不会被自动重新生成（页面照样标"可能过时"）。手动生成不受这个上限和冷却限制。

**界面**

- Wiki 页头：有模块页时显示"全部生成说明"按钮，旁边一行写"生成说明中 3/60"，或者"12 个模块待生成说明 · 本月生成 3 次 · 26.1K tok"。
- 模块页页头：显示"生成说明"或"重新生成说明"按钮，生成时转圈，并一直跟着进度，结束后刷新页面；中途出错就显示原因。
- 两段推断内容的小节标题用不同的图标和颜色，和直接读到的小节区分开。

## Alternatives considered

- **Wiki 单独设一个模型**：可以给 Wiki 选更便宜的模型。没选：用户已经在记忆里配好了分析模型，再加一个设置只会多一处要维护的地方；以后需要时再拆。
- **让模型自由写，不强制引用**：写出来更流畅。没选：路线复核要求推断的内容要有出处，没有出处的句子没法验证，读起来却和事实一样可信。
- **只标"可能过时"，不自动重新生成**：一分钱不花。没选：用户希望自动跟上代码，所以自动重生成，但每天最多 20 个，而且只在空闲时做。
- **只用 token 数判断成本，不看金额**：CPA 的模型不在价目表里，只能这样；有价格的模型以后可以接上 R3 的价目表。

## Consequences

- **收益**：
  - 模块页现在能回答"这个模块管什么、改它要注意什么"，每条都能点回代码行或笔记去核对。
  - 代码变了以后，页面会明确提示这两段可能过时，不会把旧说法当成现在的事实。
- **代价**：
  - 每生成一个模块约 6–9K 输入 token。60 个模块的项目全量生成一遍约 50 万 token，按每天 20 个自动生成，要 3 天才能补齐。
  - 引用只核对位置，不核对意思：模型可能引用了对的行，却说错了这一行的作用。
  - 片段只覆盖入口文件和公开符号附近的代码，私有实现里的坑看不到。
- **验证**：
  - core 单测（`knowledge::explain_tests`）：
    - 输入里有入口文件和符号片段（重叠合并、带行号），只带提到本模块文件的笔记；
    - 引用核对：越出片段的行号、没给过的文件和笔记都算不合格；
    - 带代码块围栏的回答能解析，没有合格引用的句子被丢弃，不是 JSON 时报错；
    - 编译后"职责（推断）""常见坑（推断）"排在概览后面，来源版本是生成时的版本；文件变了以后开头出现"可能过时"。
  - Swift 单测（`WikiTests`）：单页生成后提示"已生成说明"；全部生成会跟进度直到结束，并显示中断原因；状态那一行的文字；状态的解码。
  - 第一轮目检（2026-11-10，Codex Computer Use，审阅版）：
    - Wiki 页头显示"60 个模块待生成说明"；
    - sessions 页的两段推断都有内容：职责 4 条、常见坑 5 条，每条带引用，小节图标和颜色与直接读到的小节不同；
    - 生成后页头变为"59 个模块待生成说明 · 本月生成 1 次 · 8.1K tok"。
    - 抽查两条引用：
      - `live/mod.rs:52` 的注释"Changes take effect from the next turn"支持"配置变更从下一轮生效"；
      - `live/mod.rs:163` 只支持那一句的前半部分，后半部分靠同一句的另外两处引用。这说明核对只看位置、不看意思，和代价里写的一致。
    - 问题：点"生成说明"两次都报"宿主没有及时回应"，结果却在稍后出现。已改为后台生成、界面跟进度。
  - 复测（2026-11-10）：点"生成说明"后按钮一直显示"生成中…"，约 60 秒后页面自动出现两段内容，按钮变成"重新生成说明"，没有再弹超时。
  - 运行记录还暴露了一个问题：另一个项目里"LYX"这个合并出来的大模块，文件不停在变，一个下午被自动重新生成了 4 次。为此给自动重新生成加了 24 小时冷却。
  - 运行记录里也看到 CPA 两次返回 429（用量到上限），都记为出错，下一轮巡检再试。
