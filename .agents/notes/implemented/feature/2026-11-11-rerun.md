# Agent Note: 换模型重跑与并排比较（R5-2）

Status: implemented

## Problem

想知道"这一轮换个模型或换个 Harness 会不会做得更好"，以前只能自己新开会话、手动把代码退回去、再把几次结果对着看。路线复核把它列为 R5："从历史会话恢复起点，换模型或 Harness 重跑，并排比较交付和证据"。

用户 2026-11-11 定的做法，全部按推荐：

- 先做 [回合分级](2026-11-11-turn-outcomes.md)（R5-1），比较时用它；
- 从任一改过文件的回合开始，代码回到这一轮开始前的快照；
- 每个重跑放在自己的独立副本里，一次最多 3 个，同时跑；
- 默认带上这一轮的消息和原会话已确认的决定，可以只给消息；
- 入口放在改过文件的回合下方；
- 重跑就是普通会话，原会话里有一张比较卡；
- 比较卡上原回合放第一列做对照，后面每个重跑一列，只并排列出数据，不打分；
- 跑完照常跑项目检查；
- 用户挑一个带回，不自动撤销原回合，原回合的改动还在时提示。

## Decision

**起点**

- 回合账本里每个改过文件的回合都存了开始前的快照树（`TurnRecord.before`）。重跑的副本从这棵树建起：`isolated_copy::create_from(.., from)` 先 `git worktree add --detach HEAD`，再把 `HEAD..from` 的差异打进副本，起点钉在这棵树上。
- 带回时比较的是"起点"和"副本现在"。原目录在这一轮之后又变过的，走 [独立副本](2026-11-05-isolated-copy.md) 已有的冲突流程。
- 没有改动记录的回合（只读回合、导入的会话）不能重跑：它们没有开始前的快照。

**提交**

- `SubmissionRequest` 新增可选的 `copyFrom`，必须和 `isolated` 一起用。只在设了它时写进指纹（追加字节 3 和树的哈希），旧请求的指纹不变；schema 里加为可选字段。
- 宿主的 `rerun.start {taskId, turnId, message, brief?, targets: [{configurationId, model?, reasoningEffort?}]}` 为每个目标构造一个提交，走 `TaskService::submit`。配置校验、建任务、建副本、启动都和用户手动新建会话完全一样：
  - 配置版本用当前目录的版本号；
  - 权限：配置支持就用"自动编辑"，否则沿用原会话的。重跑只改自己的副本，一条命令一问只会让它停在那里，用时也成了用户回复的速度（R5 目检时一个重跑 8 分 40 秒，大半在等"批准一次"）；
  - 会话改名为"原标题（重跑 · 配置 · 模型）"。

  某个目标被拒时，把原因写进 `refused`，其余目标照常开。全部被拒才算整次失败。
- **消息**：
  - 默认在用户的消息前面加一段"这个任务之前已经确认过下面这些"，内容是原会话检查点里在这一轮之前就有证据的目标、决定和约束（`rerun::brief`）。
  - 检查点的回合号从 1 开始，所以会话记录里第 i 轮（从 0 数）之前的条目，回合号都 ≤ i。
  - 证据上没有回合号的条目，时间不明，不带。

**记录与比较**

- 每次重跑存一组，放在 `<data>/reruns/<原会话>.json`：回合、起点、消息、是否带了摘要，以及每个重跑会话的 id、配置和模型。
- `rerun.list {taskId}` 每次现读，返回每组的原回合一列、每个重跑各一列，每列包括：
  - 分级：运行中、完成、没跑成、已中断、产品失败；
  - 输入和输出 token、费用、用时、工具步数；
  - 改动的文件数和行数；
  - 检查结果。
- 重跑会话只看它的第一轮；之后用户在里面接着聊的回合不算进比较。
- 每一列的分级和数字由 core 的 `rerun::column` 算，宿主只读会话记录和账本再交给它。

**界面**（R5-2b）

- **入口**：在改过文件的回合标题那一行，点"⋯"，选"换模型重跑…"。推荐里写的是放在"撤销 / 接受 / 重做"同一排，但那一排在窄窗口下已经挤满了，所以放进了已有的"⋯"弹层；"⋯"现在只要能重跑就会显示，不再只在能"撤销到这一轮之前"时才出现。
- **面板**：
  - 列出项目里所有能启动的配置（没有被拦下原因的），和原会话同一个 Harness 的排在前面；名字重复的配置（每个 Harness 都有一个"全部第三方模型"）后面加上 Harness。
  - 每个配置是一条 28pt 高的扁胶囊：名字在左，右边是"已选 N"小胶囊、模型数和一个展开时转向下的箭头。点它展开，模型在胶囊下方排成可换行的 20pt 扁胶囊（`AeroricChipStyle`，新加在 `Design/Components/AeroricControls.swift`），选中的是实心胶囊加对勾；同一个配置可以选多个模型，总共最多 3 个。展开用的是普通按钮：一开始用的 SwiftUI DisclosureGroup 不响应辅助功能的点击，目检脚本点不开。
  - 面板打开时，键盘焦点会落在第一行上，macOS 用系统强调色（用户设的是紫色）画一圈焦点环；列表和消息框都关掉了焦点效果（`.focusEffectDisabled()`）。
  - 消息框隐藏 `TextEditor` 自带的方角背景，外面是 12pt 圆角的底和描边，和记忆页的编辑框一致。
  - 面板打开时让 App 重读这个项目的配置目录：重启后宿主还没问到 Codex 的模型时读的目录里没有 Codex，之前要等切换项目才会重读。
  - 消息预填这一轮用户说的话，可以改。
  - "只给消息"默认不勾，也就是默认带上已确认的决定和约束。
  - 有目标被拒时，在会话里提示哪些没开成。
- **比较卡**：放在对应回合的下面。
  - 原回合是第一列，后面每个重跑一列，横向可以滚动。
  - 每列显示分级、改动、检查结果、token、用时和工具步数、费用；没跑成的悬停可以看到错误原文。
  - 有重跑还在跑时，每 5 秒刷新一次。
  - 每个重跑有三个按钮："打开"跳到那个会话；"带回这个"把它的副本全部带回原目录；"丢弃"删掉它的副本，会话留在侧栏。卡头另有"全部丢弃"。副本已经丢弃的重跑（`rerun.list` 的 `copy` 为假），"带回这个"和"丢弃"不可点。
  - 原回合在重跑开始之后被撤销（通常是"撤销原来这一轮，再带回"），这一列显示"重跑后已撤销"，不算产品失败：用户选了重跑的结果，并不说明原来那一轮做错了。
  - 比较卡用 `.accessibilityElement(children: .contain)` 加标识，里面的按钮保留各自的标识（目检时卡片的标识把"全部丢弃"的覆盖了）。
  - 原回合的改动还在时，"带回这个"会问：先撤销原来这一轮再带回，还是直接叠在一起带回。带回出现冲突时，提示去那个重跑的改动页处理。

## Alternatives considered

- **宿主自己建任务、建副本、启动，不走提交流程**：委派就是这么做的，不用改提交格式。没选：配置校验、副本检查、启动失败的回执，提交流程里都有，再写一份容易两边不一致。加一个可选字段，代价更小。
- **重跑放在原会话里，撤销这一轮再重做**：R2 已经有"撤销再重做"。没选：那只能同一个模型一次跑一个，也没法并排比较。
- **副本从原目录的当前状态起步**：不用改副本代码。没选：这一轮之后原目录可能已经又改过好几轮，重跑看到的代码和原回合当时看到的就不一样了，比较不公平。

## Consequences

- **收益**：同一个起点、同一条消息，可以一次让三个配置各跑一遍，结果和原回合并排看，失败的那列能看出是没跑成还是做错了。
- **代价**：
  - 每个重跑占一个独立副本和一个会话，跑完不要的要丢弃。
  - 只有改过文件的回合能重跑。
  - 带的摘要只有检查点里有证据的条目，对话里口头说过、没进检查点的约定不会带上。
- **验证**：
  - protocol 单测：`copyFrom` 只在设了时改变指纹，可以往返序列化。
  - core 单测：
    - 副本从更早的快照起步，内容是那时的，原目录不受影响，不存在的快照会报错；
    - 摘要只带这一轮之前的条目，第一轮没有摘要；
    - 消息的拼法；
    - 重跑组按原会话分别保存。
    - 原回合在重跑开始后被撤销时显示"重跑后已撤销"，之前就撤销的仍是产品失败；配置支持时重跑用"自动编辑"权限。
  - Swift 单测（`RerunTests`）：比较结果的解码，包括运行中、没跑成、会话已删除的列；分级、改动、检查、用量、用时的文字；开始和带回后的提示。
  - `rerun.start` 和 `rerun.list` 要真实的项目仓库、Agent 配置和会话，现有的 host 测试脚手架搭不起来，留给目检。
  - 目检（2026-11-12，Claude 经 SSH 用辅助功能接口在后台操作审阅版，报告在 `~/Documents/computer-use/2026-11-12-0850-aeroric-r5-claude/`）：重跑两个模型、比较卡、打开、带回（走冲突分支）、全部丢弃、窄窗口都正常；发现的配置重名、展开点不开、余额不足归错类、卡片标识覆盖、丢弃后按钮可点、撤销后误标产品失败、重跑停在审批上，都已在这篇笔记描述的版本里修掉。
