# Agent Note: 项目与会话标签

Status: implemented

## Problem

侧栏的项目和会话越来越多，只能按状态筛选，没法按“重要”“部署”“调研”这类自定的维度归类。导入的会话（`imported.<id>`）也要能归类。

## Decision

- **一套标签库**（T1）：核心独占的 `tags.json`（`TagStore`，`core/crates/aeroric-core/src/projects/tags.rs`）：`tags` 是名字、预设色（`ProjectColor` 的 8 个 id）、范围（缺省为所有会话，`projectId` 为仅当前项目）；`assignments` 把侧栏行的 id（项目 id、`task.<id>`、`imported.<id>`）映射到标签 id。宿主并发处理请求，读改写在一把进程锁里完成。
- **接口**：`tags.list` / `create` / `update` / `delete` / `assign`。`assign` 一次给出这一行的全部标签；宿主校验范围：项目与会话都接受所有会话的标签和它所属项目的标签（项目的所属项目是它自己，目检后 Q1-a），并在 `rowProjects` 记下这一行所在项目。`update` 可改范围：改为「仅某项目」时从其他项目（或不属于任何项目）的行上摘掉，App 先按 `rowProjects` 算出会摘掉几处并确认（Q2）；改为所有会话不摘任何东西。删除标签同时从所有行摘掉，摘空的行从表里去掉。同一范围内名字不能重复，名字最多 24 字。
- **界面**（设计稿经用户确认，Q1–Q5 均按推荐）：
  - 行内完整显示标签胶囊（T2），最多 2 个，其余 `+N`；标题先截断，标签不消失。项目行、会话行、导入会话行都显示。
  - 筛选菜单在“状态”下面加“标签”，一次一个（Q1-a）；项目带这个标签时整个项目与其会话都显示，否则只显示带它的会话（Q2-a）；筛选时项目自动展开；顶部出现「标签：名 ✕」。
  - 会话与项目的菜单里「设置标签 ›」：已贴的用系统菜单原生的勾，每项带彩色圆点（菜单图片默认按模板画成同一种灰，圆点要设 `isTemplate = false`），保持库里的顺序（Q4）；末尾「新建标签…」建好即贴上、「管理标签…」。
  - 新建对话框（目检后重做）：实时预览胶囊、名称、色板、可用范围（`CapsuleSlider` 一直显示；不属于任何项目的会话「仅 当前项目」置灰并说明，Q3-a）与一行范围说明；按钮「创建并贴上」。
  - 「管理标签…」在设置标签子菜单和筛选菜单里（Q4-b）：每行颜色圆点（点开改色）、预览或改名框、范围下拉（所有会话 / 仅各项目）、铅笔与删除图标按钮，右上角「新建」。
- **客户端**：`TagBook`（`AeroricUI/Shell/SidebarTags.swift`）经环境传给侧栏，不给 `ProjectSidebar` 再加参数；勾选先在本地生效，再写宿主并重读。

## Alternatives considered

- **把标签写进 `projects.json` / 任务记录**：不选。旧客户端的类型化结构会在下次保存时丢掉不认识的键；导入会话也没有自己的记录。
- **标签按项目各存一份**：不选。T1 要一套库；仅当前项目的标签用 `projectId` 表示即可。
- **侧栏用彩点**：用户 T2 要求完整显示名字。

## Consequences

- 新文件 `tags.json`（私有权限、原子写），备份与迁移要带上它。
- 单测：核心 3 个（范围、删除级联、名字与颜色），客户端 3 个（可用标签、筛选、顺序）。

- 删除项目或会话不清理它的 `assignments` 条目；条目指向不存在的行，不显示也无害。
- 筛选是窗口内的展示状态，不持久化。
