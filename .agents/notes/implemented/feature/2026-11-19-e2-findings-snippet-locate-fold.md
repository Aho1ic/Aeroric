# Agent Note: E2 审查意见带代码片段：按代码定位，重复的合并

Status: implemented

## Problem

[1118 调研](../../proposed/architecture/2026-11-19-new-addition-1118-research.md) 的 E2。[审查循环](2026-10-30-review-loop.md) 的意见只有 `file`、`line` 和文字：

- 审查者写的行号常常对不上（OCR 说的"位置漂移"），App 和写代码的会话都会被带到错的地方；
- 同一处问题换个说法提两遍，卡片上就是两条（OCR #709）；
- 路径写成 `./src/a.rs`、`repo/src/a.rs` 这类形式时，和 E1 的覆盖清单对不上。

## Decision

- **意见带代码片段和类别**：
  - 审查者的 JSON 加 `snippet`（照抄改动后的代码，一到几行；也接受 OCR 的 `existing_code` 和 `code` 写法）和 `category`（`bug`、`security`、`performance`、`maintainability`、`test`、`style`、`documentation`、`other`，其他值忽略）；
  - 提示词写明 snippet 要照抄，行号写错时 Aeroric 会按它找到位置。
- **路径对齐**：意见的路径如果按目录边界匹配到这一轮要审的文件（E1 的 `same_path`），就改写成那个文件的路径。
- **按代码定位**（`review/locate.rs`）：
  - 从这一轮的快照树里读出改动后的文件（`git cat-file -p <after>:<路径>`）；
  - 匹配时，两边都压缩空白、跳过空行，所以重新缩进或换行都还认得出来；
  - 一行的片段如果整行对不上、但有 4 个字以上，允许作为一行的一部分来匹配；
  - 出现多次时，取离审查者写的行最近的那一处。
  - 找到了且行号不同：行号改成找到的位置，原来的写在 `movedFrom`；
  - 找不到：标 `unlocated`，行号保留审查者写的。
  - 没有片段的意见不检查。
- **合并重复**：
  - 同一文件、同一类别、同一段代码（压缩空白后），或者没有片段时文字相同（压缩空白、不分大小写），合成一条；
  - 保留第一条的编号和文字，级别取其中最高的，`merged` 记合进来几条。
  - 合并发生在发给写代码的会话之前，所以对方只需答复一次。
- **写代码的会话**收到的每条意见下面，都附上片段原文。
- **App**：
  - 意见行末尾写"（3 条相同）"；
  - 展开后显示片段（等宽字体），以及"位置已按代码修正（审查者写的是第 N 行）""引用的代码在文件里找不到，位置以审查者写的为准""合并了 N 条说同一处的意见"。
- **不做事实核查过滤**（用便宜模型删掉被 diff 直接驳倒的意见）。它在调研文档里是待 owner 拍板的事项，推荐先做一轮评测再决定。2026-11-26 owner 定开工、默认关，见 [E2 事实核查过滤](2026-11-26-e2-fact-check-filter.md)。

## Alternatives considered

**片段找不到时，让模型从 diff 里摘出它指的代码**（OCR 的 `RE_LOCATION_TASK`）。最强的理由是能救回改写过的片段。没选：多一次模型调用，结果也不可复现；先标"找不到"，看实际出现得多不多再说。

**按意见文字的相似度合并。** 最强的理由是能认出措辞差别更大的重复。没选：对同一处代码提的两个不同问题，文字可能很像，误合并会吞掉一个真问题。按"同一段代码 + 同一类别"合并，结果确定，也和 OCR 的意见身份一致。

## Consequences

- **收益**：行号对不上时能找回位置；同一个问题只出现一次，写代码的会话只答一次；E3 的轮间对比可以直接用"路径 + 类别 + 片段"作意见的身份。
- **代价**：每条带片段的意见要读一次文件，同一轮里同一个文件会重复读。
- **局限**：
  - 片段要从改动后的文件里照抄；指向已删除代码的意见会被标为"找不到"；
  - B5 的"无进展"判断仍按"文件:行"加文字比较，行号被修正后会更稳定，但没有改用片段。
- **验证**：
  - `locate.rs` 新增 2 个测试：
    - 重新缩进和换行后仍能定位；重复出现时取最近的；一行的一部分；找不到时标记，没片段时不检查；
    - 合并：同片段、不同类别、只有文字相同这几种情况，级别取最高，保留第一条的文字。
  - `review/tests.rs` 新增 `findings_land_on_their_code_and_say_the_same_thing_once`：在真实 git 仓库里，`./src/a.rs` 第 1 行的意见被移到第 4 行，和第二条合并为一条阻断，写代码的会话收到了片段。
  - Swift 新增 `testAFindingSaysHowItsPlaceWasSettled`。
  - 界面待目检，记在路线文档 §8。
