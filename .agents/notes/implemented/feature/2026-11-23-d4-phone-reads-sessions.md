# Agent Note: D4 后续：手机点进任务看会话

Status: implemented

## Problem

D4 八步做完，手机能看到项目和任务列表、答审批、新建任务，但点不进任务。[第八步笔记](2026-11-23-d4-phone-follows-live-sessions.md)的局限里写着：“会话消息、终端、文件和 Git 仍不随推送更新”。

动手前（`main@c7357b63`）核对的事实：
- **宿主早有接口，手机一个没用：** `session.messages`、`project.files`、`git.changes`、`git.diff` 都在宿主上（`remote_headless.rs`），手机端没有任何调用。手机 store 里的 `sessionMessages: [String]` 只在清空时出现过。
- **`session.messages` 的 DSH、OMP 分支有错：**
  - 对 `Result<Vec<SessionMessage>, String>` 调了 `into_iter()`，整份消息列表被当成一个元素，回给调用方的是 `[[…]]`；
  - 解析失败时回空列表，看不出读坏了。
  - Claude、Codex 走另一个分支，没有这个问题。
- **整份转写一次发出：** 不限条数，也不截长文本。经 Relay 发给手机，长会话会有几 MB，附件还带着 base64 数据。
- **转写路径由驱动写进任务记录：** 实时会话启动后，驱动报告会话路径（`TaskServiceSink::session` → `attach_session`），任务记录里就有 `<族>SessionPath`，`session.messages` 读的就是它。

## Decision

**宿主：`session.messages` 只回最近的、截过的。**
- **解析分支：** 解析改成返回 `Result`。DSH、OMP 读不出时回 `{available: false, reason: "unreadable", detail}`，嵌套的问题随之消失。
- **只回最近的：** 新的纯函数 `phone_transcript` 只回最近 `limit` 条，按原来的线上形状（`role`、`content`、`messageId`）：
  - `limit` 默认 40，最多 200；
  - 文本、思考、工具输入、工具输出每块最多 4000 字，截过的块标 `truncated: true`；
  - 附件去掉 `source`（数据），也标 `truncated`；
  - 另回 `total` 和 `omitted`，说明一共多少条、没显示多少条。
- **调用方：** 只有手机，没有别的调用方要兼容。

**手机：任务页。**
- **点进任务：** 任务列表的每一行点进去是任务页，里面有两部分：
  - 这个任务的待审批，用和列表页同一个审批行；
  - 会话的最近消息：“你”和“Agent”分开，工具调用、工具结果（失败的标红）、思考、附件各有写法，截过的写“太长，只显示了前面一部分”，有没显示的写“只显示最近 N 条，较早的 M 条在 Mac 上看”。
- **几种状态：**
  - 读取中；
  - 已显示（`refreshing` 表示正在更新）；
  - 没有可显示的：写明原因，例如“这个任务还没有会话记录”、项目在 SSH 或 WSL 上、记录读不出来；
  - 没读到：写原因，带“重试”。
- **谁读：** store 只记状态（`transcript`），要读时通知连接器（`onTranscriptWanted`），由连接器调 `session.messages`。store 自己不碰网络，和发命令一个做法。
- **何时重读：** 每次快照（重连、推送触发的重读、判旧后的重读）都会把打开着的任务再读一次。所以 Mac 上一有 `task-changed`，比如回合开始或结束、来了新审批，任务页就跟着更新。
  - 同时只有一次读，读的时候又被要求就记一笔，读完再读一次；
  - 任务在快照里没了，写“这个任务在 Mac 上已经没有了”。
- **不会出错的几处：**
  - 晚到的回答属于已经离开的任务时，丢掉；
  - 已显示的会话在一次读失败后保留，断线时页面不变空；
  - 取消配对或设备被撤销时清掉。

## Alternatives considered

**宿主按条推送增量消息。** 没选：手机端的规则是“快照是权威，推送只是提示”。重读最近 40 条只要一个请求，不会因为漏了某条增量而错位。

**用 `tasks.get` 带上消息。** 没选：任务快照每次推送都会重读所有项目的任务，带上消息会让每次重读都变重。会话只在用户打开任务时才读。

**手机端分页往前翻。** 这次没做：`limit` 最多 200，再早的去 Mac 上看。要翻页时，再给 `session.messages` 加起点参数。

## Consequences

- **收益：**
  - 手机能看任务在做什么、Agent 说了什么，不用回到 Mac；
  - DSH、OMP 会话的消息格式对了；
  - 长会话经 Relay 不再整份发送。
- **局限：**
  - 只读最近的消息，不能往前翻，也不能在任务页里发消息；
  - 实时会话正在输出的那条消息，要等写进转写文件才看得到；
  - 文件、Git、终端仍没接；
  - 真机、真实 Mac、真实 Relay 上 NOT RUN，界面没有目检。
- **验证：**
  - 宿主新增 1 个测试：
    - 只回最近 40 条（从旧到新）；
    - 长块截到 4000 字并标记、附件没有数据；
    - `limit` 给小、给大、给 0 的处理；
    - `total` 和 `omitted` 对。
  - 手机新增 5 个测试：
    - Mac 的回答变成消息和各种行，不认识的块跳过；
    - 没有可显示的几种原因、读不懂的回答；
    - store 打开、离开、晚到的回答、读失败时保留；
    - 快照触发重读、任务没了、取消配对后清掉；
    - 经假 Mac：打开任务读出消息（带 `limit` 和没显示的条数），推送 `task-changed` 后读出新消息，离开后不再读。
  - MacBook 上：
    - 宿主 `remote_headless` 测试 4 个都过，`cargo fmt --check` 过；
    - iOS 包 62 个测试都过，连接相关三套连跑 5 次都过；
    - iOS App 在模拟器上编过。
