# Agent Note: 整轮撤销（R2-1）：改了文件的轮次待验收，可接受、撤销、重做、撤回撤销

Status: implemented

## Problem

Agent 一轮里改了文件，用户只能自己去 git 里翻。改坏了没有一键退回，也看不出哪些轮次还没确认过。每一轮开始和结束时其实都有 git 快照，但只用来统计改动行数，既没有保存下来，也没有交给界面。

## Decision

- **轮次账本**（core `turn_ledger.rs`）：
  - 改了文件的轮次，记一条 `TurnRecord`，存在 `<data>/turns/<task>.json`。内容包括两份快照的 tree id、这一轮开始和结束时的 HEAD、改动文件和状态（待验收 / 已接受 / 已撤销）。
  - 两份快照写到私有引用 `refs/aeroric/turns/<task>/<turn>/{before,after}`，避免被 `git gc` 清掉。每个仓库最多保留最近 50 轮，超过 30 天的自动删除。
- **撤销计划**：
  - 对比两份快照，列出这一轮动过的文件。工作区里的内容如果还是这一轮留下的样子，就恢复；否则跳过，并写明“这一轮之后又改过”。
  - 下面几种情况整体拒绝，并说明原因：这一轮里 HEAD 变了（附提交号）、会话正在运行、快照已经被清理。
  - 撤回撤销用同一套逻辑，只是把两份快照的方向对调。
- **执行**：用 `git cat-file blob` 把内容写回工作区，按文件模式恢复可执行位和符号链接。这一轮新建的文件会被删除。全程不碰 index、HEAD 和分支。
- **告诉 Agent**：撤销成功后，`CheckpointSink::arm_note` 会在下一条消息前加一个“[Aeroric 状态提醒]”块，列出被恢复的文件，并提醒 Agent 不要假设那些改动还在。这个块的格式和现有状态提醒相同，R1-3b 的授权识别能正确跳过它。
- **RPC**：`turns.list` / `turns.plan` / `turns.apply` / `turns.accept`。
- **界面**：
  - **轮次对应**：按开始时间，把记录对应到对话记录里的轮次，前后误差 5 秒内算同一轮；对不上就不显示按钮，不去猜。
  - **轮标题上的标记和按钮**：
    - 待验收：显示“接受 / 撤销 / 重做”；
    - 已接受：显示“撤销”；
    - 已撤销：显示“撤回撤销”。
  - **会话运行中**：撤销类按钮置灰，悬停提示“这一轮结束后可撤销”。
  - **确认框**：列出要恢复的文件、要删除的文件和要跳过的文件，底部固定一句说明，告诉用户哪些改动撤不回去。
  - **重做**：先撤销，成功后把这一轮的原话放回输入框，由用户自己发送。
  - **待验收胶囊**：对话顶部显示“N 轮待验收”，点一下滚到最早一轮待验收。

- 目检补充：
  - **失败的那一轮被标成“已完成”**：Codex 失败时不会把错误写进会话记录，光看记录分不出这一轮失败了。现在任务状态为“失败”时，最后一轮的标题显示“失败”。
  - **同一条报错显示两次**：Codex 会把一次失败先报成错误，再在这一轮结束时报一次。紧挨着出现的相同报错，现在只显示一次。
  - **提示条名称不对**：`via-<agent>-login` 其实是 Agent 自己的本机登录经网关转发。提示条改为显示“本机登录经网关”，“去登录”给出 `codex login` 等命令，不再引导去设置里改 Agent 配置。

  - Agent 配置页“官方登录”一栏的 Claude 状态：如果 `~/.claude/settings.json` 的 env 里配了 `ANTHROPIC_API_KEY` 或 `ANTHROPIC_AUTH_TOKEN`，就显示“API Key”。和 `claude auth status` 一样，API Key 的优先级高于订阅登录。只检查这个键有没有，不读它的值。

## Alternatives considered

- **用 `git checkout <tree> -- <path>` 恢复**：会改写真实的 index，把用户暂存的东西弄乱。
- **用 `git stash` 或建分支保存快照**：会出现在用户的 git 界面里，还可能被推送出去。私有引用不会出现在分支和标签里。
- **把 turnId 放进对话记录来对应轮次**：要改 Codex、Claude 等各家的记录格式。按开始时间对应已经足够准，对不上时直接不显示，不会误操作。
- **在这一轮之后改过的文件上强行覆盖**：会丢掉用户或后续轮次的改动。

## Consequences

- 每个仓库最多留 50 轮快照，会多占一些磁盘空间，过期后自动清理。
- 被 `.gitignore` 忽略的文件，以及工作目录以外的改动（装依赖、改数据库等），撤销不了。确认框里写明了这一点。
- 只支持本机会话：远程会话的快照拿不到，就不会有记录，也就不显示按钮。

## Verification

- core 单测（临时仓库）：
  - 撤销后再撤回，文件恢复正确，index 不变；
  - 之后又改过的文件被跳过；
  - 这一轮有提交、会话正在运行时被拒绝；
  - 快照固定成引用，过期的被清理，不新增分支。
- 宿主端到端：一轮里改了文件，记录下来，撤销后文件复原，下一条消息前面带上提醒。
- Swift：轮次对应、不猜测、文字、撤销计划的解析。
