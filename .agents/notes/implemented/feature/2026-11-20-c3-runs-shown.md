# Agent Note: C3 第三步：整理记录可以取消、看每条去向、重建索引

Status: implemented

## Problem

[C3 第一步](2026-11-20-c3-runs-queued-running-canceled.md)和[第二步](2026-11-20-c3-retry-writes-uses-reindex.md)在宿主里做了：

- 排队、进行中、取消（`memory.runCancel`）；
- 逐条结果（`outcomes`）；
- 只补写失败的条目（`memory.runRetry`，App 的"重试"已改用它）；
- 重建索引（`memory.reindex`），以及 `memory.runs` 的 `indexHealthy`。

App 只认得新状态的文字，其余都看不到（`main@5a825327`）：

- 没有取消按钮；
- 进行中的行不会自己更新，要切换标签才刷新；
- 逐条结果、写入失败了几条，看不到；
- 索引坏了没有提示；
- "重建索引"那一行按普通整理显示，会写"0 线索 · 0 候选"，还会出现"重试"。

## Decision

全部在 `macos/AeroricKit/Sources/AeroricUI/Memory/`：

**排队中和进行中的行**：

- 进行中前面有转圈，状态徽标用强调色。
- 行尾有"取消"，悬停说明后果：
  - 排队中："不再整理这个会话；需要时可在会话菜单里手动整理"；
  - 进行中："在下一次写入前停下，已写入的保留"。
- 进行中的取消要等模型回复回来才生效。宿主回复仍是进行中时，徽标改为"正在取消"，不再显示取消按钮，直到记录里这一行结束。排队中的取消立即生效。
- 记录里有排队中或进行中的行时，页面每两秒重读一次 `memory.runs`，全部结束就停。只在"整理记录"标签显示时读，用 SwiftUI 的 `.task(id:)`，离开时自动取消。

**每条去向**：

- 有逐条结果的行，行尾多一个列表图标。悬停显示汇总，例如"新写入 3 · 并入已有 1 · 写入失败 1"。
- 点开是一个小弹出框，逐条写：类别（会话线索 / 经验 / 候选）、去向，以及原因（被规则拦下或写入失败的）。
- 写入或并入的，如果记忆页当前读到了那条记忆，就显示它的文字。
- 宿主不发原文，所以没写入的条目、不在当前范围的记忆，只显示类别和去向。弹出框底部写明这一点。

**重试**：只对抽取的行出现。整理（dream）和重建索引不出现，它们重新做一次即可。悬停写明：

- 有写入失败的："只补写没写进去的 N 条，不再调用模型"；
- 否则："重新整理这个会话"。

**重建索引**：

- `indexHealthy` 为假时，"整理记录"顶部一行警示："搜索索引不完整，部分记忆可能搜不到、Agent 也召回不到"，旁边"重建索引"。悬停说明不调用模型、不占次数。
- 重建后的行标题是"重建索引"，结果徽标是"索引已重建"，原因里写重写了几条。旧宿主没有这个字段，按完好处理，不显示提示。

## Alternatives considered

**"重建索引"做成整理设置里常驻的按钮。** 最强的理由是用户想重建时随时能点。没选：索引完好时重建没有用处，常驻按钮会让人以为需要定期点。宿主能判断是否完好，只在需要时出现更清楚。

**逐条去向直接展开在行下面。** 最强的理由是不用多点一下。没选：整理记录是一行一条的紧凑列表，一次抽取可能有十几条结果，全部展开会把列表撑得很长。弹出框只在用户想看时出现。

**逐条去向里用签名去查没写入的条目的原文。** 没选：签名就是为了让原文不可还原而设计的，App 也没有原文可查，只能如实写"没有写入的条目不保留原文"。

## Consequences

- **收益**：用户能看到正在进行和排队的整理、能取消，能逐条看到模型提议的东西最后去了哪里，索引坏了能看到也能修。C3 的方案条目全部完成。
- **局限**：
  - 每两秒的刷新只在整理记录标签打开时进行；侧栏和"需要我处理"不显示进行中的整理。
  - 逐条去向里的文字只来自记忆页当前读到的条目。切换范围后，其他范围的条目只显示类别和去向。
- **验证**：
  - Swift 测试新增 2 个（`MemoryTests`）：
    - 逐条结果、写入失败数、索引状态的解码（旧宿主缺字段时按完好处理）；汇总和单条的文字；哪些行能重试；重建索引行的标题和结果；
    - 取消进行中的行显示"正在取消"，记录里结束后清掉；排队中的取消不必等；有进行中的行时页面会继续刷新；重建索引调用宿主。
  - 界面待目检，记在路线文档 §8。
