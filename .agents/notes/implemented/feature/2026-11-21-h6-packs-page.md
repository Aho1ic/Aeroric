# Agent Note: H6 第三步：能力包页和接口，OMP 同名服务器按上游优先级让位

Status: implemented

## Problem

[H6 第一步](2026-11-21-h6-capability-packs-mcp.md)和[第二步](2026-11-21-h6-pack-skills-roles-hooks.md)做完了能力包的清单、信任和五类投影，但用户只能手写 `pack.json`，也看不到每个包在各家给了什么。方案 H6 还剩两件事：

1. 管理界面：加 MCP 服务器、装包、确认来源，用不上的那家写明原因（方案第 3、5 条的“用户会看到”）。
2. 第 4 条：OMP 会自己导入用户其他 Harness 的 MCP 配置，同名服务器可能出现两次，要写明哪个生效。

动手前（`main@1bdabd18`）核对的事实：

- 界面上的 `MCPSettingsView`、`ExtensionStore` 是 P8-01 留下的空壳：应用创建了 store，但没有页面用它，也没有接到核心层。
- Agent 配置页有“技能”等分页；“技能”页由 `BuiltinSkillBook` 加宿主的 `builtinSkills.*` 撑起来。
- OMP 的 MCP 来源（本地克隆，v18.13.1；`v18.12.0` 到现在这两个文件没变）：
  - `discovery/builtin.ts`：OMP 自己的 agent 目录 `mcp.json` 和项目 `.omp/mcp.json`，优先级 100；
  - `discovery/claude.ts`：80；
  - `codex.ts`、`claude-plugins.ts`：70；
  - `gemini.ts`：60；
  - `cursor.ts`、`windsurf.ts`：50；
  - 其余更低。

  去重在 `capability/index.ts`：按名字，或按“同一个连接”（命令、参数相同），先到先得，也就是优先级高的留下。项目级的排在用户级之前。

## Decision

**核心层的管理操作**（`extensions/pack_store.rs`），写入都是 0600 的 `pack.json`，因为服务器的环境变量里常有密钥：

- `overview`：每个包，加上它在六种去处的计划结果。六种去处是 Claude、Claude 走预设、Codex、Codex 走预设、OMP、DSH，用的就是启动时那个 `plan`，页面看到的和会话拿到的是同一个结论。环境变量里像密钥的值（键名含 key、token、secret、password）掩码后返回。
- `save_server`：在 Aeroric 里加的 MCP 服务器自成一个包。
  - id 等于服务器名，来源记为 `local`/`aeroric`，算已确认（用户自己写的）；
  - 保存时，值为掩码的环境变量保留原值；
  - 已有同名包、但不是这里加的，拒绝；
  - 改的时候保留它的启用状态。
- `import`：把一个含 `pack.json` 的文件夹复制进来。
  - 来源一律改成那个文件夹，只保留清单里的版本号；`confirmed` 置为 false；
  - 清单里自称内置或官方的，也不信；
  - 先复制到临时文件夹，完成后再改名换上，失败时不留半成品。
- `set_enabled`、`set_confirmed`。
- `remove`：交给调用方给的丢弃函数，宿主传的是“移到废纸篓”。

**宿主接口** `packs.list`、`packs.saveServer`、`packs.import`、`packs.setEnabled`、`packs.setConfirmed`、`packs.remove`，都是对上面的薄包装。`import` 只接受存在的绝对路径。

**页面**：Agent 配置 → 能力包（`CapabilityPacksPane`、`PackBook`）。

- 每个包一张卡片：名字、“来源已确认 / 待确认来源”、内容数量、来源。
- 卡片上的操作：
  - 确认来源：弹出确认，说明确认后会运行这台 Mac 上的命令；
  - 撤销确认：只对导入的包；
  - 编辑：只对自己加的服务器；
  - 删除：确认后移到废纸篓；
  - 启用开关。
- 展开后按去处列出每一项给了没有、为什么。
- 顶部两个按钮：“添加 MCP 服务器”（表单：名字、用途、命令、参数、每行一个 `KEY=VALUE`），“导入能力包文件夹…”。
- 读不了的文件夹单独列出原因。

**OMP 的同名服务器不另做去重。** 按上游的规则，Aeroric 写进受管目录的服务器优先级最高，会盖过从其他 Harness 导入的同名服务器（以及命令相同、名字不同的那个）；只有项目里 `.omp/mcp.json` 的同名服务器能盖过它。计划里 OMP 一栏的去处写明了这一点。

**P8-01 的 `MCPSettingsView`、`ExtensionStore` 留着没删。** 它们和这一步无关，删不删另议；能力包页不复用它们，因为它们的数据形状（按 Harness 分的技能列表、Hook 脚本）和能力包不一致。

## Alternatives considered

**导入时信任清单里写的来源（内置、官方市场加版本）。** 最强的理由是官方的包装上就能用。没选：清单是包自己写的，谁都可以自称官方。Aeroric 还没有市场，也没有签名，所以来源只能由导入这个动作决定。

**OMP 启动时读用户其他 Harness 的配置，主动删掉或改名同名的服务器。** 最强的理由是彻底消除重复。没选：

- 要读用户的 `~/.claude.json` 等文件，碰了不属于 Aeroric 的配置；
- OMP 自己的优先级已经让 Aeroric 的胜出，再做一遍只会和上游的规则打架。

**接着用 P8-01 的扩展页。** 没选：那几个视图从没接到核心层，数据形状也对不上。改它们，比单独做一页还要多改。

## Consequences

- **收益**：
  - 用户在一个地方加 MCP 服务器、装包、确认来源；
  - 每个包在每一家给了什么、为什么没给，一眼可见，和会话真正拿到的是同一个结论；
  - H6 方案的五条都有了落点。
- **局限**：
  - 只能添加本地命令（stdio）的服务器，HTTP 服务器没有接；
  - 导入只从本机文件夹，没有市场，也没有签名校验；
  - 包里的技能、角色、命令、事件处理不能在页面上编辑，要改源文件夹里的文件再重新导入，或者直接改 `<数据目录>/packs/<id>/`；
  - P8-01 的旧扩展视图仍在代码里，没有页面用；
  - 页面未目检，已记进路线图 §8 待目检清单；真实 Harness 里加的服务器能否用上，NOT RUN。
- **验证**（在 Mac mini 上跑）：
  - 核心层：
    - 加的服务器自成一个已确认的包：0600 文件里留着密钥，读出来是掩码，六处都可用；原样保存掩码保留密钥，保存不改启用状态；
    - 名字不合规、命令为空、同名的导入包，都拒绝；
    - 导入的包保留文件，来源改成文件夹；没确认时服务器不给、技能照给，确认后服务器可用；重复导入和没有 `pack.json` 的文件夹被拒绝，不留临时文件夹；
    - 删除走丢弃函数，不存在或名字不合规的 id 报错。
  - Swift：
    - `packs.list` 的解码、来源和数量的文字、每处“n/m 项可用”；
    - 表单按空格拆参数、按行拆环境变量，编辑时掩码原样发回；
    - 改动之后重新读取，失败时写明哪一步失败。
