# Agent Note: 能力表与登录失效（R1-3a）：选择器按每族实际能力灰掉或说明，鉴权被拒标记登录失效

Status: implemented

## Problem

原生会话（Codex、Claude、omp）没有一张说明"这一族能做什么"的表，导致：

- 斜杠菜单里"仅 Codex"、`/review` 是否可用，都是界面里写死的判断；
- 权限选择器对三族显示同样三档，看不出这档权限是沙盒强制、Agent 自己把关，还是只靠提示。

另外，登录失效没有专门的状态：鉴权被拒只表现为一轮 Failed 的错误文字，再加上 R1-2 中 blocked 的投递。用户只能对着一串失败去猜原因。

路线复核 Q-S11 决定基于能力表补全、不新增页面；本轮 Q1–Q7 的细化见任务 `11-02-truth-capabilities/design.md`。

## Decision

- **能力表**：
  - core 新增 `sessions/live/capabilities.rs`：`support(family, place, feature)` 以 `match` 穷举，新增族时编译器会要求补齐。
  - 状态有四种：支持、不支持（写原因）、降级（写差异）、未知（标"未确认"）。
  - 事实来自各驱动：Codex 有 OS 沙盒；Claude 和 omp 由自己把关；omp 启动时固定权限；Claude 的插话会变成下一轮；`/review` 只有 Codex 有。远程环境下的委派和审查先标"未知"。
  - 宿主提供 `session.capabilities`。
- **界面**：
  - 权限选项右侧写明谁负责强制执行，不支持的选项灰掉；
  - 斜杠菜单和 `/review` 的拦截都改为读表；
  - Claude 会话的"立即插话"带上降级说明。
  - 宿主没有这张表时，保持旧的答案。
- **登录失效**：
  - core 新增 `sessions/live/login.rs`，放在 sink 链中投递队列的下一层，所以既能看到驱动的 Failed，也能看到队列的失败投递。
  - **身份**：Agent × 位置 × 来源，由宿主根据任务记录解析。
  - **标记**：鉴权类原因出现时标记，判断规则 `auth_failure` 从 `user_fixable` 中拆出。
  - **保存**：标记写入 `login-state.json`，重启后仍在。
  - **清除**：同一身份下任意一轮 Completed 就清除，同时重试该身份被 blocked 的投递。只认实时更新，回放历史不会触发清除。
  - 宿主提供 `login.state {taskId?}`。
- **"去登录"**：会话页和新建页在输入框上方显示提示条，点开是一个面板：
  - 自带登录：显示要运行的命令，可复制，也可打开"终端"。
  - Agent 配置：提示去设置里检查密钥，并可直接打开设置。
  - Aeroric 不接触凭据。

- 目检补充（2026-11-04）：
  - Claude 遇到 401/403 会自己重试约 3 分钟。现在映射 `system/api_retry`：登录被拒时立刻中断这一轮，并按“登录被拒”记为失败；其他原因的重试只提示一次。
  - 提示条显示 Agent 配置自己的名字，不再只显示 Claude、Codex、omp 这样的族名。
  - 中断一轮后，Claude 会在会话记录里写一行 user 消息 `[Request interrupted by user]`。读历史和统计轮数时都跳过这一行，不再显示成用户气泡，也不再多算一轮。

## Alternatives considered

- **扩充旧的 `AgentCapabilities`**：它是布尔值，表达不了降级和未知，也没有"位置"这个维度。旧表留给 adapter 用。
- **启动时探测能力**：会拖慢启动，而且探测失败本身也有歧义。改用静态表，再用实测结果修正。
- **在 App 内开终端标签并预填登录命令**：App 的终端绑定在任务的 PTY 上，没有独立的 shell 标签。改为面板给出命令，再配合打开系统"终端"。原设计里的这一项因此调整。
- **登录失效时自动打开登录页**：只给入口，凭据由用户自己输入。

## Consequences

- 新增一族 Agent 时必须填表，否则编译不过。
- 鉴权规则可能误判，比如错误文字里恰好带 "403"。只看 Failed 轮和启动失败的原因；即使误标，下一轮跑成后也会自动撤销。
- 新建页只对本机的自带登录或配置显示提示；远程身份的提示只出现在会话页。

## Verification

- core：能力表每族每项都有结论，各驱动的事实有断言；登录标记会持久化，Completed 时清除，启动失败也会标记。
- 宿主 e2e：一轮返回 401 后标记 Codex（本机），并给出 `codex login`；再跑成一轮后清除。`session.capabilities` 返回 Claude 不支持 review。
- Swift：斜杠菜单和权限选择器读表；无表时回退到旧答案；登录列表能正确解码。
