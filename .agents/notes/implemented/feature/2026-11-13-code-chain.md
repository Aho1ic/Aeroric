# Agent Note: 代码版本链：每轮改动按"分支 × 文件 × 定义"记下来，挂在召回的记忆下面

Status: implemented

## Problem

路线图 J6 和 §6.1 的记忆分层里有一层"代码版本链"（来源 MEM-HY）：

- 不调用模型；
- 按"分支 × 文件 × 函数块"记下每一版的真实 diff，后来被回退的版本也保留；
- 本身不参与检索，像装饰器一样挂在检索到的记忆下面。

Q-M3 把分支放进这一层，留到了 B6。

B5 的记忆只有文字：一条经验说"SSH 超时改用 ConnectTimeout"，Agent 召回时看不到当时到底改了哪个文件的哪个函数，也不知道那次改动后来有没有被撤销。

R2 的[轮次账本](2026-11-04-turn-undo.md)已经在每轮前后各存一份快照，撤销过的轮次也留着记录，但只保留 50 轮、30 天，而且是按会话存的，召回记忆时用不上。

用户 2026-11-13 说"全部按推荐"，定了 6 条：

1. 改动从轮次账本取（Aeroric 亲眼看到的改动），不扫 git 提交历史。
2. 用 `git diff -U0` 拆成块，每块归到它所在的定义；分支取那一轮结束时的 HEAD 名字。
3. 存在 memory.db 的新表里，每块一行，带最多 2KB 的 diff 原文；保留 180 天，每个项目最多 5000 块。
4. `memory_recall` 命中一条带会话来源的记忆时，下面附最多 3 行"改动"；不提供单独的检索工具。记忆页上能看到同一份列表。
5. 只记开启了记忆的项目。
6. 项目打开记忆时、宿主启动时，从账本里现有的轮次补建。

## Decision

**一轮怎么拆成块**（core `memory/chain.rs` 的 `changes`）

- 取账本记录里这一轮的前后两棵快照树，跑 `git diff -U0 --no-renames --no-color --no-ext-diff before after`，逐文件解析：
  - 被删掉的文件从删除前的树里找定义；
  - 二进制文件只记一个没有定义名的块。
- 每个改动段的起始行（删除的文件用旧行号）归到包住它的最内层定义，同一文件同一定义的段合成一块，累计增删行数、拼接改动原文。
- 原文截到 2000 字（`CHAIN_DIFF_CHARS`），每轮最多 200 块。
- 块上记下项目、分支、文件、定义、会话、轮次、这一轮的结束时间，以及这一轮当时的状态（待验收 / 已接受 / 已撤销）。

**定义从哪来**（`knowledge/code_index.rs` 的 `file_definitions`，新增）

- 原有的 `file_symbols` 是 Wiki 和参考代码库用的公开表面：只收顶层的 `pub` 定义。归类改动要的是"改在哪个函数里"，所以另写了一个遍历：
  - 私有的、嵌套的都收；
  - 嵌在别的定义里的，名字带上外层前缀：`impl TurnLedger` 里的 `planned` 叫 `TurnLedger::planned`，Python 的类方法叫 `Trainer::step`；
  - 每个定义带起止行，归类时取包住改动行的最内层那个。
- 支持 Rust、Python、Swift、TypeScript/TSX，与结构索引相同；其他语言的改动只记到文件。

**分支**（`record_turn`）

只在这一轮记录的结束提交 `head_after` 仍是当前 HEAD 时，才用当前分支名；补建旧轮次时，HEAD 早已移动，分支就留空。分离 HEAD 时也留空。

**存储**（memory.db 的 `chain` 表）

- 记一轮时，先删掉这一轮已有的块再写，所以重复记录不会重复。
- 写完后清理这个项目：超过 180 天的删掉（`CHAIN_KEEP_MS`），只保留最新的 5000 块（`CHAIN_KEEP_PER_PROJECT`）。
- 原文在这里另存一份，账本清理快照之后，版本链仍然在。

**何时记录**

- **每轮结束**：在 executor 的轮次钩子里，先通知委派（delegations），再记版本链，最后通知审查回环（reviews）。条件是这一轮改了文件、`TurnChangeTracker::project_of` 能查到项目、项目开启了记忆。钩子本来就在跟踪线程上执行，git 操作不会挡住会话。
- **补建**：
  - 宿主启动时，在后台把每个开启了记忆的项目补一遍；
  - `memory.project` 把一个项目从关切到开时，也补一遍；
  - 只补版本链里还没有的轮次（`has_changes`）。

**怎么挂到记忆上**

- `Memory::changes_for(item, n)`：取这条记忆证据里出现的会话，返回这些会话最新的 n 块。用户手写的记忆没有会话来源，所以没有版本链。
- `memory_recall`（宿主 `context_recall`）：每条命中的记忆下面最多附 3 行（`CHAIN_PER_ITEM`），例如 `  改动：src/ssh.rs::connect · main · +3 −1 · 已撤销`。只要附了，就在末尾说明："改动"是来源会话改过的代码块，从新到旧，已撤销的也列出，说的是当时，不代表现在的代码。
- 状态在读取时刷新：账本还有这一轮，就用账本的当前状态（接受或撤销之后会变）；账本已经清理掉，就用记下时的状态。
- `memory.chain {id}` 返回一条记忆的最多 20 块。
- 记忆页：有会话来源的记忆，⋯ 菜单里多一项"相关改动…"，弹窗里逐块列出"文件::定义 · 分支 · +a −d · 状态 · 时间"。点一块展开看 diff 原文，箭头打开改动它的会话。

## Alternatives considered

- **扫 git 提交历史**：不依赖 Aeroric 看到过这一轮，Aeroric 之外的提交也能算进去。没有采用：提交里不知道是哪个会话改的，没法和记忆的证据对上；没提交的改动、被撤销的版本也看不到，而这正是 J6 要保留的。
- **只引用账本的快照，不另存原文**：省空间。没有采用：账本每个仓库只留 50 轮、30 天，记忆要活得更久；快照清理之后，版本链就断了。
- **用原有的 `file_symbols`**：不用新写遍历。没有采用：它只收顶层的 `pub` 定义，私有函数和 impl 里的方法里的改动都会被归到文件开头附近的某个公开类型下，"函数块"就名不副实了。
- **按"最近一个在上方的定义"归类**：不需要结束行。没有采用：一个 impl 结束后、下一个定义之前的改动，会被算到 impl 的最后一个方法里；带起止行取最内层更准。
- **单独的 `code_history` 检索工具**：Agent 可以按文件查改动史。没有采用（第 4 题）：路线图定的是"装饰器、不参与检索"；按文件查历史，Agent 自己用 git 就能做到。

## Consequences

- 收益：
  - Agent 召回一条经验或会话线索时，同时看到当时改的是哪个文件的哪个函数、改了多少、后来有没有被撤销；
  - 全程不调用模型：一轮一次 `git diff`，每个改动的文件一次 `git show`；
  - 原文另存，账本的快照清理之后，版本链照样在。
- 代价：
  - 只有 Aeroric 记录过的轮次才有，Aeroric 之外的改动不在里面；关闭记忆期间的轮次，要等再打开时才补，前提是账本里的快照还在；
  - 归类按行号近似：改动段只看起始行，跨两个函数的段算到前一个；
  - 补建的旧轮次没有分支名；
  - 每条召回结果最多多出 3 行，命中多时，召回文字会变长；
  - 同一会话的块挂在这个会话产出的每条记忆下面，不区分这条记忆具体对应哪一块。
- 待目检（已记进路线图的待目检清单）：
  - 记忆 ⋯ 菜单的"相关改动…"、弹窗里的块和 diff 展开、打开会话；
  - 真实会话里 `memory_recall` 返回的"改动"行。

## Testing

- core `memory::chain` 3 个测试：
  - 两处改动分别归到私有函数 `alpha` 和方法 `Ledger::beta`，增删行数和原文正确，撤销过的轮次保留状态，分支取到 `main`；
  - diff 解析认得删除的文件和二进制文件；最内层定义的取法，以及在所有定义之前、之后的情况；
  - 一条来自会话的记忆按时间从新到旧列出它的块，重复记录一轮不会重复，180 天前的被清理，没有会话来源的记忆没有版本链。
- core `knowledge` 新测试 `file_definitions_name_nested_and_private_ones_with_their_span`：Python 类与方法、私有函数，TypeScript 类方法与箭头函数，Swift 结构体与方法，以及不支持的语言。
- 宿主集成测试 `a_memory_without_a_session_has_no_code_chain`：手写的记忆没有版本链，未知的记忆返回 NOT_FOUND。
- Swift `MemoryTests`：改动块的解码、"文件::定义"和详情文字、哪些记忆有版本链、记忆页取一条记忆的改动。
