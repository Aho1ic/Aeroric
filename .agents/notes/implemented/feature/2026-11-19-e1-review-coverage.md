# Agent Note: E1 审查覆盖清单：每个改动文件都有结局

Status: implemented

## Problem

[1118 调研](../../proposed/architecture/2026-11-19-new-addition-1118-research.md) 的 E1。[审查循环](2026-10-30-review-loop.md) 的审查者说"通过"就算通过，没人知道它看了哪些文件：

- 改动超过 6 万字时，diff 不贴进提示词，只给文件名，让审查者自己用 `git diff` 去看。它要是一个都没打开就判"通过"，卡片照样显示"通过"。
- OCR 把这叫作"大改动时偷工减料"，并且遇到过真实事故（OCR #1454）：零个文件被选中却以成功退出，"坏掉的版本和'审过没问题'分不出来"。
- 改动里的 `.env`、私钥原样贴进了审查者的提示词，提示词里那句"完整改动也可以用 `git diff` 查看"也会把它们带出来。

## Decision

做法学自 OCR 的运行清单（`session/manifest.go`）和委托模式"覆盖是强制的"。

- **范围由宿主定**（`review/coverage.rs` 的 `plan`）：
  - 这一轮改动的文件，除下面两类外都要审；
  - 排除的文件逐个写明原因：
    - 可能含凭据的：`.env` 及 `.env.*`（不含 `.example`、`.sample`、`.template`、`.dist`），以及私钥、`.pem`、`.key`、`.p12`、`.pfx`、`.keystore`、`.jks`、`.netrc`、`.pgpass`、`.git-credentials`；
    - 二进制文件。
  - 贴给审查者的 diff 用 `:(top,exclude,literal)` 去掉这些文件。门禁标记也只看剩下的 diff。
- **提示词**：
  - 列出"要审查的文件"，以及"不在审查范围、不要打开的文件"和原因；
  - 原来"完整改动也可以用 `git diff` 查看"改成按单个文件查看；
  - 要求输出 `files`：逐个文件写 `reviewed`，或 `skipped` 加原因，并且"不要只审一部分就给结论"。
- **每个文件的结局**（`coverage::judge`），只能是下面五种之一：
  - `reviewed`：审查者说审了；
  - `skipped`：审查者说跳过了，带原因，没写原因就记"审查者没有写原因"；
  - `seen`：审查者没交代，但文件在提示词里（diff 贴进去了），或者审查者的工具调用里出现过这个路径（从 `ToolCall` 的标题和输入里查）；
  - `missed`：没交代，也没看到过；
  - `excluded`：宿主排除的。
- **整轮的终态只由文件推出，不看结论**：
  - `complete`：范围内每个文件都审了或看过；
  - `partial`：有的跳过或没看；
  - `unreviewed`：一个都没审、没看；
  - `empty`：没有文件在范围内。
- **对卡片的影响**：
  - 审查者判了通过、但终态是 `unreviewed` 时，不算通过：卡片转为"需要你处理"，原因写"审查者没有看任何改动的文件，这一轮不能算通过"。
  - 其余情况结论照旧，覆盖情况随卡片一起显示。
- **App**：
  - 审查卡总评下面一行："审查覆盖 7/9 个文件（结果可能不完整）"、"没有审查：…一个都没看"或"改动的文件都不在审查范围"；
  - 点开逐个文件列出结局；
  - 进度页的一行摘要，在部分覆盖或没有审查时加"覆盖 7/9"。

## Alternatives considered

**只信审查者自报的 `files`，没交代的一律算没审。** 最强的理由是口径最严。没选：diff 贴进提示词时，审查者确实看到了每个文件，只是没逐个交代；一律算没审，会让每次普通审查都显示"不完整"。改为单列 `seen`（"看过，审查者没有逐个交代"），既不冒充"已审"，也不冤枉。

**部分覆盖时也不算通过。** 最强的理由是更保守。没选：审查者有理由跳过生成代码这类文件，每次都把用户拉进来，代价太高。部分覆盖时如实显示"结果可能不完整"，由用户判断；只有一个文件都没看时才拦下。

**按工具调用记录逐行判断审查者"真的审过"。** 没选：看过一个文件不等于审过它，工具调用只能证明"打开过"，所以只用它来判断 `seen`。

## Consequences

- **收益**：
  - 一个文件都没看的"通过"不会再出现；
  - 审查卡写明覆盖了多少、哪些没看；
  - 凭据文件不再发给审查者。
- **代价**：
  - 审查者的输出多一个 `files` 字段；
  - 每个审查者回合多记一份工具调用文本，最多 2000 条，回合结束时清掉。
- **局限**：
  - 回合账本最多记 200 个文件（`turn_changes::MAX_FILES`），超出的部分不在范围里，也不会显示为"没看"；
  - 工具调用里出现路径不等于读过内容，例如 `ls` 也算。
- **验证**：
  - `coverage.rs` 新增 3 个测试：
    - 凭据和二进制排除、模板保留；
    - 五种结局和四种终态；
    - 只有排除文件时终态为 `empty`，路径按目录边界匹配。
  - `review/tests.rs` 新增 4 个测试：
    - `a_pass_that_rests_on_no_file_is_not_a_pass`：判通过、没交代、没打开、没贴 diff，卡片转为需要你处理；
    - `a_file_the_reviewer_opened_counts_as_seen`：打开过的文件是 `seen`，没打开的是 `missed`，终态为 `partial`；
    - `a_secret_is_left_out_of_the_review_and_the_files_are_accounted_for`：提示词把 `.env` 列在"不要打开"一栏，审查者自报的文件是 `reviewed`；
    - `the_inlined_diff_never_carries_a_secret`：真实 git 仓库里，贴出的 diff 不含 `.env` 的内容。
  - 原有的 `PASS` 回复改为带 `files`。
  - Swift 新增 `testTheCardSaysWhichFilesTheReviewerAccountedFor`。
  - 界面待目检，记在路线文档 §8。
