# Agent Note: C2 第二步：删除或归档的经验立刻离开 Wiki，遗忘的连历史一起清

Status: implemented

## Problem

[C2 第一步](2026-11-20-c2-withdrawal-reaches-memory-store.md)让记忆库里的派生数据跟着删除和归档更新，并列出了 19 处会引用或复制记忆内容的地方。其中三处在记忆库之外，还没处理：

- **第 15 项 Wiki 页面**：Wiki 的"操作手册"页由经验编译而来，每条经验一段，段落键是 `memory:<id>`，标题就是经验的原文。经验被删除或归档后，这段要等下一次编译才会消失。编译只在用户点"编译"或后台巡检时进行。在那之前，Wiki 搜索、页面、`pages/*.md` 文件，以及 Agent 的 `context.wikiRead` / `context.wikiSearch` 都还读得到。
- **第 16 项修订历史**：每次保存都追加一份整页 Markdown。即使重新编译过，旧修订里也一直留着原文。待核对事项里，"来源有更新"那类还把旧段落原文存在 `suggestion` 里，标题也写在说明文字里。
- **第 18 项导出文件**：用户导出到项目目录的 Wiki 文件。

方案第 5 条还要求：删除时传播没成功的地方，进"需要我处理"。

## Decision

**Wiki 立即撤回段落**（`Wikis::withdraw_memory`，`core/crates/aeroric-core/src/knowledge/mod.rs`）：

- 删除或归档一条经验后，宿主马上对相关项目的 Wiki 调用它：
  - 项目经验只处理所在项目；
  - 全局经验处理所有项目。
  
  不重新编译整个 Wiki。编译要扫描项目代码，较慢，还会顺带带进与删除无关的变化。
- 用户没改过的段落直接去掉，存成一个新修订，原因是新增的 `withdraw`。页面、全文索引和 Markdown 文件由同一次保存一起更新。
- 用户改过的段落保留（那是用户自己的字），去掉来源，开一条"来源已删除"的待核对：
  - 归档时写"「标题」依据的经验已归档，你改过的这段先保留，请核对。"
  - 永久遗忘时不复述标题，写"这段依据的记忆已被永久遗忘……"；段落标题本身就是被遗忘的原文，所以改成"（来源记忆已遗忘）"。

**永久遗忘时清掉历史**：

- 遍历这个项目所有页面的所有修订，包括已被删除页面的修订，去掉标题是已遗忘原文的 `## ` 小节，其余内容原样保留。
- 判断标题是不是已遗忘的原文，用的是记忆库的遗忘签名（`Memory::is_forgotten`）。这样能认出同一条经验以前各个版本的标题，Wiki 一侧也不用另存原文。
- 涉及这些段落的待核对，清空 `suggestion`，说明文字换成通用的那句。
- 归档不清历史：归档的经验还能恢复，属于用户自己的知识。

**失败重试**（宿主 `memory.rs` 的 `reach_wiki` / `run_backlog`）：

- 某个项目的 Wiki 没能改成功时，`withdrawal.failed` 写"项目「名称」的 Wiki 没能更新：原因"。
- 同时在记忆库的键值表里记一条待办，只有项目 id、记忆 id、是否遗忘和原因，不存原文。
- 每次删除或归档、每次读"需要我处理"（`memory.attention`）都会重试。仍然失败的在 `memory.attention` 的 `wikiBacklog` 里返回，第三步在 App 里显示。
- 重试时如果页面已经保存、但 Markdown 文件没写成，会对比后重写文件（`Store::reproject`）。这是写测试时发现的：保存是先写数据库再写文件，只看段落还在不在，会漏掉写了一半的情况。

**返回结果**：`withdrawal` 加 `wikiPages`（改了几页）、`wikiFlagged`（保留了几段用户改过的），以及 `failed`。

**导出文件（第 18 项）不动**：那是用户放进项目目录的文件，可能已经提交进仓库。Aeroric 不替用户改，这一点写在这里，第三步在界面上说明。

## Alternatives considered

**删除时直接调用现有的编译。** 最强的理由是编译本来就会去掉来源消失的段落、给用户改过的段落开待核对，不用写新逻辑。没选，原因有两条：

- 编译要扫描项目代码。对一个大仓库，删一条记忆要等好几秒。
- 编译会把笔记、代码这段时间的其他变化也一起带进这次修订，修订原因就说不清了。

现在的做法只碰 `memory:<id>` 这几段，结果与之后的编译一致。下次编译时，经验条数变了，编译会照常进行。

**修订历史保持只追加，被遗忘的内容只是在显示时过滤掉。** 最强的理由是历史不被改写，可以审计。没选：永久遗忘的承诺是原文不再留存。显示时过滤，数据库和导出里仍然有原文，搜索和恢复旧版也能把它找回来。

**待办里存被遗忘的标题，重试时用来清历史。** 最强的理由是不依赖遗忘签名表。没选：那就等于为了删除而把原文另存一份。遗忘签名本来就永久保存，用它判断，不需要原文。

## Consequences

- **收益**：
  - 永久遗忘一条经验后，Wiki 的页面、搜索、Markdown 文件、修订历史、待核对，以及 Agent 的 Wiki 工具，都读不到它了，不用等重新编译；
  - 归档时页面立即更新，历史保留，可以恢复；
  - 改不成功的不会悄悄留着，会写明原因并自动重试。
- **代价**：
  - 修订历史不再是严格只追加，永久遗忘会改写旧修订；
  - 每次删除，所有涉及项目的 Wiki 都要打开、遍历一遍修订；
  - 全局经验涉及所有项目，会为还没有 Wiki 的项目建一个空库。
- **局限**：
  - 已采纳的技能文件里的原文仍在（按方案由用户决定），第三步给出入口；
  - 导出到项目目录的文件不动；
  - 用户改过的段落，正文是用户的字，予以保留。
- **验证**：
  - Wiki 核心层新增 3 个测试（`knowledge/withdraw_tests.rs`）：
    - 归档：段落立即离开页面、搜索和 Markdown 文件，修订原因是 `withdraw`，历史保留，另一条经验的段落不动，重复撤回不再产生修订；
    - 遗忘：页面、搜索、文件、历史、待核对都找不到，其余内容在每份修订里保留；
    - 用户改过的段落保留并开待核对；遗忘时标题换掉，待核对不复述原文。
  - 宿主集成测试新增 2 个：
    - 一条经验先能被记忆列表、召回、Wiki 搜索、Wiki 页面、Agent 读 Wiki 找到；永久遗忘后，记忆列表与搜索、召回、需要我处理、技能列表、Wiki 的页面 / 搜索 / 修订 / 待核对、Agent 的 Wiki 搜索和读取，全都找不到那个词。
    - 让 Markdown 文件写不进去：遗忘结果里写明哪个项目的 Wiki 没能更新，待办只有 id；恢复可写后，读一次"需要我处理"就重试成功，文件和历史里都没有了。
