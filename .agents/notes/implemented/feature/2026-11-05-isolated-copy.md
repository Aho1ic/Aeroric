# Agent Note: 独立副本、带回原目录、冲突转新一轮（R2-3b）

Status: implemented

## Problem

到 R2-3a 为止，会话都直接写在项目目录里。想放手让 Agent 试一条思路、或让委派的子会话写代码时，它的半成品会立刻出现在用户正在用的目录里；两个写者也不能同时写一个目录。路线文档 Q-R3 定了：普通会话新建时可选独立副本，委派的可写子会话默认用独立副本，改动由用户带回。

## Decision

- core `sessions/live/isolated_copy.rs`：
  - **创建**：第一次创建前，往仓库的 `.git/info/exclude` 加一行 `/.aeroric/`。然后执行 `git worktree add --detach <repo>/.aeroric/worktrees/<task> HEAD`，不新建分支。原目录的快照树（含未提交的改动和新文件）作为起点：用 `git diff --binary HEAD <起点>` 生成补丁，在副本里 `git apply`。起点钉在 `refs/aeroric/copies/<task>/base`，记录写在 `<data>/copies/<task>.json`。被 git 忽略的文件默认不进副本；2026-11-09 起，既被忽略、又列在原目录 `.worktreeinclude`（gitignore 语法，和 Claude Code 桌面版同名）里的，会复制过去：APFS 上是 `clonefile` 克隆，保留修改时间（构建工具不会因此重编译），链接照旧是链接；复制不了的跳过并记日志（参照 worktrunk 的 copy-ignored；只认白名单，不复制全部 ignored 文件，免得带出 `.env`）。启动时任务记录里的 `worktreePath` 指向副本，现有的启动逻辑不用改。
  - **带回**：`ChangeScope::Origin` 比较的是“起点”和“副本现在”。在这个范围下接受一段 = 把这一段补丁正向 `git apply` 到原目录，只改工作区，不碰 index。成功标 `Applied`，套不上标 `Conflict`。丢弃 = 在副本里反向应用这一段（沿用 R2-2 的拒绝）。还有一个“全部带回”。
  - **冲突转新一轮**：先列出原目录在起点之后改过的每个文件，逐个处理：副本没动过的，直接用原目录的版本；原目录没动过的，跳过；两边都改了的，用 `git merge-file` 合并，冲突处留下标记。处理完把起点前移到原目录当前的快照，再返回预填文字。客户端把这段文字放进这个会话的输入框，不自动发送。
  - **清理**：删除用 `worktree remove --force`，同时删掉对应的 ref 和记录。删之前先停掉工作目录在副本里的进程（2026-11-08 E 批，参照 worktrunk 的 `--reap`）：先 TERM，3 秒后仍在的 KILL，`copies.remove` 回 `stopped` 个数，界面删完提示一次。宿主自己、它的父进程和它直接起的子进程不碰：会话的 Agent 由驱动结束，从背后杀掉会被当成异常退出；Agent 的 shell 再起的程序（开发服务器）照停。全部处理完（没有待带回、也没有冲突）满 30 天的副本，在宿主启动时清理。
- 宿主：
  - `task.run` 新增 `isolated`。只有设了它才写进指纹（追加一个字节 2，和 `clarify` 的 1 区分开），回执里也只在这时多报一项 `isolated`，所以旧的提交照样能匹配。远程项目、不是 git 仓库、还没有任何提交的仓库，都在产生任何副作用之前就拒绝。
  - 新增 RPC：`changes.bringAll`、`changes.resolveConflicts`、`copies.get`、`copies.remove`。
  - 委派新增 `Workspace::Copy`。内置的两个可写角色（写代码、测试）默认改用它，“共享目录”仍然可以手动选。`start_child` 会在 `mark` 之后为子会话建副本。
- 界面：
  - 新建会话页：项目选择右边加一个“独立副本”胶囊开关，默认关；远程项目下置灰。
  - 会话左上角：显示“独立副本”胶囊，悬停显示路径。
  - 侧栏：Harness 图标右下角叠一个小的副本标记。
  - “改动”页：对比范围单独占一行，铺满整宽。副本会话多一个“相对原目录”，里面有：
    - “副本里还有 N 处没带回”和“全部带回”；
    - 每一段的“带回 / 丢弃”；
    - 冲突段上的“交给 Agent 处理”。
  - 委派卡片上显示“N 处在副本里 · 去带回”，点了直接打开子会话的“相对原目录”。
  - 归档时还有没带回的段，会问是保留副本、删掉副本还是取消；删除会话时，会提示副本会一起删掉。这一问放在 `AppServices.toggleArchived` 里，侧栏、顶栏 ⋯、任务看板三个归档入口都经过它（2026-11-09 复测发现顶栏和看板原先绕过了这一问）。

## Alternatives considered

- **给副本建一个分支（`aeroric-task/<id>`）**：项目规定开发 Aeroric 时不新建分支，而且分支要合并、要提交，不符合“带回成为未提交改动”的决定。
- **副本只取 HEAD 的内容**：Agent 看到的就和用户看到的不一样，带回时还会把用户没提交的改动当成 Agent 的改动反向覆盖掉。
- **冲突时只预填文字，不先合并**：Agent 得自己去原目录比较，起点也不会动；它改完之后，“相对原目录”里还会混着原目录那边的改动。由 Aeroric 先做三方合并、前移起点，Agent 只需要清理冲突标记，之后看到的只剩它自己的改动。
- **把副本信息写进任务记录**：除了 `worktreePath`，其余字段只有副本模块会用。单独存放，任务记录的格式就不用改。
- **改用户的 `.gitignore`**：那是用户自己的文件；`info/exclude` 只在本地生效。

## Consequences

- 副本放在项目目录里面。虽然 git 已经忽略它，编辑器的全局搜索之类的工具仍可能扫到。
- 起点前移后，已经带回的段和原目录内容一样，不再出现在 diff 里，这是预期的。
- 二进制文件的改动不能按段带回，只能丢弃，或者交给 Agent 处理。
- 归档时选“保留副本”，副本会一直留着，直到所有改动处理完后满 30 天才清理。
- 目检时顺带修了：
  - 冲突段的“交给 Agent 处理”原来和“冲突”标记挤在同一行，把窄面板撑出了左边界；现在单独占一行，顶部那行放不下时也会折成两行。
  - 第一次目检时，副本会话的第一条消息报了“transport closed”，同一会话再发一条就好了，重跑时也没再出现。当时 Agent 的 stderr 被丢弃，查不到原因，所以现在把它的前 40 行写进宿主日志（日志本来就会脱敏），下次再出现就能看到原因。

## Verification

- core 单测（临时仓库）：
  - 副本里带着未提交的改动和新文件，原目录的 `git status` 看不到 `.aeroric`；`exclude` 不会重复写入；删除后目录和记录都清掉了；
  - 带回一段只改原目录的工作区，不碰 index，`clearedMs` 记下了；
  - 原目录改了同一处，就标成冲突；合并后冲突标记在、用户的改动并进来了；起点前移后，diff 只剩 Agent 的改动，再带回成功；
  - 还没有提交的仓库被拒绝。
- 宿主端到端：`copies.get`；`changes.diff` 的 origin 范围；`bringAll` 一段成功、一段冲突；`resolveConflicts` 返回的预填文字和合并结果；`copies.remove`。
- Swift：副本信息的解码、带回相关的文字、指纹在设置 `isolated` 时追加的那个字节，以及 JSON 字段。
