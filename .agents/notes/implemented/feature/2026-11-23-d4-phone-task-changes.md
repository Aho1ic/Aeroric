# Agent Note: D4 后续：手机任务页看这个任务的改动

Status: implemented

## Problem

手机的“文件与 Git”页按项目看改动（见 [那一步的笔记](2026-11-23-d4-phone-files-and-git.md)），任务页只有待审批和会话。用户想知道“这个任务改了什么”，只能去项目页看整个项目的改动，而且分不出哪些是这个任务改的。

动手前（`main@c0db1a33`）核对的事实：
- **宿主能按任务读：** `git.changes`、`git.diff` 带 `taskId` 时，任务有自己的副本（`worktreePath`）就读那里，否则读项目目录。
- **回答里没有说读的是哪里：** 一个直接在项目目录里改的任务，拿到的是整个项目的未提交改动，里面可能有别的任务或用户自己的。手机如果照样写成“这个任务的改动”，就是说假话。

## Decision

**宿主：`git.changes` 多回 `scope`。**
- `"worktree"` 表示读的是任务自己的副本，`"project"` 表示读的是项目目录。
- 选哪棵树抽成纯函数 `tree_to_read`，`git.changes` 和 `git.diff` 共用：
  - 任务的 `worktreePath` 不为空，就读它；
  - 否则读项目。

**手机：任务页加“改动”一节。**
- **读取请求：** `CompanionRead.changes`、`.diff` 可以带 `taskId`。
- **页面状态：** store 为打开着的任务单独记一份 `CompanionTaskChanges`，包括 `scope`、改动、打开的差异。和“文件与 Git”页的状态分开，答案也按 `taskId` 分流：项目的回答不会落到任务上，反过来也一样。
- **怎么写：**
  - `worktree`：写“这个任务在自己的副本里改，下面是它的改动”；
  - `project`：写“这个任务直接在项目目录里改，下面是项目里全部没提交的改动，可能有别的任务或你自己的”。
- **看差异：** 每行写状态、路径、是否已暂存，点开在弹出页看差异，差异也按任务的树读。
- **何时读：** 打开任务就读。之后每次快照触发的重读（任务页的会话本来就会重读）也会重读改动和打开着的差异，已显示的在读取期间保留。读失败时，已显示的也保留。
- **离开时：** 离开任务、任务在快照里没了、取消配对时清掉。晚到的回答丢掉。

## Alternatives considered

**宿主只给有副本的任务回改动，没副本的回“不可用”。** 没选：直接在项目里改的任务也常见，看看项目的改动仍有用，写明范围就不会误导。

**按任务自己的回合改动（`turn_changes`）列出它改过的文件。** 这次没做：那是会话级的记录，接口和 Git 改动不同。以后可以加一节“这个任务改过的文件”。

## Consequences

- **收益：**
  - 在任务页就能看这个任务的改动和差异；
  - 直接在项目目录里改的任务，写明看到的是整个项目的改动。
- **局限：**
  - 没副本的任务分不出哪些改动是它的；
  - 只读，不能暂存、提交、撤销；
  - 真机、真实 Mac 上 NOT RUN，界面没有目检。
- **验证：**
  - 宿主新增 1 个测试：有副本读副本，没有或为空读项目。
  - 手机新增 2 个测试：
    - store：
      - 打开任务就带 `taskId` 读改动；
      - 项目的回答不落到任务上；
      - `scope` 和改动读出、差异按任务读；
      - 快照重读改动和差异，读取期间保留；
      - 读失败时保留；
      - 任务没了清掉，离开后晚到的回答丢掉。
    - 经假 Mac：任务的改动带 `scope` 读出，差异请求带着 `taskId`。
  - MacBook 上：
    - 宿主 `remote_headless` 测试 5 个都过，`cargo fmt --check` 过；
    - iOS 包 69 个测试都过，连接相关四套连跑 5 次都过；
    - iOS App 在模拟器上编过。
