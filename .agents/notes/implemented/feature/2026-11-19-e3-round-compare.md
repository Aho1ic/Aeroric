# Agent Note: E3 审查轮间对比：新增、仍在、已解决、未复查

Status: implemented

## Problem

[1118 调研](../../proposed/architecture/2026-11-19-new-addition-1118-research.md) 的 E3。[审查循环](2026-10-30-review-loop.md) 第 2 轮起，卡片只显示这一轮的意见，上一轮的意见从卡片上消失了：

- 用户分不清哪条是新冒出来的、哪条是上一轮说过还没改好的；
- 上一轮的意见没再出现，看起来像是改好了。但第 2 轮只审写代码的会话这一轮改的文件（`resolve` 把 `answer_diff` 作为新一轮的 diff），对方没碰的文件，审查者根本没再看。这种"没再提"不等于"已解决"。

OCR 用会话对比解决同样的问题；OCR #854 的另一面是每次都重审整个范围（19 轮，每轮约 200 万 token）。Aeroric 已经只审新改动，缺的是把结果如实对比出来。

## Decision

- **对比在审查者回合结束时做**（`review/compare.rs`），在 E2 的定位、合并和 E1 的覆盖判断之后，只在有上一轮时做（第 2 轮起）。
- **这一轮的每条意见**：和上一轮某条说的是同一件事，就在 `repeats` 记下那条的编号（"仍在"），否则是"新增"。"同一件事"指：
  - E2 的意见身份相同（文件 + 类别 + 压缩空白后的片段，没有片段时用文字）；或者
  - 同一文件、文字相同（压缩空白、不分大小写）。审查者第二次提同一个问题时，可能这次带了片段、上次没带。
  - 上一轮每条最多对上这一轮的一条。
- **上一轮采纳了、这一轮没再提的意见**，按它所在的文件这一轮的覆盖结局分：
  - 文件这一轮被审了或看过（E1 的 `reviewed`、`seen`）：**已解决**；
  - 文件不在这一轮的范围里（对方没改它），或者被跳过、没看：**未复查**，不算已解决；
  - 意见没有文件时，这一轮覆盖完整才算已解决，否则算未复查。
- **被驳回、审查者也没再提的意见不进对比**：对方给了理由，审查者接受了，但问题并没有被改掉，算"已解决"不对。
- 两份清单存成上一轮意见的副本（`RoundCompare.resolved`、`unchecked`），卡片不必再回查上一轮。
- **提示词**：
  - 审查者看到的上一轮意见带上片段；
  - 加一句"上一轮的问题还没改好的，用原来的 file 和 snippet 再报一次；已经改好的不要再报"，让"仍在"认得出来；
  - 发给写代码的会话时，仍在的意见下面写"（上一轮也提过，还没改好）"。
- **App**：
  - 总评下面一行"新增 1 · 仍在 1 · 已解决 1 · 未复查 1"，只列不为零的项；有未复查时用警示色；
  - 点开逐条列出"已解决 · …"和"未复查（这一轮没人再看这个文件） · …"；
  - 仍在的意见点开写"上一轮也提过（当时是 r1），还没改好"；
  - 进度页的一行摘要加"N 条未复查"。
- **结论不变**：未复查不会让一轮从"通过"变成别的状态，只如实显示。

## Alternatives considered

**按文件内容哈希复用上一轮的结论，把没改的文件也算进这一轮**（调研里的原方案）。最强的理由是卡片能说"这个文件没变，沿用上一轮"。没选：第 2 轮本来就不审没改的文件，"沿用"只会把上一轮的意见原样搬过来，看起来像是又审了一遍。如实写"未复查"更准确。

**把上一轮意见所在、这一轮没改的文件也加进审查范围。** 最强的理由是"未复查"会变少。没选：会把审查范围扩回 OCR #854 的老路；而且对方没改那个文件，采纳了的意见多半还在，再审一遍得出的也是同一个结论。审查者愿意的话，提示词里有上一轮的意见和片段，它可以自己去看并再报一次。

**未复查的阻断问题让"通过"变成"需要你处理"。** 最强的理由是更保守。没选：修复可能落在另一个文件里（例如意见说调用方没检查，修复改在被调用的函数里），这时一律拦下会冤枉正常的通过。先如实显示，看实际出现得多不多。

## Consequences

- **收益**：
  - 第 2 轮起，用户能看出哪些问题还在、哪些改好了；
  - 没人再看的旧意见不会被误当成已解决；
  - 写代码的会话知道哪些是第二次被提。
- **代价**：卡片多存两份上一轮意见的副本，最多是上一轮的条数。
- **局限**：
  - 只在一个审查循环内对比；对方下一次改动开的新循环从第 1 轮开始，不和上一个循环对比；
  - 审查者换了措辞、也没带片段时，认不出"仍在"，会显示成一条新增、一条已解决；
  - B5 的"无进展"判断仍按"文件:行"加文字比较，没有改用 `repeats`。
- **验证**：
  - `compare.rs` 新增 `each_old_finding_persists_resolves_or_goes_unchecked`：
    - 换了说法、重新缩进的片段仍算仍在；只有文字相同也算；
    - 文件被审过的算已解决，没看的算未复查，没有覆盖信息时全部未复查；
    - 没有文件的意见按整轮覆盖判断；被驳回的不进对比。
  - `review/tests.rs` 新增 `the_second_round_says_what_persists_what_is_resolved_and_what_went_unchecked`：第 1 轮在 a.rs、b.rs 上各有意见，对方只改了 a.rs；第 2 轮重提 a.rs 的一条，另一条已解决，b.rs 的未复查；写代码的会话收到"上一轮也提过"。
  - Swift 新增 `testTheSecondRoundComparesWithTheFirst`。
  - 界面待目检，记在路线文档 §8。
