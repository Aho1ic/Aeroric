# Agent Note: 工作安排第一批：待办——用户写、手动交办给 Agent、会话结束后由用户验收

Status: implemented

## Problem

backlog A12"工作安排"一直只有一份 DEBUG 下的设计稿（`WorkArrangementsReview`），没接后端。设计稿覆盖了 8 个场景：目标与来源、明确交办与范围、暂停与停止、规则差异、漏跑与补跑、繁忙、局部冲突、共享护栏。[定时任务](2026-11-14-scheduled-tasks.md)两批做了其中"到点开会话"的部分。

用户想让 Agent 去做的具体事情，现在没有地方记：只能直接开会话。会话结束了，这件事算不算做完、做得对不对，也没有地方标。设计稿里最核心的一条是"执行结束不等于目标完成"。

2026-11-15 集中目检期间，用户说"你先做下一步任务"。我按上一轮推荐的顺序选了工作安排第一批，并按推荐定了 5 条：

1. 下一项做工作安排第一批：项目待办，加手动交办。
2. 待办存在 core（数据目录里的 `todos.json`），侧栏"需要我处理"下面加一个"待办"页。
3. 交办：选一个 Agent，开一个新会话，名字是"标题（待办）"；同一个待办可以重新交办，以最新一次为准。
4. 会话结束不算完成：待办变成"待验收"，用户点"验收通过"才算完成。没跑成、失败、中断都如实显示，并给"重新交办"。"需要我处理"里加一行"待办待验收 N 条"。
5. 以下放到第二批：Agent 提议待办（Context MCP 的 `todo_add`，用户确认后才进列表）、按规则自动交办、用检查结果作为完成依据。

## Decision

**协议**（`aeroric_protocol::todo`）

- `Todo`：`id`、`project_id`、`title`（最长 200 字）、`notes`、`state`、`assignments`、`created_ms`、`updated_ms`、`closed_ms`。另有宿主读的时候才填的 `progress` 和 `progress_detail`。
- `TodoState`：
  - `open`：写下了，还没交办；
  - `assigned`：交办出去了；
  - `done`：用户验收了；
  - `cancelled`：用户取消了。

  状态只由用户的动作改变，会话怎么样不会改它。[第二批](2026-11-15-todos-second.md)加了 `proposed`：Agent 提议、等用户收下的待办。
- `Assignment`：每交办一次记一条，包括会话 id、Agent、模型、时间。最后一条是现在算数的那一次。
- `Progress`（只对 `assigned` 的待办，每次列表时从最新那个会话现读）：
  - `running`：进行中；
  - `waiting`：等你确认；
  - `review`：会话这一轮结束了，等你验收；
  - `notRun`：最后一轮没跑成，例如额度用完、登录失效；
  - `failed`、`stopped`；
  - `missing`：会话已经不在了。
- RPC：`todo.list {projectId?}`、`todo.save {todo}`、`todo.delete {id}`、`todo.assign {id, agent, model?}` → `{todo, taskId}`、`todo.decide {id, decision: accept | cancel | reopen}`（第二批加了 `take` 和 `todo.check`）。

**core**（`aeroric_core::todos`）

- `Todos` 和定时任务一样：一个 JSON 文件，整个读、整个原子写，一把锁。
- `save_todo` 只改标题和说明，标题和项目不能为空。
- `assigned` 记下交办，待办变成 `assigned`。已经完成或取消的待办也可以重新交办，交办后重新打开。
- `decide`：
  - `accept`：只有 `assigned` 的待办能验收；
  - `cancel`：随时可以取消；
  - `reopen`：交办过的回到 `assigned`，没交办过的回到 `open`。
- `progress(session)`：按会话记录的状态判断。`pending` 和 `running` 是进行中；`input_required` 是等你确认；`failed` 带上失败原因；`interrupted` 和 `cancelled` 是已中断；其余（会话停在空闲）看最后一轮的分级，没跑成就是 `notRun` 并带上报错，否则是 `review`。
- `prompt_for`：标题，加说明，再加"做完后用几句话说明：改了什么、怎么验证的、还有什么没做完"，好让验收时有东西可看。
- 列表把在办的（`open`、`assigned`）排在前面，各自按更新时间从新到旧。

**宿主**（`session_live_services/todo.rs`）

- 交办开会话，复用定时任务开会话的那段代码，抽成了 `schedule::open_session`：走 `task.run`，用这个 Agent 的默认权限模式，再改名。定时任务现在也调用它。
- `TodoEnv::session`：读任务记录的状态和 `failureReason`。会话没在跑时，用 `rerun::turns` 取最后一轮的分级。
- 删除待办不删它开过的会话。

**界面**（Swift）

- 侧栏"需要我处理"下面是"待办"（`WorkspaceSection.todos`）。
- 待办页：
  - 顶部一句说明和"新建"；在办的待办逐行列出，已完成和已取消的收在一个胶囊按钮后面。
  - 每行显示标题、项目、"交办 N 次 · 上次某 Agent"、状态胶囊。状态胶囊悬停时显示没跑成或失败的原因，这个原因也会在行内显示出来。
  - 每行的按钮随状态变化：待交办时是"交办…"和"取消"；待验收时是"验收通过"、"重新交办…"、"打开会话"；出了问题时，"重新交办…"会被突出显示。
  - 编辑和删除用图标胶囊。
  - 整页不用 `Menu`：App 在后台时，`Menu` 不响应辅助功能的点击。
- 交办弹窗：选 Agent，默认是上次交办用的那个；预览会话名和将要发出去的消息；交办后直接跳到新会话。
- "需要我处理"顶部：有待验收的待办时显示一行"待办待验收 N 条"，点了打开待办页。侧栏"需要我处理"的数字也把这一行算进去。

## Alternatives considered

- **直接接上设计稿的整套流程**：设计稿已经把来源、授权、规则、繁忙、护栏都画好了。没有采用：那是 8 个场景、几十种状态，超过一批能做完、能拍板的量；先把"写下 → 交办 → 验收"这个闭环做实。
- **会话结束就算完成**：少一次点击。没有采用（第 4 题）：设计稿的第一原则是"执行结束不等于目标完成"。Agent 说做完了，可能只做了一半，也可能做错了；只有用户能判断。
- **交办时也选模型**：更灵活。当时没有采用：定时任务也只选 Agent、用默认模型，两处保持一致；需要别的模型，可以在会话里切换。2026-11-16 复测证明进会话再换会白跑一轮，交办已改为选配置和模型，见[交办选配置和模型](2026-11-17-todo-assign-configuration.md)；定时任务仍只选 Agent。
- **待办存在任务记录上**：不用新文件。没有采用（第 2 题）：没交办的待办没有会话，挂不到任务记录上；一个待办也可能交办多次，对应多个会话。
- **把 Agent 提议的待办也放进这一批**：Agent 做事时常会发现"还应该做什么"。没有采用（第 5 题）：要加 MCP 工具、确认流程和防刷，这一批先只做用户自己写的待办。

## Consequences

- 收益：
  - 要做的事有了一个地方记；
  - 交办只要一步，交办出去的会话的进度在待办页上就能看到；
  - "做完"由用户验收来定，没跑成、失败、中断都如实显示，并可以重新交办。
- 代价：
  - 状态要靠列表时现读会话记录和转写；待办多、会话多时，打开待办页会慢一些；
  - "需要我处理"的待验收数字跟着它原有的刷新节奏更新，不是实时的；
  - 远程项目不能交办（`open_session` 只认本机项目），和定时任务一样；
  - 交办时选配置和模型已由[交办选配置和模型](2026-11-17-todo-assign-configuration.md)实现；
  - 待办只在 Mac 上；
  - 设计稿里的按规则自动交办、权限、繁忙、共享护栏，都没做；Agent 提议待办、检查作为完成依据、检查没过让 Agent 接着修、交办会话算无人值守，由[第二批](2026-11-15-todos-second.md)实现。
- 设计稿（`WorkArrangementsReview`）保留在 DEBUG 里，作为后续批次的参考。
- 待目检（已记进路线图的待目检清单）：
  - 侧栏"待办"和待办页；
  - 新建和编辑弹窗、交办弹窗和跳转；
  - 各种状态胶囊和对应的按钮；
  - "需要我处理"里的待验收行；
  - 一个真实待办从交办、待验收到验收通过的全过程。

## Testing

- core `todos` 3 个测试：
  - 交办后进行中；会话结束变待验收，状态仍是已交办；重新交办后以新会话为准，没跑成时带上报错；验收后不再读进度；重新打开回到已交办；没交办过的不能验收。
  - 列表在办的在前，按项目过滤；会话不在了时显示 `missing`；编辑只改文字、不改状态；空标题、空项目被拒；删除，重复删除返回 `false`。
  - 各种会话状态对应的进度；发给会话的提示词格式。
- 宿主集成测试 `a_todo_is_handed_out_and_accepted_by_the_user`：
  - 保存时去掉空白；交办前不能验收；交办后开出会话，会话的提示词以待办的标题和说明开头；列表带进度；验收；
  - 项目不存在时拒绝；删除，再删返回 NOT_FOUND；交办不存在的待办返回 NOT_FOUND。
- Swift `TodoTests`：
  - 线上解码（多次交办、进度和原因），保存只发文字；
  - 状态文字、何时显示"重新交办"、交办次数、"需要我处理"那一行的文字、提示词；
  - Store 的保存、交办、验收、删除都发到服务，待验收计数正确，被拒绝时保留原因。
- 没有在审阅版里实际点过：用户正在用审阅版做集中目检，这一批没有重建、替换审阅版。
