# Agent Note: E6 第三步：用量上限的设置和侧栏的暂停按钮

Status: implemented

## Problem

[1118 调研](../../proposed/architecture/2026-11-19-new-addition-1118-research.md) E6 写的“用户会看到”：

- 设置里可以按日和月、按金额或 token，给无人值守的工作设上限；
- 到 80% 时用量页变色，到顶时只通知一次；
- 侧栏有一个“暂停所有 Agent”开关。

动手前（`main@4cb07ebf`）：

- [第一步](2026-11-21-e6-budget-rules.md)写好了规则；
- [第二步](2026-11-21-e6-budget-applied.md)让宿主在开始无人值守的工作前检查，并执行全部暂停；还有 `budget.status`、`budget.set` 两个接口。App 里还看不到这些。

核对的位置：

- 用量相关的东西都在 Agent 配置 → 用量与成本（`ChangeCostPane`）：额度节奏卡、改动成本、网关请求；
- 侧栏底部有一行：左边是设置按钮，右边是连接状态（`ProjectSidebar.footer`）。

## Decision

**用量与成本页顶上，加一段“无人值守的用量上限”**（`BudgetSection`）：

- 第一行说门现在的状态，按颜色区分：
  - 没设上限 → “没有设上限”；
  - 在上限以内 → “在上限以内”；
  - 到了 80% → 橙色，写宿主给的原因，加“快到上限了”；
  - 到顶 → 红色，写宿主给的原因；
  - 暂停 → 红色，“已暂停所有 Agent：正在跑的回合已停下，新消息不收”。
- 第二行是今天和本月的用量：token 和估算金额。
- 每条上限一行，例如“每天 200K tok”“每月 $20.00”，可以删。
- 加上限：选每天或每月，填 token 或美元（至少一个），点“添加上限”。宿主拒绝的（比如 0），写“保存失败：…”。
- 最后是说明：
  - 只算无人值守的工作：定时任务、不是你发起的委派和审查，你自己发的消息不受限；
  - 只在开始新工作前检查；
  - 到上限时，每天（或每月）只提醒一次。

**侧栏底部，设置按钮旁，加一个暂停按钮**（`PauseAllButton`）：

- 没暂停时是一个暂停图标。点它先弹确认：“正在跑的回合会立刻停下，之后发的消息不收，定时任务到点跳过。随时可以恢复。”
- 暂停后变成醒目的“已暂停 · 恢复”，点一下就恢复，不再确认。

**状态对象** `BudgetBook`：

- 连上宿主时读一次，所以侧栏一打开就知道是不是暂停着；
- 换暂停、改上限时，其余设置原样带上；
- 出错时写原因，页面不变。

**协议模型** `LiveBudget`、`LiveUsageCap`，客户端 `BudgetClient`，文字 `BudgetText`。

## Alternatives considered

**上限放进“设置”窗口。** 最强的理由是方案写的是“设置里”。没选：

- 上限要和用量放在一起看；
- 用量与成本页已经有额度节奏、改动成本和网关请求，放在这一页，“用了多少”和“最多用多少”在一处。

**暂停开关放在用量页，不放侧栏。** 没选：方案明确要侧栏开关。暂停是要随手能按到的急停，不能藏在二级页面里。

**恢复也要确认。** 没选：恢复不会停下任何东西，也不会丢东西；多确认一次，只会在急着恢复时添麻烦。

## Consequences

- **收益：**
  - 用户能在 App 里设上限，看到用量和是否快到顶；
  - 一键暂停或恢复所有 Agent。
- **代价：**
  - 用量与成本页多一段；
  - 侧栏底部多一个按钮。
- **局限：**
  - 用量和门只在打开这一页、或连上宿主时读，不会自己刷新；
  - 暂停按钮只显示连上宿主那一刻的状态，在另一个客户端里切换了，这边要等下次读才会变；
  - 没有系统通知，到顶的提醒只在相关会话和运行记录里；
  - 新会话的输入框在暂停时没有提前置灰，发出去才会被拒。
- **验证：** Swift 新增 `BudgetTests` 2 个，全部通过：
  - 状态按页面的样子读出：上限一行的写法（token 和美元）、门的几种说法、用量一行；发回宿主的设置里，上限和暂停都在；
  - 状态对象：暂停时上限原样带上；改上限时暂停原样带上；被拒时写“保存失败”。
- **待目检：** 已记进路线文档 §8 待目检清单。
