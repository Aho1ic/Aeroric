# Agent Note: D2 第二步：发布草稿和发布的宿主方法，只给 App

Status: implemented

## Problem

[D2 第一步](2026-11-21-d2-publish-core.md)在 core 里做好了发布：草稿、标记核对、逐条发送、结果不明不自动重发、重启恢复（`main@a1b56a16`）。它留下三件事给宿主：

- **App 要能调用：** 从一份审查建草稿、列出、改条目、发布。
- **防连点：** 同一份草稿同时只能有一次发布。core 只会拒绝状态是“发送中”的草稿，可是连点两次时，第二次可能在第一次存盘之前就读到了“草稿”。
- **方案第 1 条：** 发布是用户动作，Agent 不能触发。

核对的事实：

- Agent 拿到的工具全部来自共享工具表 `aeroric_protocol::tools::AERORIC_TOOLS`（C8）。`mcp-context` 只把这张表里的工具转成宿主方法。宿主新加的方法不在表里，Agent 就调不到。
- D1 的 `github_services.rs` 已经有现取 gh 令牌的 `gh_token`，以及按项目读写的写法。

## Decision

**四个方法**，放在 `github_services.rs`，和 D1 的快照方法在一起：

- `github.writeDraft {projectId, reviewId}`：
  - 审查必须已有结论，否则说“这份审查还没有结论”；
  - 一份审查只有一份草稿，再要一次就返回原来那份。不然两份草稿的标记不同，同一条结论可能变成两条评论。
- `github.writes {projectId}`：列出草稿。
- `github.writeEdit {projectId, id, itemId, body?, included?}`：改正文或勾选，规则同 core。正在发布时拒绝。
- `github.publish {projectId, id, resendUnknown?}`，按顺序：
  1. 先占住这份草稿：进程里有一个“正在发布”的集合，占不到就回“正在发布，等它结束”。发布结束时（不管怎么结束）放开。
  2. 读出草稿，按“上次被打断”恢复：占住以后，盘上还写着“发送中”的，只可能是上次没跑完。
  3. 没勾选任何条目就拒绝。这一步在取令牌、联网之前。
  4. 现取 gh 令牌，交给 core 的 `publish`。写超时 30 秒，每条发送前后都存盘。

**读草稿时恢复：** 一份草稿没在发布、盘上却写着“发送中”，读出来就是“结果不明”，涉及的条目注明“发送时 Aeroric 停了”。这样 App 在宿主重启后看到的是真实状况，不会是一直转圈的“发送中”。

**不进 Agent 的工具：** 这四个方法不在共享工具表里。测试断言表里没有带 `publish` 或 `github` 的工具名。

## Alternatives considered

**防连点只靠 core 的“发送中”状态。** 最强的理由是不用再加一把锁。没选：两次点击之间，第一次可能还没把“发送中”写进盘，两次就会都读到“草稿”，各发一遍。进程内的集合在读盘之前就把第二次挡住了。

**每次 `writeDraft` 都新建一份草稿。** 最强的理由是用户可以从头再来。没选：两份草稿的标记不同，同一条结论会被发成两条评论，正好违反完成条件。想改内容，在同一份草稿上改就行。

**宿主启动时扫一遍，把“发送中”改成“结果不明”。** 最强的理由是只做一次。没选：读的时候改，效果一样，也不用在启动流程里加一步；草稿不多，读一次的代价可以忽略。

## Consequences

- **收益：**
  - App 能走完建草稿、改、发布这一流程；
  - 连点、重启都不会让同一份草稿同时发两次；
  - Agent 碰不到发布。
- **代价：** 进程里多一个集合。宿主重启后它是空的，这时靠盘上的状态恢复。
- **局限：**
  - 没有界面；
  - 只防同一个宿主进程里的并发。两个宿主同时开着同一个数据目录的情况，由数据目录的写者租约挡住，这里不另外处理。
- **验证：** 宿主新增 1 个测试，通过：
  - 审查还没有结论时不能建草稿；
  - 有结论后建草稿：两条，状态是草稿；再要一次，返回同一份；
  - 能改勾选；正文改成空白被拒；
  - 都不勾选时发布被拒，没有取令牌、没有联网；
  - 盘上留着“发送中”的草稿，列出时是“结果不明”，条目也是；
  - 共享工具表里没有发布相关的工具。

  网络部分（发送、核对标记、目标已更新）由第一步 core 的 6 个测试覆盖。
- **NOT RUN：** 对真实 GitHub 的发布。
