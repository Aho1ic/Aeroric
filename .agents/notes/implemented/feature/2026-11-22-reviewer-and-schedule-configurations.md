# Agent Note: 审查者和定时任务能选 Agent 配置和模型

Status: implemented

## Problem

2026-11-22 的四份目检报告里，有一组项一起没测成。

报告 `2026-11-22-1421-aeroric-review-1122-review` 写道：审查者只能选“自动 / Claude Code / Codex”，选了 Claude Code 也没有连接或模型可选。提示词要求用 Magpie 的 `42/deepseek-flash`（Claude Code 用不了官方订阅），所以审查回环没开。定时任务也是这样，只能选 Agent。结果 C1–C3、D1 和 E16 的结果判定都没跑，因为它们都要先开一次审查或定时任务。

动手前（`main@1239808f`）核对过：

- **审查：协议早就能带配置。** `ReviewerChoice::Named` 有 `agentConfigId` 和 `model`，宿主开审查会话时也会把它们写进新任务。缺的是两处：
  - `review.reviewers` 只列 Harness，App 的选择器只能选这几项；
  - 宿主不核对配置还在不在、能不能用。
- **定时任务：协议和执行都缺。**
  - `ScheduleRule` 只有 `agent` 和 `model`，开会话时 `agent_config_id` 写死为 `None`；
  - 编辑器只有 Agent 一栏，连模型都不能选。
- **交办（2026-11-17）已经有现成的做法。** `todo.assign` 收 `configurationId`（会话目录里的 id），`pick_configuration` 核对四件事：
  - 配置存在；
  - 没有拦截原因；
  - 属于这个 Agent；
  - 有这个模型。

  核对通过后再交给 `open_session` 的 `agent_config_id`。

## Decision

**审查和定时任务都复用交办的核对。** `todo::pick_configuration` 和 `Picked` 改成模块内可见。

**审查：**

- `review.reviewers` 多返回 `configurations`：本项目会话目录里的 Agent 配置（`agent-config:` 开头），条件是没被拦截、跑的 Harness 在本机能当审查者。每项带：
  - `agentConfigId`（不带前缀）
  - 名字、Agent、模型列表
  - 是否和写代码的会话同族

  内建项就是那几个 Harness，不重复列。会话目录读不出来时只少这一段，列表照常返回。
- 选了配置的审查者，开审查前按交办的规则核对一遍；不通过时，这一轮审查失败并写明原因。审查卡上的审查者名字写“配置名 · 模型”。
- App 的选择器在 Harness 下面多一段“Agent 配置”。只有一个模型的配置直接选；有多个模型的展开再选模型。
- 选中的配置后来没了或被拦截时，标题写“配置 名字 · 现在不能用”，下面一行用警示色写“下一次审查会失败；换一个”。

**定时任务：**

- `ScheduleRule` 新增可选的 `configurationId`（会话目录 id）。它不在契约文档里，不用重新生成。
- 保存时按交办的规则核对，`agent` 改成配置所属的 Agent。每次运行前再核对一次：配置可能在保存之后被删或被拦截，这时那次运行失败，并写明原因。
- 编辑器在 Agent 下面多一栏“配置”，默认是“不用配置（Agent 自己的登录）”，选项是本项目能用的 Agent 配置。选了有模型列表的配置，再多一栏“模型”。换 Agent 时清掉上一个 Agent 的配置。
- 规则那一行写“配置名 · 模型”，配置不在了就写“现在不能用”。

## Alternatives considered

**审查者的配置也让 App 从会话目录里自己筛（交办就是这样做的）。** 没选。原因：

- 能不能当审查者要看两件事：Harness 在本机装没装，`takes_task` 认不认。只有宿主知道；
- 进度面板本来就从 `review.reviewers` 取候选，在这里一起返回，App 不用多接一条会话目录的线。

**定时任务也让宿主列配置。** 没选。编辑器要先选项目，会话目录本来就按项目加载；交办页已经这样接了，照用即可。

**内建配置也列进来。** 没选。测试宿主里内建的 Codex 配置本身带拦截原因（“内建配置的路径……尚未……完整采用”），真机上也可能这样。交办的规则写明：拦截原因只针对“按配置提交”，不影响按 Agent 名字开会话。所以内建就是选 Agent 本身，用 Agent 那一栏。

## Consequences

- **收益：**
  - 目检能指定 Magpie 的 `42/deepseek-flash` 开审查回环和定时任务，C1–C3、D1、E16 的结果判定可以补测；
  - 配置失效时，事前能看到，事后有原因。
- **局限：**
  - 进度面板的审查者列表每个任务只读一次，新加的配置要切走再回来才出现；
  - 定时任务那一行里的配置名靠 App 已加载的会话目录，目录还没加载时写“现在不能用”，加载后会自动更正；
  - 委派面板仍然只能选 Harness，这次没动；
  - 都还没目检。
- **验证：**
  - 宿主单元测试 2 个：哪些配置能当审查者（被拦截的、Harness 不在本机的、非审查 Harness 的都不列，同族标记）；选中配置的核对与名字（不存在、被拦截、模型不支持、Agent 不对都拒绝）；
  - 宿主集成测试延伸 2 处：`review.reviewers` 带 `configurations`；定时任务保存不存在或被拦截的配置时被拒；
  - Swift 新增 2 个：审查者配置的解码、选择与“现在不能用”；定时任务规则带配置的往返与那一行的写法；
  - 全量验证结果见路线文档。
