# Agent Note: C5 第二步：连接测试记下出口，配置变了就标"需要重测"

Status: implemented

## Problem

[C5 第一步](../bug-fix/2026-11-19-c5-gateway-honours-connection-proxy.md)让连接测试、模型目录和网关走同一个出口。方案还剩两条：

- 第 3 条：测试结果带上出口的摘要和配置的修订号，读取时比较，配置改过的标"配置已变，需要重测"。
- 第 4 条：测试只发最小的真实请求，界面写明会产生的费用量级。

动手前的现状：

- 测试结果只是 App 里的一行临时文字，显示 8 秒就消失，宿主也不存。
- 无从回答"这个模型上次测试是什么时候、通没通过、当时走的是哪个出口"，也看不出测试之后配置有没有变过。
- 第 4 条已经满足：测试按钮的提示写着"向上游发一句'回复 pong'，最多回 64 个 token，消耗极少额度"。

## Decision

**记下出口**（`core/crates/aeroric-core/src/agent_connections/test_record.rs`）：

- 每次测试（无论成败）存一条记录，放在 `<数据目录>/connection-tests.json`。每个连接加模型只留最新一条，删除连接时一起删。
- 记录里有：时间、HTTP 状态（没收到回应记 0）、耗时、回复开头或失败原因，以及出口 `Egress`：
  - 端点地址；
  - 协议；
  - 代理地址（去掉其中的用户名和密码，直连时为空）、`no_proxy`、代理用户名；
  - 凭据指纹：密钥 SHA-256 的前 12 位十六进制。密钥本身和代理密码都不存。
- 出口由 `Egress::of` 算出，用的是第一步那个共用判断 `connection_proxy`。宿主的测试处理也改为：先算出口，再按这个出口发请求（`probe_connection_via`），发请求和记录用的是同一个决定。

**读取时对照现状**：

- 宿主的连接快照（`agentConnections.load` 和每次修改后的返回）带上 `tests`。
- 每条记录都按连接现在的配置重新算一遍出口，对不上就写"配置已变，需要重测（…）"，括号里依次检查：
  - 地址改过；
  - 协议改过（包括连接不再支持当时用的协议）；
  - 代理设置改过（包括开关被关掉，或者勾了代理却没配）；
  - 凭据换过。
- 快照本来就要读每个连接的凭据来判断"已存 / 缺失"，凭据指纹就在这里顺带比较。所以在 Aeroric 之外换了钥匙串里的凭据，也能发现。
- 方案写的"配置修订号"，就用这份出口描述代替：只有影响请求怎么发出去的字段才会让测试过期。改个连接名称，不需要重测。

**全局代理设置按需读取**：

- 快照、测试和网关按配置解析上游，都只在有连接勾了"使用全局代理"时才读全局设置。
- 第一步提交的网关解析是每个请求都读一次。全局设置的读取会在测试没有注入数据目录时落到真实设置文件上，规范化后还可能写回，这次一并改成按需读取。

**App**（`ConnectionsPane.swift`）：

- 模型行上，没在测试的时候显示上次测试的结论："上次通过""上次失败"或"需要重测"（警示色）。
- 悬停显示：过期原因、测于何时、HTTP 状态和耗时、直连还是经哪个代理、协议和端点；失败的还附上原因。
- 测试结束后重读一次快照，新结果马上出现。

## Alternatives considered

**存整份配置的修订号，读取时比修订号。** 最强的理由是任何改动都不会漏。没选：连接没有现成的修订号，改名、启用模型这类和出口无关的改动也会让测试过期；只比出口相关的字段，过期的理由能说清楚。

**写凭据的地方给测试打"凭据换过"的标记，不存指纹。** 最强的理由是磁盘上完全不留与密钥有关的东西。没选：在 Aeroric 之外换钥匙串里的凭据时，这种标记会漏掉；12 位十六进制的指纹由高熵密钥算出，还原不出原文。

## Consequences

- **收益**：
  - 每个模型能看到上次测试的结论和当时的出口；
  - 改了地址、代理或凭据之后，旧的"通过"不再冒充现在。
- **代价**：
  - 数据目录多一个小文件；
  - 快照为每条测试多算一次出口，不涉及网络。
  - 代理地址里内嵌的密码改了，不会被判为改动（密码不存）。
- **验证**：
  - `test_record_tests.rs` 新增 3 个测试：
    - 出口不含密钥和代理密码，指纹 12 位；
    - 地址、协议、代理（换地址、关开关、勾了没配）、凭据变化，各自写出对应的原因；
    - 每个模型只留最新一条，删除连接后测试跟着消失，不存在的连接不显示。
  - 宿主集成测试 `a_test_message_goes_through_the_connection_with_its_key` 延伸：
    - 测试之后快照里有这条通过的记录，出口直连，快照里看不到密钥；
    - 换凭据后标"凭据换过"；
    - 删除连接后记录消失。
  - Swift 新增 `ConnectionTestRecordTests`：解码三条记录，检查"上次通过 / 上次失败 / 需要重测"的文字和悬停说明。
  - 界面待目检，记在路线文档 §8。
