# Agent Note: 文件页写操作与保存冲突检查

Status: implemented

## Problem

文件页只能浏览和预览。宿主早就有新建、重命名、移到废纸篓的方法，界面里也有菜单，但没有接线，行也是早期的 List 样式。文件标签页 2026-10-26 起已经能编辑保存，可保存时直接覆盖磁盘。如果 Agent 在你打开之后改过这个文件，它的改动会被悄悄冲掉（Trellis 任务 `10-26-git-files-writes` Q3/Q4，设计稿 2026-10-30 通过）。

## Decision

**文件树**
- 改成胶囊行，按层级缩进。鼠标悬停时出现「…」：文件夹可以新建文件和文件夹；文件和文件夹都可以重命名、移到废纸篓。
- 顶部「＋文件」「＋文件夹」在项目根目录下新建。名字在树上方的胶囊输入框里填。
- 移到废纸篓先确认，界面上不提供永久删除。
- 名字合不合法由宿主判断，客户端不重复校验。失败原因显示在树上方。
- 关联文件夹只读：它们属于 Mac 上的其他文件夹，关联时说好了「不会往里面写」。

**接线**
- `AppServices.applyFileEdit` 调 `files.create_file / create_directory / rename_path / delete_path`，然后重新读取发生变化的那一层目录。在一个收起的文件夹里新建时，会先把它展开。

**保存冲突**
- 保存前先重读磁盘，和开始编辑时的原文（`draftBase`）比较。相同就直接保存。
- 不同就让用户三选一：取消；放弃我的修改并重新读取；覆盖保存（标为危险操作）。默认按钮是「取消」。

## Alternatives considered

- **宿主按版本号或修改时间拒绝过期写入**：不选。`files.write_file` 没有版本参数，要改协议。客户端先读一次再比较，就能挡住常见情况：Agent 在你编辑期间改了文件。代价是读和写之间还有一个很小的时间窗口。
- **冲突时自动合并**：不选。文本合并可能出错，让用户自己决定更稳。
- **关联文件夹也可写**：不选，和关联时的承诺不符。

## Consequences

- 旧的 `FileOperationSheet` 和 `FilesOperation` 保留。`FilesOperation` 仍是行菜单的动作类型，表单不再使用。
- 重命名或移走一个已经打开成标签的文件后，标签不会自动关闭，再读取会提示找不到文件。
- 测试：路径拼接、刷新哪一层、关联路径不可写、表单标题、保存冲突判定、展开。
- 沙箱：用临时数据目录和临时项目单独起一个宿主，跑通新建、重名被拒、重命名、带 `..` 的重命名被拒、移到废纸篓（确实进了废纸篓）、写入和读回。
