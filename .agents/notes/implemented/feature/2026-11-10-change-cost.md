# Agent Note: 每个被接受改动的成本（R3-3a）

Status: implemented

## Problem

[本回合账单](2026-11-09-turn-bill.md)能看出一轮花了多少，[整轮撤销](2026-11-04-turn-undo.md)记下了改过文件的回合最后是接受、撤销还是待验收，但两边没有连起来：用户没法回答"这个配置、这个模型，一次被我留下的改动要花多少，有多少花在了被撤销或没产出改动的回合上"。[路线复核](../../proposed/architecture/2026-11-02-roadmap-recheck.md)把它列为只有 R2、R3 串起来才有的指标，模型路由要靠它而不是靠榜单。

R3-3 拆成两批：R3-3a 是本篇的改动成本；R3-3b 额度节奏另做，因为现在的额度只读得到本机 Codex 订阅，而会话走 CPA，两者是不是同一个账号还没核实。

## Decision

- 宿主新增 `session.changeCost {rangeDays, agent}`，`agent` 是 `all`、`codex`、`claude`、`omp`、`dsh`（界面现在只用 `all`）。
  - 扫所有项目的本机会话，归档的也算（做完的工作常被归档）；SSH 会话跳过。
  - 会话文件修改时间早于区间起点的跳过；其余读末尾 32 MB，用 `transcript_stats` 的解析器取每轮的 `TurnStat`，按文件大小和修改时间缓存。
  - 回合账本直接读 `<data>/turns/<taskId>.json`（`turn_ledger::read_at`），不经过会话执行器，没在跑的会话也能算。
- **回合怎么归类**（`sessions/change_cost.rs`）：会话文件里一轮的开始时间与账本里某一轮相差不超过 60 秒，就取最近的那一轮的状态——接受、撤销、待验收；对不上的算"没产出改动"（账本只记改过文件的回合）。真实数据里两边相差不到 1 秒。会话文件没记用量的回合（一开始就失败、旧版 Claude 会话）不计，否则只会多出"1 轮 · 0 tok"的卡片。
- **按回合算，不按行数**：逐处审查里拒绝了一部分的回合，只要整轮被接受，就整轮算有效花费。
- **花费口径**：token 是输入（含缓存读取）加输出，和账单芯片一样；金额来自价目表，桶里只要有一轮没有价格，这个桶就不给金额，不显示部分和。
- **分组**：Agent 族 × 会话的 `agentConfigId` × 模型，按总 token 从多到少；配置名从 Agent 配置文档取 `label`，取不到就显示 id，没选配置的会话显示"codex（未选配置）"这样的族名。
- **界面**：Agent 配置页加一个标签"改动成本"（在"Agent 升级"后面），可选 24 小时 / 7 / 14 / 30 天。每个配置和模型一张卡片：标题"配置 · 模型"，右边是接受率胶囊（接受 ÷ 接受加撤销），下面四项等宽排开（各卡片同一项上下对齐），是每个接受回合的平均花费、撤销浪费、待验收、没产出改动；卡片下写明口径。会话页不加东西。

## Alternatives considered

- **按逐处审查接受的行数分摊花费**：更细，能区分"一轮里留下一半"。没选：拒绝和接受的行数跟花费不成比例，摊出来的数字看着精确其实是编的；回合粒度已经能比较配置和模型。
- **用网关的 `router_requests` 表算花费**：每个请求都有 token 和目标连接，比会话文件准。没选：只有经过本机网关的请求才有，直连和远程会话没有；而且请求和回合要再对一次时间。
- **放在运维的用量面板里**：用户最初批的是这里，和总用量、订阅额度挨着。没选：运维页在侧栏里是"即将推出"，设置窗口里也没有用量栏，放进去用户看不到；开放运维页又会带出诊断、通知中心这些没目检过的东西。成本本来就是按配置和模型比的，放在 Agent 配置页更顺（用户 2026-11-10 确认）。
- **在会话页每轮账单里显示"已接受 / 已撤销"**：一眼能看到单轮。没选：单轮的去向在回合条上已经有了，缺的是跨会话的汇总。
- **金额缺价时按同档推算**：用量面板的总费用这样做过。没选：CPA 的模型名没有同档可参照，推出来的金额没有依据。

## Consequences

- **收益**：能按配置和模型比较"留下一次改动花多少、浪费多少"，为模型路由和后面的优化提供依据；没产出改动的花费单列，排查、提问花了多少也看得见。
- **代价**：
  - 只算 Aeroric 自己跑过的回合的去向；外部导入或账本里已被修剪（每仓库 50 轮、30 天）的回合会落到"没产出改动"。
  - 待验收的回合不进接受率，用户不验收就一直不算。
  - 每次打开这个标签或切换区间都会扫一遍区间内写过的会话文件，变了的才重新解析。
  - CPA 模型不在价目表里，现在只有 token。
- **验证**：
  - core 单测：账本状态按最近开始时间匹配、超出 60 秒不匹配；四个桶分别累加，区间外的轮不算；一轮没价格整个桶没金额；按模型分行、按 token 排序；没记用量的回合不计。
  - Swift 单测（`ChangeCostTests`）：解码宿主应答（`SessionsClient.changeCostRows`）；标题、接受率、平均花费、桶合计的文字；没有可判定回合时不显示接受率。
  - 目检（2026-11-10，Codex Computer Use，审阅版）：Agent 配置页"改动成本"标签在"Agent 升级"后面；7 天、30 天、24 小时三档卡片数与 `session.changeCost` 返回的行数一致，第一张卡片四个桶的轮数和接口对得上；离开再回来区间保持。首轮看到各卡片的四项没对齐、有几张"1 轮 · 0 tok"的卡片、没选配置的会话只显示族名，改成等宽四列、不计没记用量的回合、标题写"（未选配置）"后复测通过。
  - 未覆盖：窄窗口布局（Computer Use 拖不动窗口边缘）。
