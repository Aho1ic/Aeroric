# Agent Note: H3 第一步：统一的开场白，有系统层的三家都拿到

Status: implemented

## Problem

[各 Harness 原生融合](../../proposed/architecture/2026-11-16-harness-native-capabilities.md) 的 H3 要求：换一个 Harness 开会话，Agent 一样知道用户的偏好和项目约定，一样知道这里有 Wiki 和以前的会话可查。

动手前（`main@2a0ebade`）的情况：

- **开场只有记忆档案。** `hand_brief` 只拼记忆档案（上限 1200 字），有交接简报时接在后面；用户没有记忆时什么都不给。
- **"Aeroric 能做什么"只写在 MCP 服务说明里。** 那一句在 `mcp_context.rs` 的 `instructions()` 里。Codex 只给模型看这句，并据此决定加载哪组工具（R4-3）。系统层里没有这句，没接工具的会话完全看不到。
- **没有指路。** 会话不知道项目 Wiki 有哪些页、角色库有哪些角色。
- [H2](2026-11-20-h2-omp-opening-and-tools.md) 之后，本机 Claude、Codex、OMP 都有系统层；DSH 没有。

方案把 H3 列成五条：

1. 拼三段，各有上限，另有总上限；
2. 按家族决定放在哪里；
3. 用途说明和 MCP 服务说明共用一份文字；
4. 计入"已注入"；
5. 进上下文账单的"记忆""说明"两类。

## Decision

本片分三步。这是第一步：第 1、3、4 条，以及第 2 条里有系统层的三家。

- 第二步：账单按段把开场白计入"记忆""说明"（第 5 条）。现在 Codex 的账单按开头判断类别，开场白开头是用途说明，会算进"其他"；Claude 的会算进系统提示。
- 第三步：没有系统层的 DSH，把开场白带明显标记附在第一条消息前，界面显示为"Aeroric 附加的上下文"（原融合笔记 §8 第 2 问）。

**`sessions/live/opening.rs` 拼三段，按这个顺序：**

- **用途说明**（`# Aeroric 能做什么`，上限 480 字）：
  - 内容：Aeroric 是什么；什么时候用它的工具（要以前的讨论、项目约定、设计决定，或者想把工作交给别人时），不需要时不必调用。
  - 不写"每次必须先查"之类的硬规则。
  - 接了工具的会话附上工具清单那一句；没接工具的（远端会话，或宿主没准备服务器）写明没有工具。
- **记忆档案**（原有的，上限 1200 字）：每条照旧计入"已注入"。
- **指路**（`# Aeroric 里能查的`，上限 600 字）：
  - 内容：项目 Wiki 页标题（项目开了 Wiki 并允许 Agent 读时）和委派角色名，只给标题。
  - 放不下的写"等 N 个"，两行平分预算。
  - 只给接了工具的会话，因为没有工具就打不开这些页。
- **总上限** 2280 字（三段上限之和）。超出时先去掉指路。

**共用文字。** 工具清单那一句挪到 `opening::tool_uses(Offered)`。MCP 服务的 `instructions()` 改为调用它，原文一字未改，Codex 据此加载工具组的行为不变。

**投递。**

- `hand_brief` 每次启动（含恢复）都拼开场白，交给 `set_instructions`。
- 有交接简报时，简报接在开场白后面，中间用 `---` 分隔。
- Claude、Codex、本机 OMP 都收下（`--append-system-prompt`、`developerInstructions`、H2 的临时文件）。
- 远端 Claude 和远端 Codex 也收下，内容里写明没有工具。
- DSH 和远端 OMP 不收，等第三步。

**入口记录。** 不收时的说明改成"开场白（用途、记忆档案、指路）没给"。能力表里 DSH 和远端 OMP 那两格的说明同步改。

## Alternatives considered

**只在用户有记忆时才给开场白（沿用原来的条件）。** 最强的理由是不给没有记忆的会话多加几百字。没选：H3 的目的就是让每个会话都知道 Aeroric 能做什么、去哪里查，这和有没有记忆无关。开场白只在启动时给一次，不是每条消息都注入，不违反原融合笔记 §7。

**用途说明放在记忆档案后面。** 最强的理由是 Codex 账单目前按开头判断类别，记忆档案在前时会算成"记忆"。没选：用途说明是理解后两段的前提，应该先读。账单按段拆分是第二步的事，不该为了账单的现状去定内容顺序。

**指路给出 Wiki 页的摘要。** 没选：方案明确只给标题；摘要会让开场白随 Wiki 增长而膨胀，Agent 要看时用 `read_wiki` 去读。

## Consequences

- **收益**：
  - Claude、Codex、本机 OMP 的每个会话都知道 Aeroric 提供什么、什么时候用，没有记忆的用户也一样；
  - 接了工具的会话还知道项目 Wiki 有哪些页、有哪些角色可以委派；
  - MCP 服务说明和开场白不会说两套话。
- **局限**：
  - 账单还没按段拆分（第二步）；
  - DSH 和远端 OMP 还拿不到开场白（第三步）；
  - 开场白对 Agent 实际行为的影响要等 H8 的评测才知道。
- **验证**（在 Mac mini 上跑）：
  - 新增 3 个单测：
    - 用途说明在上限内、包含 MCP 那一句、没有硬规则、没接工具时写明；
    - 指路只给标题、放不下的计数、两行各有份额；
    - 三段顺序、总上限、超出时先去掉指路。
  - 执行器测试核对：Codex 的 `developerInstructions`、Claude 的 `--append-system-prompt`、OMP 的开场内容都以用途说明开头并带工具清单那一句；没有工具服务器时写明没有工具、不给指路；有交接简报时简报接在后面。
  - 两条宿主测试按"开场白在前"改了期望值。
