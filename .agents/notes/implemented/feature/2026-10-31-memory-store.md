# Agent Note: 记忆地基（B5-1）：事实与画像、/记住、Agent 提议、遗忘屏障

Status: implemented

## Problem

每个会话都从零开始。用户的语言、习惯和项目约定，每开一个会话都要重说一遍。路线文档 §6 要求的记忆有几条前提：

- Aeroric 是唯一写者；
- 只追加，修改时用"取代"标记，不覆盖；
- 模型只能提议，不能直接写；
- 每条记忆都要有证据；
- 遗忘之后，同样的内容不能被重新加回来。

B5 一次做完太大。owner 2026-10-31 定了 Q-M1–Q-M8：拆成三批，先做不额外调用模型的 B5-1。之后 owner 又确认了草图和 R2-1–R2-3：

- R2-1：画像在所有会话都注入；项目事实和记忆工具只在开启了记忆的项目里提供；第一次在项目里 `/记住` 时自动开启这个项目的记忆。
- R2-2：`/记住` 默认写到当前项目，卡片上可以改为全局。
- R2-3：记忆入口放在侧栏顶部，项目右键菜单里另加"项目记忆…"。

## Decision

**存储**（协议 `memory.rs`，core 新的顶层模块 `memory/`）

- 数据库是 `<data>/memory/memory.db`（SQLite）：
  - `items`、`evidence` 两张表；
  - FTS5 全文索引 `items_fts`，正文先用 `notebook::rag::cjk::segment` 切开中文；
  - `barrier` 存遗忘签名；
  - `projects` 记每个项目的记忆开关。
- 作用域有全局和项目两层。
- 条目分两类：
  - `profile`（关于你），类别有语言、习惯、偏好、限制；
  - `fact`（项目上下文）。
- `assertion` 由 core 按调用来源设置：
  - `memory.remember` 记为 userExplicit；
  - `context.memoryPropose` 先是 pending，用户确认后变成 agentConfirmed；
  - `MemoryDraft` 用 `deny_unknown_fields`，客户端带了 assertion 字段就会被拒绝。
- 文本从不原地修改：
  - 修改 = 插入一条新的，旧的标为 superseded，并指向新的；
  - 同一作用域里，同样的话（规范化后相同）只追加一条证据；
  - 用户说出 Agent 已经提议过的话，那条提议直接变成 active。

**遗忘**

- 永久遗忘会删除这条记忆和它取代过的所有旧版本：items、evidence、FTS 三处都删。
  - 数据库开着 `secure_delete`，删除后再做一次 `wal_checkpoint(TRUNCATE)`；
  - 测试确认数据库文件和 WAL 里都找不到原文。
- 删除前，对每一版的规范化文本算 `HMAC-SHA256`，作为签名写进 `barrier`。
  - 密钥是 `<data>/memory/barrier.key`，32 字节随机数，权限 0600，不进钥匙串。
- 签名的作用：
  - Agent 再提议同样的内容，一律拒绝；
  - 用户再 `remember` 同样的内容，先解除签名再写入，因为这是一次新的明确意思；
  - 用户"拒绝"一条提议，按遗忘处理，免得 Agent 反复提。
- "撤销"只用在 `/记住` 刚写完的时候：直接删除，不留签名。

**注入与检索**

- 画像在会话启动或恢复时交给模型：
  - `executor.hand_brief` 先拼出画像，再把它放在交接清单前面，合成一段 instructions；
  - Claude 走 `--append-system-prompt`，Codex 走 `developerInstructions`；
  - 驱动不支持 instructions 时，画像不会塞进用户消息。
- 画像的内容：
  - 全局的 profile 一律带上；
  - 项目开启了记忆，再带上这个项目的 profile 和 fact；
  - 置顶的排在前面，总长控制在 1200 字以内，超出部分写成"还有 N 条未列出，可用 memory_recall 检索"。
- MCP 工具 `memory_recall` 和 `memory_propose`：
  - 只在项目开启了记忆时出现在工具列表里。`tools/list` 时 CLI 会问宿主 `context.memoryEnabled`，宿主连不上时不列出；
  - recall 用 FTS5 bm25 检索，查询词之间是 OR；
  - 排序：本项目的在全局前，然后置顶的，然后用户自己说的；最多返回 8 条；
  - 没有结果时，原样回"没有找到相关记忆。"。
- 写入前做密钥扫描：
  - 复用诊断报告的脱敏规则，另加 `ghp_` 和 `github_pat_`；
  - 命中就拒绝写入，并说明原因。

**界面**

- 新增工作区分区 `WorkspaceSection.memory`，放在侧栏导航最上面，有待确认的条目时显示数字。
- 项目右键菜单加"项目记忆…"（`ProjectRowAction.memory`）。
- 记忆页 `MemoryPage` 和 `MemoryStore`：
  - 顶部可以在全局和各项目之间切换；有"这个项目用记忆"开关和搜索框；
  - 五个标签，后三个是空状态，说明在 B5-2、B5-3 或做梦功能里开放；
  - 待确认的条目排在最前，行内有确认和拒绝；生效中的条目，置顶的排前；
  - 历史版本（已取代、已归档）默认折叠；
  - ⋯ 菜单里有：修改、置顶、改为全局、归档、永久遗忘；
  - "关于你"标签最下面，只读展示各 Harness 自己的记忆文件（`memory/native.rs`）。
- `/记住 …` 在 `LiveSessionStore.send` 里被拦下来，不发给 Agent；输入框上方出现"已记住"卡，带"改为全局""撤销"。
  - kind 由一张小词表猜：以"我""回复""以后"这类词开头的算 profile，其余算 fact。
- "需要我处理"新增"记忆待确认"，挂在提议它的会话下，点开跳到记忆页。

## Alternatives considered

- **用 JSON 文件存**，像委派和黑板那样：记忆会越积越多，还要按中文关键词检索，JSON 撑不住（Q-M2）。
- **把画像写进仓库的 CLAUDE.md / AGENTS.md**：会改用户仓库里的文件，而且和原生记忆成了两个权威（§6.4）。
- **每个回合都注入画像**：浪费上下文；画像只在进程启动时进入系统提示就够了。
- **遗忘只标记、不物理删除**：原文还在库里，违背 §6.6"永久遗忘"；所以只留不含原文的签名。
- **记忆工具始终列出，在调用时拒绝**：违背 Q-F3"记忆按项目开启"；模型也会白白看到两个用不了的工具。
- **新建一个 MemoryServiceAdapter.swift 文件**：App 的 Xcode 工程由 project.yml 生成，加文件要改工程。所以适配层放进了现有的 `LiveSessions.swift`。

## Consequences

- 与路线文档的偏差和已知限制：
  - 正在运行的会话看不到新记住的内容，下一个新开或恢复的会话才会带上；卡片的悬停提示里写明了这一点。
  - 记忆工具在会话启动时就定下来了。项目中途开启记忆，正在跑的会话要重开才会有这两个工具。
  - omp、DSH、远程会话不注入画像，也没有记忆工具。
  - "需要我处理"里的记忆条目挂在提议它的会话下，没有会话来源的提议只计入侧栏数字。
  - 原生记忆文件只读，不进索引，也不注入。
- 测试：
  - core 9 个：去重与自动开启、提议与拒绝屏障、取代与连同旧版本遗忘（数据库和 WAL 里都没有原文）、密钥与撤销、画像预算与置顶、中文检索与作用域、归档/置顶/移动、规范化、原生文件；
  - 协议 1 个；
  - 宿主端到端 1 个：记住 → 新会话 `developerInstructions` 带上画像；提议 → 进 attention → 确认 → 能检索到；遗忘后再提议被拒；项目关闭记忆后不能检索；
  - CLI 1 个；
  - Swift 6 个：命令解析、文字、解码、store 分组与动作、attention、`/记住` 不发给模型。
- 没有发过真实模型请求。真实界面没有运行过（NOT RUN），等 owner 目检。
