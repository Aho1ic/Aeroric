# Agent Note: B7 重跑对比写明输入是否一致

Status: implemented

## Problem

[调研落地批次 B](../../proposed/feature/2026-11-15-adoption-b-acceptance-and-artifacts.md) 的 B7。[换模型重跑](2026-11-11-rerun.md)的比较卡把原回合和各个重跑并排列出，但没有说明两边是不是从同样的输入出发：

- 重跑组只存了起点树、用户发出的消息、是否带摘要，以及每个重跑的配置和模型；
- 用户在发起面板里改过的消息，看不出和原回合有没有不同；
- 原回合带着整段对话，重跑只带"已确认的决定"或者只有消息；比较卡只写"带了已确认的决定"，没有当成输入的差别；
- 每个重跑的权限按配置决定，可能各不相同，没有记录；
- 副本是否真的从起点树开始，也没有核对过。

结果不同时，用户无从判断差别来自模型还是来自输入。

## Decision

**发起时冻结输入清单，存进重跑组**（`core/crates/aeroric-core/src/sessions/rerun.rs` 的 `RunInputs`）：

- 原回合（`RerunGroup.original_inputs`）：
  - 起点：回合开始前的快照树；
  - 提示词：App 发起面板最初显示的消息（`rerun.start` 新增的 `originalMessage`）的哈希；
  - 上下文：会话的第一轮是"只有消息"，之后的轮次是"完整对话"；
  - 权限、Harness、模型：取自原会话的记录。
- 每个重跑（`RerunRun.inputs`）：
  - 起点：副本建好之后对副本本身做一次快照得到的树（`CopyRecord.started`，在 `isolated_copy::create_from` 里读回）。这是 Agent 实际看到的代码，不是"应该是"的那棵树；
  - 提示词：实际发出的消息的哈希；
  - 上下文：`brief:<摘要的哈希>` 或"只有消息"；
  - 权限：这个重跑实际提交的权限模式；
  - Harness、模型：这个重跑的目标。
- 技能及版本暂时没有地方记录（批次 C 的 C7），一律为空，显示"未记录"。
- 哈希是去掉首尾空白后文字的 SHA-256 前 16 位。

**比较**（`rerun::compare_inputs`，`rerun.list` 每组新增 `inputs`）：

- 每项输入一行，依次列出原回合和各个重跑的值，结论分为相同、不同、未记录；Harness 与模型是要比较的东西，单独标出，不算差别。
- 摘要只依据记录，按下面的顺序给出：
  1. 重跑之间就有不同："重跑之间有 N 处输入不同（起点…），结果的差异不一定来自模型"；
  2. 重跑之间一致、和原回合不同："重跑之间输入一致；和原回合比，提示词、上下文不同，结果的差异不一定来自模型"；
  3. 起点、提示词、上下文、权限中有未记录的："说不出输入是否一致：…未记录"；
  4. 其余："输入一致，只换了 Harness 和模型"。
  - 技能未记录时，末尾加"技能未记录"，但不妨碍其他几项下结论。
- B7 之前建的重跑组没有清单，写"这组重跑早于输入记录，说不出两边的输入是否一致"。未记录永远不当作相同。
- 重跑组本来就按原会话存盘，宿主重启后比较照常能读，这一点不用改。

**App**：比较卡标题下面加一行摘要，有差别或说不清时用警示色。点开后列出"相同：…"，以及每项不同或未记录的输入在各列的取值。

## Alternatives considered

**宿主从会话记录里取出原回合的用户消息。** 最强的理由是不依赖 App 传过来的参数。没选：会话记录里的消息不带时间，Codex 等会把环境说明当作用户消息写进记录，按轮次去数消息容易错位，算出来的哈希一错，就会凭空报出"提示词不同"。App 发起面板最初显示的就是用户在那一轮看到的消息，用它最准。

**发起时只记要求的起点树，不读回副本。** 最强的理由是省一次快照。没选：方案要求"输入一致"必须有记录支撑；副本是把未提交的改动打补丁打进去的，补丁失败或漏了文件时，要求的树和实际的树就会不同，只有读回才知道。

**把上下文的差别（原回合带着完整对话）当作必然，不算差别。** 最强的理由是几乎每次比较都会因为它而提示。没选：它确实可能是结果不同的原因。摘要把"重跑之间"和"和原回合比"分开写，用户能看出重跑之间的比较仍然公平。

## Consequences

- **收益**：比较卡上"输入一致"的结论来自发起时的记录；不一致时写明是哪一项、各列各是什么。
- **代价**：
  - 建副本时多做一次快照，大仓库会多花几秒；
  - 原回合的权限取的是发起重跑时会话的权限，原回合之后改过权限就不准。原回合的权限当时没有记录，这是能拿到的最近的值。
- **没做**：
  - 技能版本（等 C7）；
  - 方案第 5 条，用 B6 的交付物版本作比较对象。现在比较卡的改动数仍然来自回合账本。
- **验证**：
  - `rerun.rs` 新增 3 个测试：
    - 输入相同时写"只换了 Harness 和模型"，技能显示未记录；
    - 提示词、上下文、权限不同时逐项写出，重跑之间起点不同时摘要先说这一条；
    - 未记录的输入从不算相同，旧的重跑组明说无法判断。
  - `isolated_copy_tests` 里，从早先快照建的副本，读回的 `started` 等于那棵快照树。
  - Swift `testTheCardSaysWhetherTheInputsMatched`：解码 `inputs`，每行文字正确；旧宿主不发 `inputs` 时为空。
  - `rerun.start` 和 `rerun.list` 的宿主接线没有集成测试（R5-2 也没有），比较卡的新行待目检，记在路线文档 §8。
