# Agent Note: H7 第一步：后台整理时把各家原生记忆当证据读

Status: implemented

## Problem

[各 Harness 原生融合](../../proposed/architecture/2026-11-16-harness-native-capabilities.md) H7 第 1 条：用户在 Claude 里让它“记住”的事，换到 Codex 也要能用上，但要先经用户确认。

§8 第 3 问已定：整理时把各家原生记忆文件当候选证据读；产出一律走提议和确认，不直接生效，不回写。路线文档 §6.4 原来写的是“只读并展示”“可选择导入为候选”，这一条要原地放宽。

动手前（`main@7216ab41`）核对的事实：

- `memory/native.rs::discover` 能找到这些文件：
  - Claude 的用户级 `CLAUDE.md`、这个项目的自动记忆 `projects/<编码后的项目路径>/memory/MEMORY.md`；
  - Codex 的 `AGENTS.md` 和 `memories/*.md`；
  - 项目里的 `CLAUDE.md`、`AGENTS.md`；
  - 受管目录也算。
- 记忆页有手动“导入为候选”（`memory.importNative`）：用 `import_lines` 把文件逐行拆成候选，交给 `Memory::propose`。
- `propose` 已有两条去重：
  - 同一范围、同一规范化文字的条目不会再插一条；
  - 用户拒绝过的文字被“遗忘屏障”挡住。
- 后台整理（`dream_due_scopes`）只在打开了“后台学习”、所有会话空闲时，逐个范围（全局和每个启用了记忆的项目）跑；其中的过时检测不需要模型。

## Decision

**每次后台整理的每个范围**，先读一遍原生记忆文件（`Memory::harvest_native`），不调模型：

- **内容没变不读**：按“范围 + 路径”记下文件内容的摘要，存在记忆目录的 `native-read.json`。摘要没变就跳过，所以同一份文件不会每次都产生一批提议。
- **项目和用户的文件分开**：
  - 项目自己的文件和 Claude 对这个项目的自动记忆，变成这个项目的事实提议；
  - 用户级的文件，变成全局画像提议；
  - 没有项目范围时，项目的文件留给它自己的项目。
- **逐行**用现有的 `import_lines` 拆，交给 `propose`：
  - 已有的不重复；
  - 用户拒绝过的不再出现；
  - 一份文件一次最多 20 条新提议。
- **证据写明来源路径**：摘录是“路径 · 原文”。路径写成短的形式：家目录写 `~`；Claude 那个由整条项目路径编码出来的文件夹写 `<本项目>`。原因是摘录上限 200 字，完整路径本身就可能超过。
- **文件只读**：不写、不改、不注入。用户在记忆页确认了才算 Aeroric 的记忆，之后经 Aeroric 的入口（开场白、`memory_recall`）给到所有 Harness。

`native.rs` 的文件头和路线文档 §6.4 已原地更新。

## Alternatives considered

**整份文件交给分析模型提炼，再提议。** 最强的理由是能合并、改写成更好的条目。没选：

- 每份文件每次改动都要调一次模型；
- 逐行提议已经覆盖“记住了什么”这一层，合并重复是做梦本来就做的事。

以后做梦遇到这些提议，会和其他条目一起比对。

**每次整理都重读全部行，靠去重挡住重复。** 没选：用户拒绝的行虽然被屏障挡住，但没被拒绝、也没确认的行会一直留在待确认里；按内容摘要只读一次更省，也不吵。

**证据结构加一个“来源路径”字段。** 最强的理由是路径完整、不占摘录的篇幅。没选：要给证据表加列、迁移数据，Swift 端也要跟着改；短路径已经能让人认出是哪份文件。

## Consequences

- **收益**：
  - 在 Claude 里记下的东西，会以带来源的提议出现在 Aeroric 的待确认列表里；确认后，四族都能用上；
  - 各家的记忆文件一个字节都不会改。
- **局限**：
  - 只在打开“后台学习”且会话空闲时读；
  - 逐行拆，一行里有两件事不会拆开，几行说一件事也不会合并；
  - 文件改动后，旧的、没确认的行还留在待确认里，要用户自己处理；
  - 证据里的路径是缩写；
  - 第 2 条（升降）、第 3 条（对照原文纠错）是后面两步。
- **验证**（在 Mac mini 上跑）：
  - 一份项目的 Claude 自动记忆和一份用户级 `CLAUDE.md`：
    - 前者变成这个项目的两条待确认事实，后者变成一条全局画像，证据以短路径开头；
    - 项目文件的字节不变；
    - 第二次读时内容没变，一份都不读；
  - 用户拒绝一条之后改文件：
    - 只读这一份，只多出新的一行；
    - 被拒绝的那行不回来；
  - 没有项目范围时，项目的文件不产生提议；短路径的写法正确。
