# Agent Note: C1 第二步：记忆页可以"查看原话"

Status: implemented

## Problem

[C1 第一步](2026-11-19-c1-evidence-knows-its-message.md)已经让新抽取的记忆依据记下原话所在的消息和位置，宿主的 `memory.evidenceLocate` 也能核对来源现状。但 App 里，记忆展开后只显示一行"依据：…"摘录，没有入口去看原文。方案里 C1 的第 4 条（依据行加"在会话里查看"）和第 5 条（旧记忆显示"来源位置没有记录"）都还没做。

## Decision

**入口**（`macos/AeroricKit/Sources/AeroricUI/Memory/MemoryPage.swift`）：

- 记忆展开后，"依据：…"摘录右边加一个"查看原话"。待确认的候选默认就是展开的，所以新抽取出来的候选可以直接点。
- 行尾的"…"菜单里也加一项"查看原话…"。
- 只有来自会话的依据才出现这个入口。`/记住` 的依据和从记忆文件导入的依据，本来就没有会话可查，不出现。
- 打开哪一份依据：先选记下了位置的那份；都没记位置时，选第一份来自会话的，面板会说明"没有记录"。

**面板**（`MemoryEvidenceSheet`）：

- 标题"原话"，下面一行是这条记忆的文字。
- 打开时调用 `memory.evidenceLocate`，用一句话说明核对结果：
  - 原话在来源会话的第 N 条消息里（你说的 / Agent 说的）；
  - 来源会话之后改过，原话现在在第 N 条消息里；
  - 原文之后改过，原话已经不在了；
  - 原文已不在：来源会话或它的记录已被删除；
  - 这条记忆的来源位置没有记录。
  
  第一种用普通颜色，其余四种用警示色。
- 找到时显示那条消息，原话加底色加粗。原话前最多显示 400 字、后最多显示 1200 字，消息还有内容的地方用"…"标出，原话不会落在滚动区域之外。找不到时显示当时记下的摘录。
- 宿主给的位置按字符（Unicode 标量）计数，App 也按标量切分，不按 Swift 的字形簇。所以表情、组合字符前后的位置不会错开。
- 来源还在时有"打开这个会话"，点了关掉面板，打开那个会话。
- 读取失败时写"读取原文失败：…"及原因。

## Alternatives considered

**按方案直接跳进会话，滚到那条消息并高亮。** 最强的理由是原话就在上下文里，前后对话一目了然。没选：两边的"第几条"对不上。

- 宿主的序号按"有文字的消息"计数，是读会话记录文件得到的；
- 会话页显示的是实时会话的回合与事件，工具调用、压缩提示也各占一行，两边没有可以对齐的同一个编号。

硬要对齐，就要在会话页里再按原话找一遍，而长会话是分页加载的，原话可能不在已加载的页里。先在面板里展示原话和它所在的消息，再给"打开这个会话"，能核对到原文，又不会把人带到一个找不到原话的地方。

**把原话位置画在会话页的滚动条上。** 理由同上，缺少共同的编号，暂不做。

## Consequences

- **收益**：用户能看到一条记忆依据的是哪句原话、原话在哪条消息里；来源被改写或删除时，能看到明确的说明，而不是一个打不开的链接。
- **局限**：
  - 不能直接定位到会话页里的那一行；
  - 第一步之前抽取的记忆没有记下位置，只会显示"没有记录"和摘录。
- **验证**：
  - 新增 Swift 测试 `MemoryEvidenceSourceTests`，4 个：
    - 依据位置和核对结果的解码；
    - 五种结果各自的文字；
    - 按标量切出原话，含表情和组合字符，长消息只留原话附近的内容，越界的位置不崩溃；
    - 选哪份依据、什么时候不出现入口。
  - 界面待目检，记在路线文档 §8。
