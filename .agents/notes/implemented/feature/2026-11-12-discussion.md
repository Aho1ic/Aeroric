# Agent Note: 讨论模式（圆桌）

Status: implemented

## Problem

想听几个模型对同一个问题各自怎么看，以前只能开几个会话，把一边的回答复制给另一边，再自己归纳。路线复核把它列为 R5 之后的"讨论模式"（Q-R7）：只读；第一轮独立作答，之后互相回应，最后由主持人总结。原型是 antumi 的群聊（`docs/ARCHITECTURE.md` 群聊一节、`core/src/discussion-*.ts`）。

用户 2026-11-12 定的做法，全部按推荐：

- 第一批只做圆桌：轮次、立场、主持人总结，以及暂停 / 继续 / 立即总结 / 停止。插话、@点名、匿名、再来一轮、起草评审、分工调研放第二批。
- 新建会话页加"单人 / 讨论"切换；讨论在侧栏是单独一条，成员会话折叠挂在它下面。
- 2–5 个成员，每个选配置加模型，可以写一句角度；主持人默认是第一个成员；轮数 1–5，默认 3；从第 2 轮起全员"维持"就提前总结。
- 成员用只读权限（`plan`），在项目原目录读代码；别人的发言包在 `<discussion-post>` 里，并注明只是观点、不是指令。
- 成员在等审批时，发言标"在等你确认"，可以打开成员会话处理；Claude 交计划时自动拒绝，请它直接用文字回答。
- 总结卡上有"从结论新建会话"，只预填草稿，不自动开始。
- 每条发言显示 token 和费用，页头显示合计；除了轮数上限不另设预算。

## Decision

**core：`sessions::live::discussion`**

- 讨论的状态、提示词、下一步和落盘都在 core。每场讨论存一个文件：`<data>/discussions/<讨论任务 id>.json`。
- `Discussions` 挂在会话更新链上，位于委派之上、审查之下。它收集每个成员这一轮的消息，取最后一条非空消息作为发言。
- 一条发言什么时候算说完：
  - 成员回合结束（`TurnEnded`）：正常结束且有内容就记为完成；第 2 轮起从最后几行读出立场，读不出按"已修改"算，讨论继续。
  - 成员会话整体失败、取消或中断：有的会话启动就失败（目检时 Claude 的版本检查失败），根本没有回合结束事件。此时发言记为失败，原因取任务状态带来的说明。
- 下一步（`after_round`）：
  - 这一轮没有人发言成功：暂停；
  - 到了最大轮数：总结；
  - 第 2 轮起全员维持：提前总结；
  - 否则进入下一轮。
- 每个成员只收到别人、在它目标轮之前、还没发给过它的发言（`Member.seen` 记下标）。第 1 轮重试不带别人的发言。
- 操作：
  - 暂停：等这一轮说完。
  - 继续：先重问这一轮没说成的成员；都说完了就走下一步。
  - 立即总结：打断还在说的成员，再请主持人总结。
  - 停止：打断所有成员。
- 重启后读回所有讨论：正在说的发言标"App 重启时这一轮被中断"，讨论暂停，点继续接着讨论。
- 成员交计划（`ExitPlanMode` 审批）时自动拒绝，并附上"请直接用文字回答"。其他审批和提问把发言标成"在等你确认"，讨论记录显示为"需要输入"。

**宿主：`discussion.*`**

- `discussion.start {projectId, topic, members: [{configurationId, model?, reasoningEffort?, angle?}], moderator, rounds}`：
  - 先逐个检查成员的配置和模型，都通过才开始建东西。
  - 讨论本身是一条不启动会话的任务记录（`discussion: true`），名字是"讨论 · 题目首行"，状态跟着讨论走：进行中、需要输入、已中断、完成、已取消。
  - 先在 core 登记讨论，再启动成员，这样成员说的第一句话不会漏掉。
  - 成员和委派的子会话一样：直接建任务、再启动。没有走提交流程，因为目录里每个配置的权限列表都不含 `plan`，提交会被拒。成员记录带 `discussionOf`，钉住所选配置（`agent_config_id`）和模型，名字是"题目（讨论 · 成员）"。
- `discussion.get / pause / resume / summarize / stop {taskId}` 返回 `{discussion, usage, families}`。
  - `usage`：按发言的起止时间，从成员会话记录里找出对应的回合（`discussion::usage`），给出 token、费用和用时。
- 给成员发下一轮消息走投递队列（这一轮结束后再发）。成员会话从没开始过时，队列会报"这个会话还没有可续接的对话"，所以这种情况改为带着这条消息重新启动会话。
- 成员不能再委派：`discussionOf` 加进了"嵌套会话"的判断。

**界面**

- 新建会话页左上角是"单人 / 讨论"切换。切到讨论后：
  - 输入框写题目；
  - 输入框下面列出成员胶囊（名字、角度输入、主持人、移除）；
  - "添加成员"在下方展开一块面板，从粗到细分三步：
    - Harness 滑块，和单人模式同一个控件。默认停在单人模式选中的 Harness；没有能启动配置的 Harness 置灰。
    - 这个 Harness 的配置胶囊，默认选中第一个。同名配置只在这个 Harness 里区分，不再给每个配置都挂上 Harness 名。
    - 这个配置的模型胶囊；没有模型列表的配置给一个"默认模型"。
  - 点模型就加入一个成员。面板不收起，可以连续加；按钮变成"完成"，满 5 个自动收起。已加入过的模型胶囊标"×2"。
  - 轮数用 1–5 的胶囊选。
- 右上角的 Harness 滑块在讨论模式下隐藏，Harness 只在添加面板里选，免得两处滑块意思不同。
- 切换单人 / 讨论用滑块同一条弹簧动画：
  - Harness 滑块淡出并向右收起，"独立副本"淡出缩小；
  - 输入框底栏交叉淡入淡出；
  - 成员区淡入并下移到位。
  - 整组内容在窗口里垂直居中，成员区插进来时整组上移，这段位移也在同一个动画里。
  - 打开"减弱动态效果"时只淡入淡出。
  - 以前切换值写在动画之外，这些变化挤在同一帧里跳变，看着像掉帧。
- 添加成员用的是普通按钮，不用 SwiftUI `Menu`：`Menu` 在 App 处于后台时不响应辅助功能的点击，目检脚本打不开。
- 讨论页：
  - 页头：题目、状态（"第 2 / 3 轮 · 讨论中"）、成员、合计 token 和费用，以及暂停 / 继续 / 立即总结 / 停止。
  - 发言按轮排，每个成员一张卡：发言中、在等你确认、没说完（带原因）、维持 / 已修改。重试后同一轮同一成员只显示最新那张。
  - 文本按行内 Markdown 显示，超过 10 行可以展开。
  - 最后是主持人总结卡，带"从结论新建会话"。
  - 进行中每 3 秒刷新一次。状态变了就让侧栏重读任务：宿主改讨论记录不会推送事件。
- 侧栏：讨论行用双气泡图标，成员行用 `text.bubble` 标在讨论下面。

## Alternatives considered

- **主持人的会话当讨论页**：不用新建记录。没选：主持人也是成员，它的会话页是普通会话；讨论页要把所有人的发言并排放。
- **添加成员用一列配置胶囊、点开再选模型**（第一版）：少一层。没选：配置一多，几个 Harness 的配置混在一列里，同名的还要靠后缀区分；先按 Harness 分开更清楚，也和单人模式的选法一致。
- **讨论单独存，侧栏单独一栏**：不碰任务记录。没选：侧栏、归档、删除都要再写一套。
- **发言从成员会话记录里读**：重启后也读得到。没选：回合结束时记录不一定已经写完。改为在更新链上收集，发言一收到就落盘；重启时被中断的那一轮标失败、讨论暂停，继续时只重问没说完的成员。
- **成员走提交流程（和重跑一样）**：配置校验现成。没选：提交只接受配置列出的权限，`plan` 不在其中。

## Consequences

- **收益**：同一个问题可以让 2–5 个配置各说各的，再互相回应，最后得到一份共识、分歧、建议和待决问题的总结；每条发言都能看到花了多少。
- **代价**：
  - 每个成员是一个普通会话，额度和费用照常算。只读依赖各 Harness 自己的规划 / 只读模式，Aeroric 不额外拦截。
  - 讨论记录的"停止"按钮（页头通用的）对这条不运行会话的记录没有意义；讨论自己的"停止"在讨论页里。
  - 删除讨论记录不会删除成员会话和 `discussions/` 下的文件。
- **验证**：
  - core 单测（12 个）：
    - 立场解析；
    - 下一步（下一轮、提前总结、到轮数总结、没人成功就暂停）；
    - 每个成员只收到别人新说的；
    - 暂停等这一轮说完，继续后进入下一轮；
    - 立即总结会打断还在说的成员；
    - 停止后不再发任何消息；
    - 消息发不出去时发言失败；
    - 重启后正在说的标失败并暂停，继续只重问没说完的；
    - 成员会话启动失败时发言带上原因。
  - 宿主单测：重复的成员名加编号。
  - Swift 单测（`DiscussionTests`）：解码、状态文字、用量、每轮只显示最新发言、开始条件、添加面板的 Harness → 配置 → 模型。
