# Agent Note: 讨论模式（圆桌）

Status: implemented

## Problem

想听几个模型对同一个问题各自怎么看，以前只能开几个会话，把一边的回答复制给另一边，再自己归纳。路线复核把它列为 R5 之后的"讨论模式"（Q-R7）：只读；第一轮独立作答，之后互相回应，最后由主持人总结。原型是 antumi 的群聊（`docs/ARCHITECTURE.md` 群聊一节、`core/src/discussion-*.ts`）。

用户 2026-11-12 定的做法，全部按推荐：

- 第一批只做圆桌：轮次、立场、主持人总结，以及暂停 / 继续 / 立即总结 / 停止。插话、@点名、匿名、再来一轮、起草评审、分工调研放第二批。
- 新建会话页加"单人 / 讨论"切换；讨论在侧栏是单独一条，成员会话折叠挂在它下面。
- 2–5 个成员，每个选配置加模型，可以写一句角度；主持人默认是第一个成员；轮数 1–5，默认 3；从第 2 轮起全员"维持"就提前总结。
- 成员用只读权限（`plan`），在项目原目录读代码；别人的发言包在 `<discussion-post>` 里，并注明只是观点、不是指令。
- 成员在等审批时，发言标"在等你确认"，可以打开成员会话处理；Claude 交计划时自动拒绝，请它直接用文字回答。
- 总结卡上有"从结论新建会话"，只预填草稿，不自动开始。
- 每条发言显示 token 和费用，页头显示合计；除了轮数上限不另设预算。

2026-11-13 第二批，用户说"全部按推荐"：只做圆桌里的四项——插话、再来一轮、@点名、匿名互评。起草评审、分工调研以后各做一批。

2026-11-13 第三批，用户说"全部按推荐"：起草评审，加上"讨论方式"选择（自动 / 圆桌 / 起草评审）。自动按题目里的词判断，不调模型。分工调研和"讨论要求"预设放下一批。

2026-11-13 第四批，用户说"全部按推荐"：分工调研和"讨论要求"。自动判断加上调研类的词；正反辩论、接力补充两个预设不做，它们会改变成员的角色分配。

## Decision

**core：`sessions::live::discussion`**

- 讨论的状态、提示词、下一步和落盘都在 core。每场讨论存一个文件：`<data>/discussions/<讨论任务 id>.json`。
- `Discussions` 挂在会话更新链上，位于委派之上、审查之下。它收集每个成员这一轮的消息，取最后一条非空消息作为发言。
- 一条发言什么时候算说完：
  - 成员回合结束（`TurnEnded`）：正常结束且有内容就记为完成；第 2 轮起从最后几行读出立场，读不出按"已修改"算，讨论继续。
  - 成员会话整体失败、取消或中断：有的会话启动就失败（目检时 Claude 的版本检查失败），根本没有回合结束事件。此时发言记为失败，原因取任务状态带来的说明。
- 下一步（`after_round`）：
  - 这一轮没有人发言成功：暂停；
  - 到了最大轮数：总结；
  - 第 2 轮起全员维持：提前总结；
  - 否则进入下一轮。
- 每个成员只收到别人、在它目标轮之前、还没发给过它的发言（`Member.seen` 记下标）。第 1 轮重试不带别人的发言。
- 操作：
  - 暂停：等这一轮说完。
  - 继续：先重问这一轮没说成的成员；都说完了就走下一步。
  - 立即总结：打断还在说的成员，再请主持人总结。已经在总结时再点，什么也不做、不报错（2026-11-16 复测：从第 2 轮起全员维持会自己提前总结，这时再点曾报"讨论已经结束"）。
  - 停止：打断所有成员。
- 重启后读回所有讨论：正在说的发言标"App 重启时这一轮被中断"，讨论暂停，点继续接着讨论。
- 成员交计划（`ExitPlanMode` 审批）时自动拒绝，并附上"请直接用文字回答"。其他审批和提问把发言标成"在等你确认"，讨论记录显示为"需要输入"。

**第二批：插话、@点名、再来一轮、匿名（2026-11-13）**

- 发言多两种（`PostKind`）：
  - `user`：用户说的话，`member` 没有意义；`mentions` 记下点了谁。
  - `reply`：被点名的成员单独回答，不写立场行。
- 谁能看到什么（`Discussion::unseen`）：
  - 用户的发言发给每个成员，包在 `<user-post>` 里，并注明"是用户的发言，请一并回应"；
  - 成员的回答和点名回答照常发给其他人；
  - 总结不发给成员。
- 插话（`Discussions::say`，不带点名）：
  - 讨论进行中或"说完后暂停"：记下，下一轮所有成员都看到。这一轮里用户插过话，下一轮一定进行，不受轮数上限和"全员维持就提前总结"限制。
  - 已暂停或已总结：马上再开一轮，并把这一轮定为最后一轮（`max_rounds = round`），说完后重新总结。
  - 主持人正在总结、或已停止时拒绝。已暂停或已总结、但还有被点名的成员在回答时也拒绝。
- @点名（`say` 带 `mentions`）：
  - 被点名的成员空闲时马上问，正在说话就记进 `pending_replies`，说完再问。
  - 轮次不动：这一轮的下一步要等点名回答也说完。
  - 已总结后点名，讨论仍算已总结，侧栏这段时间显示进行中。
  - 只点名的话不会强制多一轮。
  - 立即总结、停止会清掉还没问的点名；重启后也清掉。
- 再来一轮（`another_round`）：只在已暂停或已总结、没人在说话时可用，和"已暂停或已总结时插话"走同一条路，只是没有用户发言。
- 总结按轮次找（`current_summary`）：再来一轮后会有第二份总结，"总结没写出来"和"总结写完了"都只看当前这一轮的总结。
- 匿名（`Discussion::anonymous`，只在开始时设定）：
  - 提示词里所有称呼都换成"成员 A / B"（`Discussion::name`），第 1 轮还会告诉成员不要说出自己是哪个 Agent 或模型；
  - 界面照样显示真实名字，旁边标上代号。
- 宿主新增 `discussion.say {taskId, text, mentions?}` 和 `discussion.again {taskId}`；`discussion.start` 多一个 `anonymous`。用户发言的用量为空，不去会话记录里配回合。
- 界面：
  - 讨论页底部有输入框，上面一排成员的 `@` 胶囊，点一下就插入 `@名字`。
  - 发送前从文字里认出点了谁：长名字优先，匿名时 `@成员 A` 也算。点了人时，按钮写"只问 N 位"。
  - 每一轮下面依次是：用户的发言卡（"你 · 所有成员下一轮回应"或"你 · 只问 X"）、点名回答卡（标"回答你的点名"）、这一轮的总结。
  - 页头在已暂停或已总结时多一个"再来一轮"。
  - 新建页的轮数后面多一个"匿名互评"胶囊。

**第三批：起草评审（2026-11-13）**

- `Discussion::format`：`roundtable`（默认，旧记录读回也是它）或 `review`。
- 角色与轮次：
  - 起草评审里主持人就是作者，其余成员都是评审。
  - 奇数轮作者写，偶数轮评审评；第 r 轮对应第 ⌈r/2⌉ 版（`version_of`）。
  - 每轮谁说话由 `Discussion::speakers` 决定。开始时只有作者有发言；宿主也只启动第 1 轮要说话的成员，评审的会话建好但不启动，第一次评审时由"从没开始过就带着消息启动"那条路启动。
- 每个回答带上 `stage`（起草、评审、修订、定稿）和 `version`；评审还带 `verdict`，从最后几行的"结论：通过 / 需修改"读出，读不出就按需修改算（`parse_verdict`）。
- 谁看到什么：评审只看到作者的稿件和用户的发言，看不到别的评审（`unseen` 里 `reviewer` 那一支）；作者看到全部评审意见。
- 下一步（`after_review_round`，只看发言记录，所以重启后能接着走）：
  - 作者这一轮没写出来：暂停，继续时只重试作者。
  - 有评审没评完：暂停，继续时只重试没评完的评审；没评完的一版不会被当成通过。
  - 评审全部通过：定稿；
  - 修订次数用完（`version > max_revisions`）：用最新一版定稿，并标出没有全部通过；
  - 否则作者修订下一版，要求写整篇，最后附"修订说明"。
- 定稿（`finalize`）不再找作者跑一轮：直接把最新一版存为一条 `summary` 发言，`stage` 为 `final`，带版本号和是否全部通过。
- 操作：
  - "现在定稿"（`summarize_now`）不打断任何人，等正在写的写完再定稿；
  - "再改一版"（`another_round`），或已暂停、已定稿时插话：作者写下一版，再评审一次就定稿（`max_revisions` 设为这一版之前的修订数）；
  - 评审进行中不能点名，否则被点名的评审会看到别人的意见；起草或修订时可以；
  - 插话随时可以，作者下一版和评审下一次评审都会看到。
- 宿主：`discussion.start` 多了 `format` 和 `revisions`（1–3，默认 2）。定稿发言没有用量。
- 界面：
  - 新建页成员下面有一行"方式"：自动 · X / 圆桌 / 起草评审。自动按题目里有没有"起草、写一份、写一篇、文档、提案、稿"来选，并写出理由。
  - 选起草评审时，轮数换成"最多修订 1–3 次"，"主持人"换成"作者"。
  - 讨论页的页头下面有一条进度线：第 1 版 起草 → 评审 1/2 通过 → 第 2 版 修订 → … → 定稿。
  - 每轮的标题写明是第几版的起草、评审还是修订；评审卡标"通过"或"需修改"。
  - 定稿卡写版本、是否全部通过、修订了几次，有两个按钮："从定稿新建会话"和"围绕这份稿子讨论"。后者打开新建页，切到讨论，用同样的成员和主持人，方式选圆桌，题目是这份稿子，不会自动开始（`DiscussionPrefill`）。
  - 页头按钮换成"现在定稿"和"再改一版"；评审进行中，`@` 胶囊置灰。

**第四批：分工调研与讨论要求（2026-11-13）**

- `Format::Research`：第 1 轮主持人拆题（`Stage::Split`），第 2 轮其他成员各查一块（`Stage::Research`），然后主持人写报告。报告就是一份总结（`summary`）。没有第 3 轮，也没有"再来一轮"。
- 拆题：
  - 主持人在回复里写一行"分工："，下面每位成员一行"- 名字：要查清的事"。提示词写明拆成几块（成员数减一）、主持人自己不领任务。2026-11-16 复测里两位成员同名、只靠 #1 #2 区分，主持人把一块分给了自己，那一块没人查，报告里写着"超时机制尚未核查"。
  - `parse_assignments` 从带"分工"的那一行开始读，认得 `-`、`*`、`•` 和编号开头；名字不分大小写，匿名时代号和真名都算。
  - 拆题在进入下一步前检查（`check_split`）：漏了成员，这条拆题就记为失败，讨论暂停，提示"主持人没拆好分工：分工里漏了「X」"；点继续时让主持人重拆。
  - 拆好的分工按成员存进 `Discussion::assignments`。
- 谁看到什么：成员只收到自己那一块和用户的发言，看不到主持人的整份拆题，也看不到别人的结果；主持人写报告时看到全部结果和用户的发言。
- 下一步（`after_research_round`）：有成员没查完就暂停，继续时只重试没查完的人；都查完了就写报告。
- 报告的提示词要求分四部分：结论、各部分发现、证据出处、仍待查的问题。
- 操作：
  - "现在汇总"：至少一位成员查完才能用，打断还没查完的成员，用已有结果写报告。
  - 调研进行中不能点名（`working_alone`，和评审进行中一样）。
  - 调研中插话：不打断成员，主持人写报告时会看到；已暂停时插话只记下来，不会再开一轮。
  - 出了报告之后，只能点名追问。
- 讨论要求（`Discussion::requirements`）：
  - 为空表示不附加；没有这个字段（旧记录，或开始时没传）用默认的"观点要具体、说明理由，尽量在 600 字以内"，也就是以前写死在提示词里的那句。
  - "只读、不改文件"这条一直附加，不受讨论要求影响。
  - 开场、每一轮、点名回答、总结、评审、调研和报告的提示词都会带上。起草评审的作者写稿时不带，篇幅不受限制。
- 宿主：`discussion.start` 多了 `requirements`。
- 界面：
  - 新建页"方式"多了一项"分工调研"。自动判断看题目里先出现哪类词："起草"一类选起草评审，"为什么、排查、调研、原因、瓶颈"一类选分工调研，都没有选圆桌。2026-11-16 起也认英文：draft、write a / write an、proposal 选起草评审，why、research、investigate、root cause、bottleneck 选分工调研；英文词不分大小写、只按整词匹配（"redrafted"不算 draft）。
  - 选分工调研时不显示轮数，改为写明"主持人拆题 → 各自调研 → 主持人写报告"。
  - 新建页加了"讨论要求"：一个可编辑的文本框，上方是"简洁讨论 / 方案对比 / 深入分析 / 默认"四个胶囊，点了只是把对应文字填进框里。
  - 讨论页的进度线：拆题 → 调研 N/M 查完 → 报告。成员卡上写出它分到的那一块。
  - 页头按钮是"现在汇总"。出了报告之后，发送按钮要点了成员才能按。
  - 报告卡有三个按钮："从结论新建会话"、"围绕这份报告讨论"（预选圆桌）、"据此起草一份文稿"（预选起草评审）。圆桌的总结卡也加了"据此起草一份文稿"。

**宿主：`discussion.*`**

- `discussion.start {projectId, topic, members: [{configurationId, model?, reasoningEffort?, angle?}], moderator, rounds}`：
  - 先逐个检查成员的配置和模型，都通过才开始建东西。
  - 讨论本身是一条不启动会话的任务记录（`discussion: true`），名字是"讨论 · 题目首行"，状态跟着讨论走：进行中、需要输入、已中断、完成、已取消。
  - 先在 core 登记讨论，再启动成员，这样成员说的第一句话不会漏掉。
  - 成员和委派的子会话一样：直接建任务、再启动。没有走提交流程，因为目录里每个配置的权限列表都不含 `plan`，提交会被拒。成员记录带 `discussionOf`，钉住所选配置（`agent_config_id`）和模型，名字是"题目（讨论 · 成员）"。
- `discussion.get / pause / resume / summarize / stop {taskId}` 返回 `{discussion, usage, families}`。
  - `usage`：按发言的起止时间，从成员会话记录里找出对应的回合（`discussion::usage`），给出 token、费用和用时。
- 给成员发下一轮消息走投递队列（这一轮结束后再发）。成员会话从没开始过时，队列会报"这个会话还没有可续接的对话"，所以这种情况改为带着这条消息重新启动会话。
- 成员不能再委派：`discussionOf` 加进了"嵌套会话"的判断。

**界面**

- 新建会话页左上角是"单人 / 讨论"切换。切到讨论后：
  - 输入框写题目；
  - 输入框下面列出成员胶囊（名字、角度输入、主持人、移除）；
  - "添加成员"在下方展开一块面板，从粗到细分三步：
    - Harness 滑块，和单人模式同一个控件。默认停在单人模式选中的 Harness；没有能启动配置的 Harness 置灰。
    - 这个 Harness 的配置胶囊，默认选中第一个。同名配置只在这个 Harness 里区分，不再给每个配置都挂上 Harness 名。
    - 这个配置的模型胶囊；没有模型列表的配置给一个"默认模型"。
  - 点模型就加入一个成员。面板不收起，可以连续加；按钮变成"完成"，满 5 个自动收起。已加入过的模型胶囊标"×2"。
  - 轮数用 1–5 的胶囊选。
- 右上角的 Harness 滑块在讨论模式下隐藏，Harness 只在添加面板里选，免得两处滑块意思不同。
- 切换单人 / 讨论用滑块同一条弹簧动画：
  - Harness 滑块淡出并向右收起，"独立副本"淡出缩小；
  - 输入框底栏交叉淡入淡出；
  - 成员区淡入并下移到位。
  - 整组内容在窗口里垂直居中，成员区插进来时整组上移，这段位移也在同一个动画里。
  - 打开"减弱动态效果"时只淡入淡出。
  - 以前切换值写在动画之外，这些变化挤在同一帧里跳变，看着像掉帧。
- 添加成员用的是普通按钮，不用 SwiftUI `Menu`：`Menu` 在 App 处于后台时不响应辅助功能的点击，目检脚本打不开。
- 讨论页：
  - 页头：题目、状态（"第 2 / 3 轮 · 讨论中"）、成员、合计 token 和费用，以及暂停 / 继续 / 立即总结 / 停止。
  - 发言按轮排，每个成员一张卡：发言中、在等你确认、没说完（带原因）、维持 / 已修改。重试后同一轮同一成员只显示最新那张。
  - 文本按行内 Markdown 显示，超过 10 行可以展开。
  - 最后是主持人总结卡，带"从结论新建会话"。
  - 进行中每 3 秒刷新一次。状态变了就让侧栏重读任务：宿主改讨论记录不会推送事件。
- 侧栏：讨论行用双气泡图标，成员行用 `text.bubble` 标在讨论下面。

## Alternatives considered

- **主持人的会话当讨论页**：不用新建记录。没选：主持人也是成员，它的会话页是普通会话；讨论页要把所有人的发言并排放。
- **添加成员用一列配置胶囊、点开再选模型**（第一版）：少一层。没选：配置一多，几个 Harness 的配置混在一列里，同名的还要靠后缀区分；先按 Harness 分开更清楚，也和单人模式的选法一致。
- **讨论单独存，侧栏单独一栏**：不碰任务记录。没选：侧栏、归档、删除都要再写一套。
- **发言从成员会话记录里读**：重启后也读得到。没选：回合结束时记录不一定已经写完。改为在更新链上收集，发言一收到就落盘；重启时被中断的那一轮标失败、讨论暂停，继续时只重问没说完的成员。
- **成员走提交流程（和重跑一样）**：配置校验现成。没选：提交只接受配置列出的权限，`plan` 不在其中。
- **第二批一次做完六项（含起草评审、分工调研）**：和 antumi 对齐得更快。没选：后两项是另外两种讨论流程，各有一套下一步规则、进度线和定稿卡；六项一起要拍的板超过五个，分批做。
- **插话只在下一轮听到，到了轮数上限就直接总结**：最省事。没选：最后一轮插的话成员没机会回应，只有主持人在总结里看到，用户会以为被忽略了。
- **@点名的回答不算发言、别人看不到**：互不干扰。没选：点名问出来的往往正是分歧所在，其他成员下一轮应该能回应。
- **匿名可以中途开关**：更灵活。没选：前面发言里的称呼会对不上，成员也可能已经说过自己是谁。
- **自动推荐再请小模型判断一次**（antumi 的做法）：题目没有明显的词时也能选对。没选：要多一次请求，还要选模型、记缓存；先用规则，选错了用户手动改，或从定稿、总结一键转到另一种方式。
- **评审互相能看到意见**：评审可以附和或反驳。没选：后评审的容易被先评审的带偏，变成重复同一条意见；作者那边本来就能看到全部意见。
- **定稿时再请作者跑一轮，整理成终稿**：终稿可能更整齐。没选：最新一版已经是作者写的整篇；多跑一轮要多花一次，还可能改出没评审过的内容。
- **调研成员也看到整份拆题**：知道别人在查什么，可以避开重复。没选：成员容易越界去查别人的部分；只给自己那一块，更容易查深。
- **拆题漏了成员就把没分到的人跳过，照样往下走**：少一次暂停。没选：那位成员会白白空着；让主持人重拆，代价只是一次回答。
- **做正反辩论、接力补充两个预设**：antumi 有。没选：辩论要按人数分配正方、反方和裁判，接力要改每轮的提示词，这已经不只是"讨论要求"那一句文字；以后需要再单独做。

## Consequences

- 2026-11-14 加了第五种形态"接力"（ring：一棒接一棒、只看上一棒），只在 core 和 `discussion.start` 里，没进界面，见[接力讨论](2026-11-14-relay-discussion.md)。
- **收益**：同一个问题可以让 2–5 个配置各说各的，再互相回应，最后得到一份共识、分歧、建议和待决问题的总结；每条发言都能看到花了多少。
- **代价**：
  - 每个成员是一个普通会话，额度和费用照常算。只读依赖各 Harness 自己的规划 / 只读模式。2026-11-17（A4）起，开始讨论前按能力表的"严格只读"查每个成员：Codex、Claude、本机 DSH 可以；omp 的 `plan` 落到"每次都问"，被拒绝；新建页的成员 Harness 也按这一项置灰，见 [A4](../bug-fix/2026-11-17-a4-discussion-read-only-must-be-enforced.md)。
  - 讨论记录的"停止"按钮（页头通用的）对这条不运行会话的记录没有意义；讨论自己的"停止"在讨论页里。
  - 删除讨论记录不会删除成员会话和 `discussions/` 下的文件。
- **验证**：
  - core 单测（12 个）：
    - 立场解析；
    - 下一步（下一轮、提前总结、到轮数总结、没人成功就暂停）；
    - 每个成员只收到别人新说的；
    - 暂停等这一轮说完，继续后进入下一轮；
    - 立即总结会打断还在说的成员；
    - 停止后不再发任何消息；
    - 消息发不出去时发言失败；
    - 重启后正在说的标失败并暂停，继续只重问没说完的；
    - 成员会话启动失败时发言带上原因。
  - 第二批 core 单测（7 个）：插话下一轮听到、超过轮数上限也多一轮；总结后插话再开一轮并重新总结；再来一轮只在暂停或总结后可用；点名等成员说完再问、轮次等点名回答；总结后点名不改已总结；总结中和停止后拒绝发言；匿名讨论的提示词不出现真实名字。

  - Swift 单测（`DiscussionTests`）：解码、状态文字、用量、每轮只显示最新发言、开始条件、添加面板的 Harness → 配置 → 模型；第二批：用户发言和点名回答归到所在轮次、每轮取最新的总结、从文字认出点名（长名字优先、匿名代号）、能否发言和再来一轮、点名回答中的状态文字。
