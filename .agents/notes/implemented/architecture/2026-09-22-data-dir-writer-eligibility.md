# Agent Note: 数据目录的写者资格、存储拒绝的协议映射与只读第二实例

Status: implemented

## Problem

数据目录租约（`DataDirectoryLease`，`File::try_lock`）只在本地文件系统上可靠：NFS/SMB/FUSE 上记录锁可能被静默降级成"永远成功"，两个写者都以为自己独占；iCloud/OneDrive 这类同步根锁有效，风险在跨机合并。拒绝本身也有三类修法完全不同的情况（关掉另一个实例、把目录搬回本地盘、重读后再改），压成一个 `IO_ERROR` 用户就无从下手。拿不到租约的第二个实例也必须决定自己是谁。

## Decision

- **资格分级**（`storage_location`、`storage_lock`）：
  - 非本地卷 → 拒绝取得写者资格，`LeaseError::UnsupportedLocation`；
  - 已知云同步根 → 允许写，但把 `volumeKind` 记入 `runtime.json` 并发一次可见告警；
  - `Unknown`（探针未接、读不到卷信息）→ 按不可写处理（fail-closed）。
  - 不提供"我确认风险仍要写"的绕过开关；真需要的用户把 `--data-dir` 指回本地盘。
- 卷型探测是端口：core 持有 `VolumeKind{Local, CloudSyncedRoot, NonLocal, Unknown}`、判定函数与可注入的同步根前缀表，真实 `statfs` 在宿主侧实现，core 零平台 FFI。
- 私有权限是资格的一部分：新建文件 0600、目录 0700。
- 持有不等于一直持有：`acquire` 记下锁文件 `(dev, ino)`，每次写事务前重验；文件消失或 inode 变化即停止写入并报错，不自动重拿。
- 清理遗留 `.<name>.<pid>-<ns>.tmp`（24h 阈值）只允许刚取得租约的写者做一次，并返回删除清单；非写者永不扫描。
- **拒绝映射到已有错误码**（`storageRejections` 块由 Rust 枚举算出写进契约，Swift/TS 断言读同一块）：

  | 拒绝 | 码 | detail |
  | --- | --- | --- |
  | 另一进程持有目录 | `BUSY` | `lockHolder`、`epoch` |
  | 位置不具备写者资格（含 `Unknown`） | `IO_ERROR` | `reason = storage-location-not-writer-eligible` |
  | 落后写入 / 内容不是自己上次写的那份 | `REVISION_CONFLICT` | `expectedRevision`、`actualRevision`、`epoch` |

- **恢复永远不是自动的**：坏 JSON 的处置是拒绝写、原件逐字节保留、把路径与原因经 `message` 讲清；每次替换只留一代 `.bak`，不做恢复命令、不做多代环形备份、不"检测到坏就试上一个"。
- **第二个实例以只读启动**：拿不到租约的实例照常开窗口、能看项目与历史，所有写意图在入口被拒，不起进程、不落盘。不抢租约（租约只能由持有者释放），不退到临时目录另起一份数据；只读状态在整个会话期间持续可见，而不是一条会消失的提示。

## Alternatives considered

- **一律拒绝（含云同步根）**：最保守。否掉是因为会硬挡把 Home 放在同步盘上的真实用户，他们需要的是提示而不是不可用。
- **只写文档不改行为**：零回归风险。否掉是因为"一个目录一个写者"会退化为只在本地盘上成立的空话。
- **位置不可写用 `UNSUPPORTED_CAPABILITY` 或 `INVALID_ARGUMENT`**：语义上更像"不支持"。否掉是因为前者是宿主级事实（换个目录结论就变），后者暗示用户传错了参数，而默认 Home 在网络盘上时用户什么也没传错。
- **后启动的实例接管、先开的转只读**：符合"新窗口优先"的直觉。否掉是因为先开的窗口会在无人知晓时停止落盘，界面却一切正常。
- **拿不到租约就退到临时目录**：两个实例都能写。否掉是因为数据从此分叉而用户以为在用同一个资料库，这是最接近静默丢数据的选项。

## Consequences

- **收益**：写者资格在 `acquire` 前置判定，网络盘上不会出现两个"独占"写者；客户端能区分"重试可能成功"（`BUSY`）与"重试永不成功"（资格、冲突）。
- **代价与已知上限**：网络卷检测在 CI 上无法真跑，只能以注入的伪卷清单单测；同步根判定依赖前缀表，漏掉的同步服务会被当作本地卷。若出现确需恢复命令的场景，它必须带显式确认参数与反例，而不是给原子写加 `force: bool`。
